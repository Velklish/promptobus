# Controlled fixture schedules

These switches select local stub schedules in the existing focused tests. With no argument the reference schedule runs. Record results per revision: a run before a new assertion was added is not evidence that assertion passed. These schedules do not measure frequency.

After execution is authorized, build with `npm run build`. For each row, run `node test/<file>.test.mjs` once without arguments as the reference, then the same command with **one** `--schedule=<value>` at a time. Use a fresh process for each command. Keep the exact argv, Git SHA, Node version, platform, stdout/stderr including JSON receipts and individual check lines, exit code, and cleanup result. `at` on a controller receipt is local monotonic time; use turn IDs, file handoffs and exit events for cross-process order. A skipped socket, missing prerequisite, watchdog, unrelated failing check or incomplete cleanup is not a causal witness.

| File | Switches | Comparison and decision criterion |
| --- | --- | --- |
| `claude-relift` | `guard-first`, `held-turn` | Withhold send until the **second session's** first guard after its 9000 ms action. Compare the actual knock and guard in that session's trace. In the held case, wait for entry, delay send over nine seconds, check receipt and ordering, then release and observe the guard. A missing knock is not a late-knock witness. Retain stop-all, record identity, contact point, handshake and no-id checks. |
| `codex-holder-spawn` | `late-notice`, `missing-notice` | Close stdin and return initialize as usual. Hold `item/completed` until after the 250 ms wait **and** the exit/running race. Compare the frozen log with the post-release log; require the specific rate-limit params and failed tool details. In the missing case the four-second observer must fail with its log. Keep the original init, EPIPE, exit and provenance verdicts. An exit preventing delivery of the second notification does not establish delayed logging. |
| `codex-holder-turn-reservation` | `started-B`, `held-B` | Observe native B acceptance while A is outstanding. Delay the controller until B's actual trace entry versus a gate before B's notification, after the fixture delay. Compare busy after acceptance and after A completes, B still unstarted, changed-owner-auth refusal and unchanged private auth. Release B after the checks; require start and shutdown. A mutation witness must lose the reservation **after A ends while B is still held**. |
| `codex-stop-recovery` | `exited-holder`, `held-holder` | At the same socket-ready point, wait for the real 500 ms child's exit versus delaying over 500 ms with a pipe-held child. Compare first Stop's unresolved result and retained session. Close the pipe after that assertion, await actual exit, close the socket, recover, then repeat Stop for idempotency. A mere response from the fake socket is not proof of retirement. |
| `delivery-wait` | `paused-observer`, `logical-polls` | Record the returned result before pausing the controller past each original elapsed ceiling. Check update, torn JSON and unchanged-mark timeout separately. In the clock control use the real file reader: at logical 20 ms introduce invalid JSON for the torn case, at 40 ms write a newer mark for both success cases; leave the timeout file unchanged through 60 ms. A different semantic result is not an elapsed-only failure. |
| `lead-startup-cleanup-race` | `late-contender`, `contended` | In both cleanup scopes, the retry pauses after reading the missing holder `.lock`. Position the old process just before `mkdir` of the exact `.transition` directory versus waiting for the result of that syscall. Snapshot `nativeStarted` and the attempt receipt **before** releasing cleanup. Compare absence with no attempt against actual `EEXIST`; check no old spawn and one live replacement. A green late-contender run shows an untested interleaving, not a production exclusion defect. |
| `promptobus-warden` | `late-end`, `missing-auth`, `missing-tokenless`, `missing-probe` | Pause the real accepted socket. Record what the old parser/predicate sees after 50 ms, then resume that connection and collect its end before starting the next. Compare authenticated JSON lines, tokenless auth and probe-only auth separately. The old probe counts `''.split('\n')` as one line; require actual auth in the received probe. Withhold resume on one named connection to exercise its bounded diagnostic. Preserve the nonexistent-socket refusal. |

Judge each comparison independently. Confirm only when the imposed order is observed and explains a changed verdict or vacuous assertion; reject only with a completed controlled comparison that contradicts the proposed dependency. Otherwise retain UNKNOWN. An expected failing baseline or deliberate missing event is not itself a passing regression.

For relift, match the knock to the sent mailbox timestamp and require the participant's release acknowledgment before its guard. For the notification fixture, the shell acknowledges emission or deliberate withholding while the holder is alive. For turn reservation inspect the holder's `activeTurns`, not just a producer trace. An already-exited holder retires on the first Stop; a live one must acknowledge the shutdown RPC and then fail specifically on exit confirmation. Compare actual session keys in the cleanup fixture (one equal pair and one distinct pair). The missing-end schedules record failure and still test the independent dead-socket refusal after teardown.

If measurements justify a default correction, retain the smallest event-based change and rerun the baseline, its negative control and the ordinary focused file. Reservation removal and transition-exclusion removal require separate authorization and committed mutation witnesses. For exclusion removal, require an actual old native spawn or violated ownership assertion: a missing instrumentation marker alone does not count. Record build and final configured gate counts/exit codes separately. Stress and live workflows provide no substitute for these receipts.
