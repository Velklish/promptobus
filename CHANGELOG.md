## [Unreleased]

### Added

- **Subscription balance: the CLI now knows what each account has left, and `--strategy balance` spends the three of them evenly.** Three subscriptions pay for three harnesses, and routing by rating sent work to the best-rated tuple until one account was out while the other two sat idle — which is what the owner was correcting by hand. A spike on 2026-09-06 disproved the assumption [ADR-003](docs/adr/adr-003-model-routing.md) recorded, that no harness but Codex exposes a remaining limit: all three answer from local credentials with no paid turn. [ADR-004](docs/adr/adr-004-subscription-balance.md) records the owner's nine decisions of that date, supersedes ADR-003 section by section — the replace-by-selector-kind merge, the reviewer floor of 4, the four values of `--strategy`, "`promptobusHome()` is not used for routing", and "a call with no `--strategy` routes nothing" where a default is set — and PB-24…PB-33 with PB-36 implement it.

  **What `promptobus models` shows now.** Under the candidates comes an `availability:` block: one line per harness with its state and its tier, and under it one line per limit window — the window's id, its `kind` (`session`, `weekly` or `monthly`), the percentage used, its `lengthSec`, what it binds, and its reset time. A `kind` is a **name** and `lengthSec` is the **number**, and neither is derived from the other: a billing cycle is `monthly` and is not thirty days. All three harnesses can reach `available` for the first time — the word still means auth, model **and** limit confirmed. Claude Code reads its tier out of the local credential record and its session, account-wide weekly and per-model-family windows out of one `GET /api/oauth/usage`; Cursor reads its billing cycle as **two pools of the same length**, `monthly-auto` and `monthly-api`, and one spent pool does not exhaust the harness, because the resolver reads a scope per tuple; Codex reports its plan, whether it has credits, how many "Full reset" credits are waiting and whether a spend control was reached, all off the call it was already making. Every harness that could not be read stays `unknown` / `quota_unknown` and is penalised, never blocked. Beside the decision the command prints one line about the telemetry file — how many records it holds and its size — and, where no plan name has been recorded, the one question no harness method answers.

  **What each adapter reads, and what it refuses to read.** Claude Code takes three fields out of the local credential record — a keychain generic password on macOS, service `Claude Code-credentials`, read through `/usr/bin/security` by absolute path; `~/.claude/.credentials.json` elsewhere, a path the spike did not measure and the reference says so — the access token, its expiry and `rateLimitTier`, which is the tier at no request at all; one `GET https://api.anthropic.com/api/oauth/usage` then maps `limits[]` onto a `session` row at five hours, a `weekly_all` row at seven days and a `weekly_scoped` row per model family, whose scope carries the ids the driver's own alias table resolves the harness's display name to. `GET /api/oauth/profile` is asked for the tier only when the record names none. A 401 or 403 from the usage endpoint is `unavailable` / `not_authenticated`; a `session` or `weekly_all` row at 100 % or carrying `locked_reason` is `exhausted` with that row's reset — and where the harness named no reset the mark is **sticky**, the message says so and names `promptobus models --clear-exhausted claude`. A spent **model scope** exhausts nothing, being one family the resolver reads per tuple, and neither does a row the harness marks `is_active: false`: the limit is not being enforced, and exhausting on it would take every Claude tuple out of routing on a number nothing is applying. Cursor keeps its two binary calls and adds the one the binary does not make, `POST <backendUrl>/aiserver.v1.DashboardService/GetCurrentPeriodUsage`; the cycle becomes two windows of the length the answer states, the `auto` pool naming the inventory ids it covers and the `api` pool carrying no list, being the complement; the tier is `{ name: "included:<cents>", source: "derived" }` because no method returns the plan name; a token that could not be read is `quota_unknown` rather than `not_authenticated`, since `status` already answered the auth question; and Cursor's own third-party usage nudge becomes a sentence this adapter writes from the threshold and the target model rather than the nudge's own label, with `displayMessage` — the one piece of harness prose allowed into a diagnosis — travelling on the exhausted branch only and bounded either way: control characters out, whitespace collapsed, 120 characters, and a string containing `@` refused outright. Codex reports `planType` as its tier, `spendControlReached` named in the message only when true, and the count of "Full reset (Weekly + 5 hr)" credits — **nothing spends one**, and the credit balance travels as two booleans because a count is a fact about the account rather than about the plan. `account/read`, the method that answers the account e-mail, is still never called: `planType` was already inside the call the probe makes anyway.

  **`--strategy balance`, the fifth strategy.** The four ADR-003 strategies answer how to weigh the qualities of a tuple and are untouched; `balance` answers a different question — which account to spend from. For each candidate the **binding window** is the applicable one with the highest `usedPercent`, where applicable means the account-wide windows plus the scope covering that tuple; `underspend = (elapsedShare − usedShare) × 100` is how far behind its own pace that window is, in **percentage points of that window**; and `effective = underspend − balance.spendUnit × (quotaCost − 1) / 4` discounts a heavy tuple in the same unit before harnesses are compared. Each harness is represented by the tuple that would actually be picked on it, the largest `effective` leads, harnesses within `balance.band` (5 points, as is `spendUnit`) are tied and their `balanced` scores decide. It is a **choice layer, not a filter**: every candidate keeps its score and its place and gains a pace block, and when no harness can be paced the pick is the best `balanced` score with a `balance-fallback` warning rather than a refusal. `models` prints the pace table under the candidates and `--json` carries the same numbers. **Nothing in this package pins the reviewer to a harness** — it is routed by pace like a worker, with the reviewer quality floor above it and ADR-003's diversity bonus unchanged on top.

  **`near-limit`, and the switch a person agrees to holds for the next spawn.** A `near-limit` warning names a harness whose binding window is at or past `nearLimit.usedPercent` (80) or whose underspend is below `nearLimit.underspend` (−15 percentage points), with the window, its reset, **which of the two tests tripped** — a level and a rate are different facts about one window — and the strategy it would switch to: `economy` when every paced harness is past the threshold, `balance` when at least one still has room. No line when the strategy it would name is already the one running, and an exhausted harness is not repeated as near-limit. It is raised under every strategy, not only under `balance`: a person running `--strategy quality` is owed the same warning about their windows. **Nothing switches on its own** — `skills/orchestrate` tells the agent to propose the switch to the person, and `skills/solo-review` that the reviewer follows the same default. On agreement, `promptobus models strategy --set <name>` writes `defaults.strategy` into the host's writable layer, keeping every other key of that file, creating it with a `schemaVersion` when absent, atomically and mode `0600`, and refusing when no layer is writable rather than choosing a file itself; `--clear` removes it, and the command warns when what it just wrote is shadowed by a layer above. `promptobus models strategy` with no argument prints the effective default and the layer it came from.

  **Precedence, everywhere: flag → overlay default → none.** `--strategy` on the command line always wins, which is the rule ADR-003 fixed for every named value. Below it, `defaults.strategy` from the merged overlays; below that, nothing — and nothing is the legacy path, so ADR-003's "a call with no `--strategy` routes nothing" still holds word for word where no layer sets one. `models` without `--strategy` takes the same default and falls back to `balanced` where none is set, so it and the next `spawn` cannot disagree about what is in force. A lift routed by the default records `strategySource: "overlay:<layer>"` on its decision and in `metadata.routing`, so a run made under an agreed switch is auditable as one. Reading the default costs the overlay files and no probe.

  **One question the tool cannot answer, and no command writes it.** Cursor's plan name is returned by no method. It lives at `account: { "<harness>": { "plan": "<name>" } }` in the **user** overlay: `models` prints the key, the value where a person set one and the path to add it to where they have not, a person adds the line once, and the value is displayed and scored by nothing. There is no writer because the writable layer is per-workspace — a tool-written answer would be asked again in every workspace — and because a second writable layer to carry one string would make "exactly one writable layer" false the first time it was used.

  **Quality floors per role, `remaining` per tuple, hidden rows carried.** `qualityFloor: { worker: 3, reviewer: 5 }` supersedes ADR-003's reviewer floor of 4 and its absence of a worker floor: three for the worker because "a worker on a cheap model where the task needed the expensive one is paid for in review rounds" describes a floor ADR-003 never set, five for the reviewer because a defect the last reader misses costs the defect and a round trip. Both keep the shape the reviewer's had — a choice rule, not a filter — with `worker-floor-not-met` beside `reviewer-floor-not-met`; `reviewerQualityFloor` is still read as an alias, and a layer stating both raises the `quality-floor-alias` warning while the explicit key wins. `remaining` is now computed over the applicable windows **of each tuple** rather than of its harness, so a Cursor tuple in a spent pool scores below one in a pool with room under `quality`, `balanced`, `speed` and `economy` alike — a refinement of ADR-003's own word, which already said "applicable". A model row the harness lists and declines to offer is carried with `hidden: true` for a person to see and is not inventory: a tuple naming one is excluded as `model-not-in-inventory`, and a hidden unrated row is not a `runtime` row either.

  **Overlay rules accumulate instead of replacing each other, and two selectors are added.** A `deny` list of any selector kind is now the **union** across every layer that states one: a ban written in any layer stands, no layer above lifts it, and lifting one means editing the layer that wrote it. An `allow` list is the **intersection**, so one sentence covers both — a layer's rule survives every layer above it. This supersedes ADR-003's replace-per-selector-kind merge whole, and it closes what the first consumer had measured: to make its policy bans hold it had to sit on top of a person's workspace file and erase that person's own `deny.tuples` with it. Two rules it could not write at all are now writable — `byRole: { reviewer: { … } }` scopes a block to one role, and `flags: ["no-zdr"]` names a mark the availability snapshot carries on a model row. A `denied-by-policy` candidate names the rule and **every** layer that wrote it, not one; the flag selector is applied after the inventory step, because that is where the row it reads arrives, and **silence is not absence** — a harness that lists no models has no flag to match, which a run reports as the new `flag-not-in-inventory` warning instead of appearing to give a guarantee. Because an allow list can now be unsatisfiable, `models validate` gains `allow-intersection-empty` and `deny-covers-allow`, the old cross-layer contradiction becomes the `allow-shadowed-by-deny` warning — lawful under union, since deny simply wins, while a name allowed and denied in ONE layer stays an error — and the command prints every deny rule in force with the layer that can lift it. The overlay `schemaVersion` stays 1: the new keys are optional and every file on disk stays valid, and what changed is what those files do.

  **The catalog is rebuilt from the live inventories, and every rating now says what is behind it.** `models/catalog.json` goes from nineteen tuples rated off the models' own descriptions to forty-five rated by the ADR-004 rule, `source: "public benchmarks, subscription-balance series, 2026-09-06"`. Claude Code gains `claude-fable-5` — the id the binary's baked model catalog resolves the `fable` alias to, read offline out of 2.1.251 with no paid turn, which also joins `MODEL_IDS`; Codex gains `gpt-5.5` and the `ultra` effort on `gpt-5.6-sol` and `gpt-5.6-terra`; and the Cursor rows are now **only** the seven families neither of the other two harnesses serves — `composer-2.5`, `cursor-grok-4.6`, `gemini-3.8-flash`, `gemini-3.7-flash`, `gemini-3.1-pro`, `kimi-k3`, `glm-5.2` — because Cursor's second pool bills a third-party model against the same included amount, so routing there a model another subscription already pays for spends two subscriptions for one run. A `-fast` id and Codex's `fast` service tier get no rows: ADR-004 keeps the service tier out of the tuple key. **Not done, deliberately:** per-model effort ladders and speed tiers on the snapshot's model object — it is closed to four fields and ADR-004 says the service tier "is not modelled in v1 at all", so widening it is an ADR pass rather than a schema edit; PB-24.2 puts the question to the owner, and nothing is blocked meanwhile because the catalog took the ladders from the spike document. `roleRatings` is gone, being the one judgement in the file with no figure behind it. One consequence to know: **no Cursor row reaches the reviewer floor of 5**, so ADR-003's reviewer diversity bonus works over Claude Code and Codex today rather than over all three harnesses.

  **`evidence` can carry the citation, and `validate` refuses a rating that has none.** The field still takes the v1 string; the shipped rows use the object form ADR-004 asks for — `{ text, sources, interpolatedFrom, hypothesis }`, each entry of `sources` naming one rating with its `basis`, `version`, `agentHarness`, `provenance`, `figure`, `fieldSize`, `url` and `date`. For each of `quality`, `speed` and `quotaCost` a row cites a figure, or is `interpolatedFrom` a base row that cites one, or names that rating in `hypothesis` — "no figure is published for this exact model, and here is the reasoning instead". Anything else is `catalog-invalid`, as is an `interpolatedFrom` naming no tuple, or a rating claimed as both cited and hypothetical. So the sentence the catalog has made since 0.3.0 — that a rating without a source stays out — is now checked rather than promised, and a reader can see at a glance which half of a row rests on a published number. Effort ladders are generated by the ADR arithmetic (quality one band per two steps, speed one band per step inverted, `quotaCost` one band per step, clamped to 1…5) and the suite pins every rung against it.

  **`promptobus done` starts collecting local statistics: one telemetry record per participant.** Closing a task appends one JSON Lines record per participant that lifted a session to `telemetry.jsonl`, beside the availability cache the host names, mode `0600` and validated by `schemas/model-routing/telemetry.schema.json`: the tuple, the strategy and where it came from, the lift and end stamps with the duration, the bus traffic (turns, review rounds, questions, results), how many other participants of the task were live on the same harness at the lift, and — the point of the whole record — the limit windows that applied to that tuple with their `usedPercent` at spawn and at the close. A **positive delta on the binding window is what the run spent, in the account's own unit**, which is the evidence the `quotaCost` rating never had. An unrouted participant — a legacy lift or an explicit `--model` — is recorded too, with `strategy: null`, so a hand-picked tuple is measured beside a routed one. The record is written at `done` and **not at `dismiss`**: a dismissal is not the end of a participant, so a record per dismissal would put several rows on one run with nothing to merge them by, and `dismissedBeforeDone` carries the dismissal into the single row instead. **Local only:** nothing sends the file anywhere, nothing but the count line of `models` reads it, and a record carries no prompt text, no message body, no repository path, worktree or branch, no session id, no email and no token — it is assembled by copying declared fields one at a time, never by spreading a participant record, and every object of its schema is closed. The only identifier is an opaque local key made from the task id. The end reading of a window is `null` rather than a number when the cache entry is past its TTL, and since `done` probes nothing, **`promptobus models --refresh` right before `promptobus done` is what records an end value at all**; without it the record carries the start value only. The tool never rotates the file — `rm` clears it — a failure to write is a warning and never a refusal, and **reading the records back is not in this release**.

  (PB-23, PB-24, PB-26, PB-26.1, PB-26.2, PB-27, PB-28, PB-29, PB-30, PB-31, PB-32, PB-33, PB-36.)

### Changed

- **For a host implementer: one new field on a routing layer, a snapshot at `schemaVersion` 2, and one file that lives beside the cache without a method of its own.** Everything a consumer host has to do for this release is in this entry, and it is one field.

  **`HostRoutingPaths`'s layer gains `writable?: boolean`, and exactly one layer carries it whenever any layer is declared.** `readLayers` refuses zero and refuses two, naming the layers it found. The refusal is at the **declaration** and not at the write, for the reason `harnessStateHome` refuses instead of guessing: a person who learns their host names no writable layer from `models strategy --set` learns it after making the edit it refuses to keep, and two writable layers would make the file the tool writes depend on iteration order. A host that declares no overlay at all declares nothing to write, which stays lawful. **`tsc` does not say so** — the field is optional, so a host that omits it compiles — and the place it is learnt is the first routing command, which refuses with a `GateError` naming every layer the host declared; `models validate` reports the same thing as a finding rather than a refusal, and prints which layer is writable beside its path. A host should mark the **highest-precedence** layer, or the tool would write a value a layer above it overrides; `models strategy --set` warns when that happens. **The writable layer is state, not configuration, so it must not be a file anybody commits** — a consumer keeps it wherever its own state lives, under that one condition.

  **Under the standalone host the `workspace` overlay moves to `<promptobusHome>/model-routing.json`, and `<workspaceRoot>/model-routing.local.json` is no longer read.** Its content is written by the tool now — the strategy an agent proposed and a person agreed to is recorded there — and a file the tool rewrites cannot live in the repository root, where a `.gitignore` is a contract with the repository rather than with this package. It is per-workspace exactly as the old path was; what changed is which per-workspace directory. **There is no migration and no fallback**: two paths under one layer id would make the file a person edits depend on which of them exists, so rules kept in the old file are not read and have to be moved by hand. The cache and the `user` overlay are untouched and stay account-scoped.

  **The availability snapshot moves to `schemaVersion` 2.** A window now states its `kind` — `session`, `weekly` or `monthly` — its `lengthSec`, and an explicit `scope` that is `null` for the whole account, `{ model, models? }` for one model family, or `{ pool: "auto", models }` / `{ pool: "api" }` for a harness with two pools in one cycle; a harness carries `tier: { name, source } | null` and, where it has them, informational `credits` and `resetCredits`; and a model row the harness lists and declines to offer is carried with `hidden: true`. **A scope that covers models names them by id**, so nothing infers a model family from a display name the harness printed. **A cache written by an older version is discarded, not migrated**, and every harness then reports `unknown` / `stale_cache` — the shortest fact in that file lives sixty seconds and the longest an hour, so a reader for the old shape would buy one hour of not asking and be kept forever; the message says a discard happened rather than "no cache entry", so an upgrade does not read as a bug. Three rules keep the new fields honest at the disk boundary: a tier name is shaped like a code — no spaces, no `@` — because it is the second adapter-authored string that reaches disk and `message` is meant to be the only free-text one; the credit **amount** is deliberately not carried, a count being a fact about the account rather than about the plan; and the model-flag list is closed to the one mark that exists, `no-zdr`, because an overlay may deny by a flag and a name checked against nothing would let a typo ban silently nothing. A window with no length, an unknown kind or an unreadable scope is dropped rather than repaired — a garbled scope would otherwise widen into `null`, which is the claim "this binds the whole account".

  **The decision document and the participant record carry the new facts.** `harnesses` in the decision is the `availability:` block, assembled by the command from the snapshot after the resolver has answered, so `--json` carries exactly what the text form shows and `render` still reads the document and nothing else. A routed lift records `windows` on its participant — the applicable windows of the tuple it chose with the `usedPercent` they had at that moment — which is the starting value the spend of a run is later read as a delta from, and `promptobus status` prints it beside the routing line. `strategySource` says whether the strategy came from a flag or from a layer.

  **`telemetry.jsonl` lives beside `cacheFile` and the host does not name it.** It is deliberately not a method: it is one leaf inside a directory the host already owns, and a second path to declare would let a consumer put the telemetry of one account beside the availability of another. **The consequence for a consumer is that moving the cache moves the telemetry with it** — the two are read together by the calibration pass, and a `cacheFile` that changes between releases leaves the old records behind rather than migrating them. Like the cache it is the ACCOUNT's, not one workspace's: `promptobusHome()` is not used for it at all.

  **Token handling in the three adapters, since a consumer inherits it.** Claude Code's access token is read from the credential record, used as one header, and never written or refreshed — `refreshToken` is not parsed out of the record at all, the refresh endpoint is never called, and the suite greps both the verdict and the written snapshot for the token. Cursor's bearer comes from the macOS keychain item `cursor-access-token` first and from `CURSOR_API_KEY` only as a fallback; `cursor-refresh-token` is never asked for, and the backend URL read off `~/.cursor/cli-config.json` is accepted **only** as `https:`, because a bearer is about to be sent to it. Codex's tier comes off the call the probe already makes, and `account/read` — the method that answers the account e-mail — is still not called at all. Every keychain read and every HTTP call arrives as a parameter with a live default, so no test reaches the network or a keychain.

  (PB-24, PB-25, PB-26, PB-27, PB-28, PB-30, PB-36.)

## [0.3.0] — 2026-09-05

### Added

- **Model routing: name an intent, get a tuple.** `promptobus models [--strategy quality|balanced|speed|economy] [--role worker|reviewer] [--refresh] [--json]` prints what the resolver would pick right now — the chosen `role + harness + model + effort` tuple, every candidate it considered with its four score components or the reason it was excluded, the models the account exposes that the catalog does not rate, and the warnings — as text, or with `--json` as the document `schemas/model-routing/decision.schema.json` describes. The command has no `--dry-run` because it is one: it reads the availability cache and asks no harness anything, and `--refresh` is the only flag that probes and therefore the only one that writes a cache entry. A decision is aged from the OLDEST availability entry's own `checkedAt` rather than from the moment the command ran, so "12 s old" says how old the facts are, and a snapshot nothing in which was ever checked prints as `never checked` instead of an age counted from the epoch. `models validate` checks the shipped catalog and every overlay layer and names, for each finding, the layer that wrote the key it is about. The decision the whole surface implements is [ADR-003](docs/adr/adr-003-model-routing.md), fixed with its schemas and golden fixtures before any of the code (PB-11, PB-12, PB-18, PB-21). The text form prints at most eight unrated rows per harness and counts the rest; `--json` keeps every row.

- **`--strategy`, `--allow-payg` and `--refresh` on `spawn` and `review`.** The resolver picks the harness, the model and the effort, and an explicit `--harness`, `--model` or `--effort` becomes a **constraint** on that choice rather than a value — a named value is never replaced by a neighbouring one, and a named combination that is unavailable or exhausted ends the command with diagnostics instead of a substitution. `auto` is not a CLI value: the orchestrating agent turns a task into one concrete strategy before the call. Routing joins the gate order those commands already state — everything before the first disk write — so a strategy with no candidate ends with the rendered decision and leaves no task, no worktree and no participant behind; explicit constraints are checked against the merged catalog and the workspace tool manifest before the resolver is asked, because the resolver cannot tell a harness this workspace never declared from nothing surviving. `--dry-run` reads the cache and writes neither a cache entry nor task state, and `--refresh --dry-run` probes and still writes nothing. Without `--strategy` the command takes its previous path down to the driver's own defaults (PB-21).

- **A rated model catalog ships with the package, and overlay layers sit above it.** `models/catalog.json` holds the first rated matrix — nineteen tuples across the three harnesses, each rating carrying a source and evidence a later maintainer can check; a model the harness exposes and nobody could rate from a named source gets no row and appears as a runtime `unrated` line that nothing picks. Above it, `host.routingPaths()` names the overlay layers, lowest precedence first — under the standalone host `~/.promptobus/model-routing.json` and `<workspaceRoot>/model-routing.local.json`, with room for a consumer's own policy layer between them. A weight set is replaced whole, an allow or deny list whole per selector kind, everything else field by field, and a missing overlay file is normal. **A ban is final from below**: the overlay schema refuses `deny: {}` and `deny: { models: [] }` alike and every denied name must exist, so "deny nothing" cannot be written and a consumer's ban holds whatever a person writes in their workspace file. Two hazards are written down where a person meets them: Cursor carries the effort level inside the model id, so a Cursor row names the full id and no effort; and a Claude row names `claude-opus-5` or `claude-sonnet-5` rather than the `opus` / `sonnet` aliases, because an alias re-points under a rating and nothing goes red. The overlay file to copy is in [guides/model-routing.md](docs/guides/model-routing.md) (PB-13, PB-13.1, PB-13.3).

- **The three accounts can be asked what they can run, before a session exists.** Each driver declares an availability adapter — Claude Code reads `claude auth status --json` and its own model dictionary (the binary publishes no listing); Cursor reads `status` and `models`; Codex opens `codex app-server --stdio`, asks `account/rateLimits/read` and `model/list` and kills it again, with no `thread/start` and no turn, so asking costs neither a session nor a run. The preflight runs all of them at once under one 15 s budget and resolves each binary once before the race, so a harness that never answers is `probe_timeout` rather than a command that hangs, and a host that spends the budget inside its own synchronous `resolveToolBin` stops the run instead of extending it. The result is the availability snapshot, kept at the file the host names with mode `0600` and a TTL per entry — an hour for auth and inventory, a minute for limit windows, five minutes for a failed probe, a confirmed exhaustion until its reset, and one with no reset until `promptobus models --clear-exhausted <harness>` lifts it. **The file holds no prompt, no token, no e-mail and no open account id**: a verdict is projected field by field onto the closed snapshot shape before it is written, so anything an adapter attached beside the contract never travels, and a writer holds a lock across the read, the merge and the rename so two commands probing at once do not lose each other's entries. A limit hit between the preflight and the launch marks the harness exhausted and refuses with `limit-hit-at-start`, naming the file the mark went into and the two ways out of it. `available` means auth, model **and** limit confirmed: only Codex reaches it, and Claude Code and Cursor stay `unknown` / `quota_unknown` because neither exposes a stable source for the remaining limit — which the resolver penalises rather than blocks (PB-14, PB-15, PB-16, PB-17, PB-21.1).

- **A routed run is auditable while it runs, not only at its start.** The decision is kept in the participant's `metadata.routing` — strategy, role, tuple, score, the snapshot it was made on and the warnings — and `promptobus status` prints that line per routed participant. The protocol version does not move for it: `metadata` is declared open in `schemas/v1/participant.schema.json`, so a record carrying a decision is readable by a mechanism of any version, and a reader that does not know the field ignores it (PB-21).

- **The orchestrating agent has the rubric that turns a task into one strategy, and the package now ships it.** `skills/orchestrate` carries the `auto` rubric — contracts, architecture, security, migrations, incidents and any still-ambiguous statement are `quality`; ordinary development is `balanced`; reconnaissance and a small precise change are `speed`; bulk low-risk routine is `economy`; and the price of a mistake moves a track up one row — together with the strategy envelope agreed before the first spawn (strategy per track, allowed harnesses, PAYG policy), where a fallback inside the envelope needs no second approval and leaving it does. A `--harness`, `--model` or `--effort` the person named travels to the CLI unweakened; two review rounds without progress step the track up once. `skills/solo-review` gets the reviewer's default `quality` and the diversity rule — a reviewer off the worker's harness or model scores higher, and a second reading with the same blind spot is not a review. Both files are in `package.json` `files` now, so a consumer references the rubric out of the installed package rather than out of a URL it has to keep in step (PB-19, PB-20).

- **A repository can declare how to restore the process skills it does not keep in git.** A worker repository's own `promptobus.json` may carry an optional `generate` field — the argv of a command, never a shell line — and `spawn` runs it in the fresh worktree: after the participant record reaches the task journal, so an interrupted generator cannot leave a directory the next spawn refuses to reuse; before the launch files, so a generator writing into the harness config directories is not the last writer; and before the dependency install, which is the trade the field makes — an `npx …` generator works in a worktree with no `node_modules`, an `npm run …` one does not. It is read from the WORKTREE at run time, because that is the file the participant will see. A refusal does not refuse the lift: the operator gets a warning with the exit code and a log beside the worktree, and the participant preamble names the outcome in **every** case, including "no generator declared" — a participant that is never told cannot notice that its repository's rules are missing. Skills committed to git stay the default and cost this step nothing (PB-8).

### Changed

- **Host contract: `PromptobusHost` gains two required methods and one declared field, and a consumer meets all three at one release.** `routingPaths()` names the availability cache and the ordered overlay layers — account-scoped, so they do not hang off `promptobusHome()`, which stays the per-workspace task store, and an ordered list rather than a getter per layer so a consumer can insert its own policy layer without another change to the interface. `harnessStateHome(harness)` names where the package keeps its session registry for one harness and may answer `null`; precedence at the call site is `PROMPTOBUS_<HARNESS>_HOME`, then the host, then a refusal naming both, with no default any more — the default is what went wrong, a consumer that had named its own variables had two harness registries writing into the operator's real home while `inspect` read the sandbox, with no error anywhere. And `HostToolBin` now declares the `version` field three drivers and three availability adapters were already reading: optional, and its absence means UNREAD rather than "old". The standalone host answers the same paths it used to guess and returns no version deliberately — it does not search for the binary, and `resolveToolBin` is synchronous, so reading a version would mean `spawnSync` inside the preflight budget. `tsc` refuses an existing host implementation until the two methods are added (PB-11, PB-2, PB-15.1).

- **The Cursor driver declares its binary as `cursor-agent`, not `cursor`.** `options.tool` is the name the package hands to `host.resolveToolBin` and from there straight to `run`, so it must be the name of the binary that actually starts; it said `cursor`, which is the harness name, and a host that hands a name back without searching sent that through `PATH` into an operator's own `~/.local/bin/cursor`. A host that switches on that name meets `cursor-agent`; the harness id, `--harness cursor` and the `tools` list are unchanged (PB-2).

- **The Codex MCP key prefix is the consumer's name, not a constant in the package.** The `config.mcp_servers` override merges with the operator's personal file by field, so the package moves its records into a namespace that file does not use — and the word is the consumer's identity, which the host already declares. The prefix is `${host.commandName}-`: standing alone it is `promptobus-` exactly as before, and inside a larger CLI a participant reads `mcp__<commandName>-promptobus__promptobus_send` and sees the tool it is running under. The config key and the tool name in the prompt still come from one function called twice; the prefix reaches the detached holder through the session record, because that process is handed a record file and has no host to ask. A key built with no prefix refuses instead of falling back to the canonical name, which would be the collision itself (PB-3).

- **Everything the package ships describes itself in English.** `description` and `title` in `schemas/v1/*.json` are translated, with every structural keyword, `$id`, pattern and required list untouched byte for byte, so the two schema directories in one tarball agree on language; the suite's own check titles and comments were translated with them, one to one, leaving fixture literals that stand in for a person's words alone (PB-12.1, PB-9).

### Fixed

- **A Codex holder dies with its session, and a run that leaves one behind now says so.** The holder is detached on purpose — `spawn` returns after the first turn and someone has to hold the app-server stdio — but it was reaped only from cleanup hooks, and the take-down that leaks reaches none of them: a suite file taken down with SIGKILL left its holder and app-server alive, and one 2026-09-04 run left twelve such processes alive into the next day, each holding a session file under a directory that had since been removed. The holder now watches for its own record every five seconds and, when it is gone, kills its app-server and exits without writing to its log — a log write would recreate the tree that was just removed. `stop` and `done` are unchanged: they reap first and remove the record after, so the watch usually has nothing to do (PB-2.1).

- **`done` left the worktree of a squash-merged branch behind and blamed a conflict.** Cleanup decided by a re-merge, and that question stops having an answer the moment the base moves over the same lines — after a squash and a second worker on the same file, `git merge-tree` conflicted on a branch whose work was already in. A second measurement now answers where the merge cannot: the branch's own patch id (`git patch-id --stable` over `git diff <fork> <branch>`) looked for among the commits the base gained since the fork. The report names the state instead of the obstacle — `merged as a squash`, `is entirely in <base>`, `is not merged` — and recognition stays deliberately narrow: a squash whose content was edited while merging, and work taken as several cherry-picks, keep the directory, because a directory is cheap to delete and impossible to return (PB-6).

- **The Cursor stall report fired on a session that was editing files.** Liveness had two signals — the chat transcript growing and an instrumental process under the session's tmux pane — and both are blind to the same phase: the agent edits files itself, inside one long call, and spawns nothing. Twice on live runs a participant was announced stalled while the owner's panel showed sixteen files edited. A third signal now covers it: how long ago the participant last wrote in its own working tree, the newest mtime among `git ls-files -mo --exclude-standard` plus its HEAD commit time. It is positive only — a recent write lifts the verdict, no write raises none — and the verdict names every measurement and its span, because an orchestrator has to tell a silent transcript from a dead session (PB-7).

- **The one message an operator sees at an undeclared harness sent them to a command that does not exist.** `--harness <name>` outside the workspace tool manifest was refused with `Declare it: promptobus tools add <name>`, and there is no `tools` subcommand. The refusal now names the file and the field instead — declaring a harness is a hand edit — and the only command left in the message is the host's own sync, which exists. A gate reads the dispatcher's own `case` labels and fails on any command string under `lib/` that is not among them, so the next inherited command cannot arrive quietly (PB-1).

- **`HostClone` now leaves the package.** `PromptobusHost.cloneOf(abs)` returns it and neither entry point re-exported it, so a consumer implementing the host could not name that method's return type without copying the interface — and `tsc` said nothing, because the interface compiles and the package builds; only the consumer's own build failed. It is in the `export type` list of `promptobus` and `promptobus/host` now, and the check that keeps those lists honest reads every `export interface` / `export type` out of `src/host.ts` instead of naming two by hand (PB-11.2).

- **The suite could reach a real user binary, count a neighbouring run's processes, and read a file from inside an unterminated string.** Six defects of one family, none of them shipped and all of them able to make a green run mean nothing: `PATH` is now sealed to one directory holding a symlink per binary the suite may reach, so a name nobody stubbed fails to resolve instead of launching whatever is installed; machine-wide `pgrep` patterns are qualified by a path the run alone owns, after two runs 3.2 s apart reddened the same check in both by counting each other's pids; the temp-directory sweep sentinel reads both spellings of `tmpdir()` and gained the eight prefixes it had never demanded; the package import scanner is a tokenizer that knows strings and comments, after a message fragment `' from '` was read as a module specifier and everything past it parsed from inside a string that never closes; nine checks that asserted the absence of text nothing writes are gone or made real; and the home diversion every suite file needs now lives in a module every file imports first, rather than in a helper 22 of the 46 files never load (PB-2, PB-2.2, PB-4, PB-9.1, PB-14.4, PB-14.5).

- **The publicity audit reads no link out of a code span or a fenced block.** A markdown sentence that quoted the link pattern was reported as a link to its example, so the gate refused documentation about its own rules (PB-22).

## [0.2.1] — 2026-09-05

### Changed

- **`spawn` keeps the brief as a task artifact.** The assignment file the orchestrator passes was read into the participant prompt and forgotten, so orchestrators invented a home for brief files outside the bus. After a successful lift the brief is copied into the task files folder as `brief-<worker>.md` — next to the review diffs — and the lift output names the path. Every lift stores the brief it was given: a repeat at the same address takes the next number instead of overwriting the previous assignment, and a refused spawn keeps nothing (PB-10).

## [0.2.0] — 2026-09-05

### Changed

- **Host contract: `cloneOf(abs)` replaces `reposRoot()`.** The host names the clone a directory belongs to and its namespace path; the package no longer walks a single "repos root" or requires a two-segment namespace — `need-pair` and `cwd-need-pair` are gone from `reviewLayoutError`. A host with several zones (`repos/<group>/<repo>` beside `external/<repo>`) could not be expressed before (PB-5).

## [0.1.0] — 2026-09-04

### Added

- **Public repository skeleton:** package manifest, MIT license, backslop tracker layout, and a GitHub Actions matrix for Node 20.
- **The bus itself:** TypeScript core with tasks, mailboxes, artifacts and the driver contract; a JavaScript runtime; drivers for Claude Code, Cursor and Codex; and the `promptobus` command.
- **A host contract instead of an ambient workspace:** `PromptobusHost` is passed explicitly on every call, with a standalone implementation that reads `cwd`, Git and `promptobus.json`. A consumer with no previous store declares no legacy layout, and that is a normal state rather than a failure.
- **Documentation for a first-time reader:** README in English and Russian, an architecture decision on the standalone boundary, and guides for installation, hooks and trust, and contributing.
