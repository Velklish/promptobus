# PB-161.2 · Result

**Closed 2026-09-11.** Done: a Codex reviewer now works in a directory of its own, and that directory is trusted.

**The decision and why.** The review procedure arrives as a module skill, so a reviewer without the canon is a parity hole rather than a Codex property. And ADR-007's reason for withholding trust — the repository being judged would put MCP servers into the session judging it — dies the moment the cwd is the mechanism's own directory rather than the reviewed tree. The shape follows Cursor's `reviewSandbox`: `<participant settings stem>.codex-sandbox`, deterministic so `--dry-run` prints the real path; the skills copy and the `.codex/.gitignore` land there; the trust record became `trustPath(workdir)` for BOTH roles — a deletion of the role branch, not an addition; the reviewed tree is attached through `addDirs` → `runtimeWorkspaceRoots`; `done` sweeps the directory by address stem without asking the driver.

**The trust record goes into the participant's disposable `CODEX_HOME` and never into the owner's `~/.codex/config.toml`,** and the suite asserts the FILE rather than the text. That boundary is the point of the owner's isolation decision behind PB-161: the owner's own config still carries a stale `[projects]` entry pointing at a deleted spike directory, precisely because it was written down nowhere.

**A silent mutation probe found a regression of this task's own making.** Removing `mkdirSync(workdir)` from `spawn` changed nothing in the suite — because the stand-in app-server records the cwd it is handed and never enters it, so a missing directory would be noticed only by the real binary. The case is real and common: in a workspace with no `.codex/skills` canon a reviewer's plan yields no launch file at all, and nobody creates the directory. Creation moved into the plan — `.codex/.gitignore` is written for a reviewer independently of the canon, and that file creates the directory; the task store may itself sit inside a git tree, where the directory has no business appearing in a diff. The property is now a check on a pure function, and the probe bites.

**A second silent probe turned out to be dead code**, not a hole in the test: the branch recognising a claimed directory by the file's own path was unreachable, because the copy destination already passes through the claimed directory. The branch was removed and the property it guarded became a check; the reference and CHANGELOG were rewritten, since they promised two forms where only one is honest.

**The promise about the sandbox is as wide as the check that pins it** — after review pointed out it was not. The claim «nothing else is written into the reviewer's directory» was pinned by reading `<sandbox>/.codex` only, so a file dropped into the sandbox ROOT — which is the working directory of the trusted session — would not have tripped it. Both are asserted now; the probe adding `<sandbox>/AGENTS.md` turns the check red (183/186) and was green before the widening.

**Written down rather than assumed: why the sandbox is neither wiped whole nor denied trust.** Inside the mechanism nobody can write there — a Codex worker's writable roots are its worktree and rule directories, the task store is not among them; a reviewer is read-only and mutating approvals are refused before containment; `done` sweeps the directory between tasks. The remaining writer is outside the mechanism, and there the asymmetry with the participant home matters: the home is defended because `$TMPDIR` is shared with every user of the machine, while the task store belongs to the owner — whoever can write there can edit the mechanism's own code. ADR-008 names three conditions for revisiting, and says the check is what will report them first.

**ADR-008 written; ADR-007 cleaned by deletion with a pointer** — no strikethrough, no "superseded" prose around live text.

Probes: reviewer returned to the reviewed tree → three red; the role branch in the trust record restored → red; `sayReviewerHome` removed from the live lift → «(no line)»; `<sandbox>/AGENTS.md` added → 183/186.

**Left open, and this is the load-bearing one.** It is not measured whether Codex reads `.codex/skills` from a directory that is not a git repository — the sandbox is not one. Cursor needs `git init` for a measured reason (`.cursor/mcp.json` is read only inside a repository); Codex takes its MCP set from the participant home's `config.toml`, and no observation demands a repository, so no precondition was invented on a guess. **If the answer turns out to be «a repository is needed», the parity hole this task declares closed is still open.** [PB-161.3](../../backlog/active/PB-161.3-codex-reviewer-sandbox-not-a-git-repo.md) names the measurement: a stub skill carrying a marker, a lifted Codex reviewer asked to return it, two runs against the same sandbox path — as the lift leaves it, and after `git init -q` — with the marker in the reviewer's `result` as the observable. It costs one paid turn; this run had no budget for it.

**Also open, stated in ADR-008 itself:** the trust record gives a reviewer nothing applicable today — trust opens a project's own `.codex/config.toml` and `.codex/agents`, and the sandbox has neither. It is taken for symmetry and because the alternative is a role branch whose stated reason is no longer true. And «a lifted Codex reviewer reads a skill from the workspace canon» is proven only as far as the stand reaches: the canon is in the reviewer's working directory at lift and the reviewed tree kept its own files; that the harness then READS it is PB-161.3's measurement.
