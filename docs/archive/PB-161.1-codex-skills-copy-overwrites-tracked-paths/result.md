# PB-161.1 · Result

**Closed 2026-09-11.** Done, and done harness-neutrally rather than as a Codex-local skip.

**The decision and why.** The guard already sat in `writeLaunchFiles`, a harness-neutral function — only its needle was spelled `.cursor`. A Codex-local check would have left the Cursor hole warning-only and re-created exactly the per-harness asymmetry the card asks to remove. A driver now names the directories its launch files claim (`launchDirs`: `.cursor` for Cursor, `.codex` for Codex, none for Claude Code — its configs go to the task store), and the caller asks Git about them.

**Review then found the first form of that guard false-positive, and the fix went to the cause rather than to the wording.** `git ls-files -- .codex` listed everything tracked under the directory, while the lift writes exactly two paths — so a repository lawfully tracking `.codex/config.toml` or `.codex/agents/*`, which is precisely what the ADR-007 trust record exists to let a participant read, got a warning on EVERY worker lift, and both halves of it were false. The guard now builds its pathspec from the paths the lift writes; `launchDirs` keeps its one job, marking where a launch file's absolute path stops being the workdir. The copy destination is among those paths, so the true case survives: a directory in a pathspec covers its subtree, and that subtree is what the copy erases. An older Cursor false positive on `.cursor/rules` died with the same change.

**Closure is pinned by a NEGATIVE test, not only a positive one.** A clone tracking `.codex/config.toml` and `.codex/agents/reviewer.md` gets silence at lift, and the test separately asserts those files are still in the index afterwards — so the silence is the guard's judgement and not a tree that lost them.

**The exported contract was rewritten to the semantics that hold.** `launchDirs` in `src/driver.ts` is public surface (`promptobus/driver`), and its docstring still described the refuted semantics after the guard changed; it and the two driver declarations that repeated it now say that Git is asked about the paths the lift writes, never about the claimed directory as a whole, and that a declared directory is not a claim on everything under it.

**Left open, stated rather than hidden.** The `plan.driver.options.launchDirs` argument at the `review.js` call site is uncovered: the probe is silent because the line is inert today for all three drivers — Claude Code claims no directories, and the Cursor and Codex reviewers write their launch files into their own directory rather than into the reviewed repository. Covering it needs a stand-in driver that seats a reviewer in the reviewed tree AND claims directories, which is a test for the test's sake; removing the argument is worse, since symmetry with `spawn` is the only thing that keeps `review` from losing the guard the day such a driver exists.
