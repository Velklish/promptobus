The Codex holder's path containment for mutation approvals no longer compares raw string prefixes: `containmentPath` in `lib/codex-session.js` resolves each root (`cwd`, `addDirs`, from the record, never from the request) and each target segment by segment, left to right — a `..` is applied to the already-resolved prefix, never to text; a symlink's content, relative or absolute, is pushed onto the pending segments (an absolute one restarts the prefix) rather than collapsed with `path.resolve`; a missing segment starts a `missing` tail in which `..` pops and any other name is appended without a lookup, and when the tail empties the lookup resumes, so a non-existent segment cannot hide a later symlink; link expansion is capped; a dangling link counts as present and is followed; any resolution failure (ENOTDIR, EACCES, a loop, an unreadable link) answers `null` and denies with its own reason.
