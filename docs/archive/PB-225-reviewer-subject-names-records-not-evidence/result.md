# PB-225 · Result

**Closed 2026-09-17, completed under contract 1 of the two the card offered.** The review subject now lists every file the reviewed address attached to the task — landed name, the type the name claims (`gate record`, `handover record`, `other`) and the send moment, in send order — and not only the two schema-shaped records. The list is built by `attachmentsOf(home, id, participantId)` in `lib/store.js` from the task journal and rendered by `attachedFiles` / `recordKind` / `attachmentEvidence` in `lib/review.js`, which put the block above the two record blocks in the first prompt and in the re-review branch alike. Only the reviewed address's own files are listed; an artifact from the orchestrator or another participant is not this author's evidence. The contract sentence lives once, as `ATTACHMENT_CONTRACT` in `lib/handoff.js`, and is quoted word for word by the reviewer subject and by the worker preamble in `lib/spawn.js` — two copies could drift, one cannot.

**Why contract 1 and not contract 2.** Contract 2 — evidence outside the handover record does not exist for the reviewer — is the cheaper sentence but the wrong one against the incident that opened the card: the `mutationProbe` field of the handover record is singular, and one of the workers of that run had thirteen probes. Taking it would have meant growing the schema into a list before the defect could be closed at all, and it would have made a file that was genuinely attached still invisible. The run owner chose contract 1. Nothing in this change forbids taking contract 2 later.

**What makes a false «no mutation probe on record» report impossible by construction rather than by diligence.** The journal is the only place that binds a sender to an artifact, and it is written by the send itself, so the list has no filter a file can fall through: no stem pattern, no schema shape, no author label. `recordKind` only labels a line, it never drops one. All three states are said out loud: an address that attached nothing gets «attached nothing to this task, and that is the whole list rather than a gap in it», a short list names what it could not read, and a subject that is no participant worktree gets its own line — an omitted block would read as «nothing attached», which is the very report the card exists to prevent. Two silences remain by design, and both are deliberate: a piece already swept, where the record is gone from the folder and from the attic both, and a journal id outside the record-id grammar, which becomes no path and therefore no line.
