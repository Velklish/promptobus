# PB-122 · Result

**Closed 2026-09-07.** Completed. `run` now hands the caller's environment to `planRun` (`{ env: options.env ?? process.env }`), so on win32 path resolution reads the same environment the child is launched into instead of the parent's. POSIX behaviour is byte-identical: `planRun` returns on its first line for any non-win32 platform, before `env` is read at all, so the third argument is constructed and discarded there. The change is also consistent with what POSIX actually does rather than merely harmless on it — libuv replaces the child's environment and then `execvp`s, so `options.env.PATH` already governed resolution, and win32 was the only branch reading a different environment than the one it launched into. `wouldResolve` now delegates to `resolveCommand` on win32, which is the PATHEXT search, and keeps the POSIX exec-bit walk unchanged below it; without that, every trace line on win32 read `(unresolved)` and the escape gate that consumes it reported a clean run with zero evidence.

Adding Windows to the CI matrix stays out of scope, as the task says: this makes the existing win32 branches correct for when that happens or for a Windows host today.

**Verification.** New cases in `test/promptobus-copy.test.mjs` drive the real `run` → `trace` → `planRun` path with `process.env.PATH` and an explicit caller `env` both holding the same binary in different directories. Before the fix: exit 1, 15/17 — the plan verdict red on the identity of the chosen directory (it took the parent's), and the trace verdict red on `(unresolved)`, which is exactly the "escape-gate evidence is empty by construction" half of the finding. After: exit 0, 17/17. A review round hardened the trace verdict, which read the trace file with a bare `readFileSync` twice and would have thrown and aborted the whole suite file in the reachable state where `trace` swallowed its own append failure; forcing that failure now yields a named red verdict with `(missing)` and the file continues (exit 1, 16/17). An unused `platform` parameter added to `wouldResolve` was dropped in the same round — nothing called it. All three gates green on the branch tip: `npm test` exit 0 (48/48), `backslop lint` exit 0, `npm run audit` exit 0.
