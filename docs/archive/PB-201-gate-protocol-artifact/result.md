# PB-201 · Result

**Closed 2026-09-12.** Done. A worker's gate claim now leaves as a machine record instead of a sentence: `schemas/v1/gate-record.schema.json` defines one entry per gate command — the command as executed, its exit code, the counts the runner printed, the sha the run was made on, whether the tree was dirty, the timestamp and the participant address. The document is attached through the door that already existed, `artifactPath` on a send, and named `gates-<worker slug>.json`; `lib/review.js` resolves every such file of the task into absolute paths and puts them into both the first prompt and the re-review prompt from one place, so the two cannot diverge. The reviewer already reads that directory and its permissions did not change.

**Two readings of the card were corrected rather than obeyed, and both would have shipped a dead mechanism.**

The card says "tree sha". Taken literally as a git tree object that comparison would never have matched anything: what the reviewer is handed in its own prompt is `worktree HEAD <sha>`, a commit sha. The field is the commit sha, and the toolchain's own runner prints the same pair — `backslop gates` closes its output with `tree: <sha>, dirty|clean`, which is independent of this work and was found in a baseline log rather than reasoned out.

The card's Checks claimed the sha comparison catches a record claiming exit 0 for a tree whose tests fail. It does not: an author can write zero beside the correct sha having run nothing. The record binds a claim to a tree; forgery is caught only by a re-run on the same sha by someone allowed to run, and neither the record nor the reviewer is that someone. The limit is written in the protocol reference, in the reviewer preamble — where the claim is read, not only where documentation is — and a check asserts the preamble still carries it. The card was corrected in the same pass.

**The bound was measured, not chosen.** One green `gates` run prints 350 480 characters; a command's own summary sits in its last five lines, 260 characters; the longest red diagnosis measured here runs 2 450 characters over its last twenty. `GATE_TAIL_MAX` is 2 000 per entry and at most 16 entries, so a record carries the summary and sixteen lines of a failure and refuses a wall of repetitions — the case where the log, not the record, is the right place.

**What happens when a gate is absent is decided, and the mechanism cannot do two things silently.** A record with exit 0 whose sha matches is evidence. A non-zero exit, a dirty tree, or a sha that differs is not evidence about the reviewed tree, and the reviewer says which of the three it was; acceptance proceeds with the gap named as a decision rather than as a fact. A command not run at all has no entry, and the header carries an explicit "not run, because …" — an absent record with no such line reads as the second case, never as green.

The machine form of that run is itself the first live sample: `gates-pb-prompts.json`, five entries, ajv-valid against its own schema, and the approver compared its `tree` field with the branch head before accepting — the ritual the card exists for, performed by the role it was designed for. Nine mutation probes, each red with the mutation and green without.

Three of the four probes added in that round reinstate a finding and the suite refuses it: the short-sha pattern, the impossible artifact rule, and the tree-versus-commit claim are red tests now, not corrected sentences that could be uncorrected.
