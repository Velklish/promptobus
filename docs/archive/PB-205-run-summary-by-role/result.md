# PB-205 · Result

**Closed 2026-09-13 after six review passes.** The card asked for a close-time run summary by role, and it delivered one: additive nullable `idleSec` and `deliveryLatencySec` on participant rows, a projection at close reading canonical message times and the warden's delivery history, and `telemetryStats` grouping saved rows by task and role with the bottleneck taken from summed `durationSec`. What the card did not ask for, and what turned out to be the real work, is the class the reviewer found underneath it.

**One class, eleven findings, six passes.** Every one of them was the same sentence in a different place: *an absent value becomes a default, or partial coverage becomes a scalar.* Role quota percentages were summed across participants with different denominators and double-counted overlapping roles on one account; `window.scope ?? null` turned an absent scope into the explicit whole-account scope; quota coverage was computed only over rows that already had a window, so a participant with `windows: []` vanished and the remainder reported `measured`; `summaryValue` returned a scalar after one sample, so two workers with `[100, null]` reported `100` and the missing participant was indistinguishable from a zero contribution; the measured-records counter kept incrementing for windows whose evidence had been rejected, so a role read `ambiguous` with `quotaEvidence: []`; the window key was not canonical, so duplicate model ids passed against `uniqueItems` and property order became part of window identity; and the door itself accepted schema-invalid objects with extra keys.

**The turn came at the fifth pass, and it is the lesson worth keeping.** Four passes had been spent fixing addresses; each time a new address appeared. The reviewer's diagnosis was structural: validation was split among the key, the scope and the delta projections instead of producing one trusted representation, and every seam between them was a hole. The fix stopped being a patch and became `trustedQuotaWindowOf` — a single door that takes a raw window and returns either a validated representation or a refusal, checking object-ness, the `kind` enum, both endpoints in 0…100, canonical scope and an exact own-key set. Group discovery, matching and role state consume only its result and never read a raw window. After that, the class stopped recurring inside quota; the last two findings were its neighbours, not its descendants.

**A second lesson, and it cost me a wrong assumption.** A parity assertion between the public TypeScript and the private JS implementation was added in the second pass, and I treated it as protection. It is not: the fourth-pass major was **identical in both copies**, so parity stayed green while both were wrong. Parity establishes agreement, not correctness. That is now `PB-212`, with the mutation probe that proves it — introduce the same error in both copies and watch the suite stay green.
