# PB-208.1 · Result

**Closed 2026-09-16, completed.** Removing a blob raced a publication path that took no lock, and the question "does anything still name this payload" had two answers. Both are gone. **The publication takes a lock of its own** — `.lock-blobs/`, not the journal lock: the journal lock is held by a sweep across `git worktree remove`, so routing publication through it would have made an ordinary artifact send refuse with `lock-busy` because of git. The sweep of artifacts takes the same short lock, so a blob can no longer be removed while a sender is between its payload and its record. **"A payload nobody names" is one function**, `blobNamed` in `src/v1/artifacts.ts`, and it counts a hard link as a name — a payload the task's `files/` folder still shows is not listed as nameless, because that entry is a name a human reads. The records are read **once, after the lock is in hand**, and the only later change to that set is the sweep's own removals, tracked as they are made: the earlier cut re-read every record per blob, which is quadratic in a task's artifacts. **`withDirLockAsync` no longer inherits the synchronous nesting licence:** `heldSync` (the licence) and `heldAsync` (an in-flight holder) are separate, asynchronous holders of one lock path queue inside the process, and a synchronous take over a live asynchronous holder is refused outright with its own code `lock-self-async` — the wait there is `sleepSync`, which would block the very loop that has to release the lock. The asynchronous path waits on a timer rather than on `sleepSync`, so a `send` carrying an artifact no longer freezes its own session's event loop for the whole of another process's hold.

**What the race cost, measured rather than argued.** 1000 sends of each shape per run, three runs per arm, `process.hrtime.bigint()` around `engine.sendSync`, arms interleaved by rebuilding `dist/`: a message with **no** artifact pays nothing — the lock is not taken on that path at all, and the two arms sit inside each other's run-to-run spread (p50 1.58 against 1.60 ms). A send that **carries** an artifact pays about **0.45 ms** at p50 (3.60 against 3.15, medians of three medians), the cost of one `mkdir`, an owner write and an `rm -r`. The snapshot replaced a per-blob read: one `orphanBlobs` over 400 artifacts went from **3783 ms to 15.7 ms**.

**The race is reproducible, and the stand does not judge by a clock.** `test/v1-races.test.mjs` holds a real second process inside the publication stretch and runs the sweeper as a third, which marks the instant the publication lock is in its hands; the assertion is made on that mark, and entering the window is asserted separately, so a run that missed the window fails rather than passing on vacuous checks. The sender marks the window from inside the `blob` fault hook and leaves on the parent's word, not on a duration. The only clock left is a 400 ms ceiling on the negative claim — "the sweeper did not hold the lock" — and it is measured against the thing it must outlast: an unblocked take of this lock is **0.173 ms at the median, 0.617 ms at p95, 1.142 ms at the worst of forty**.

**Review, three rounds.** Round 1 raised three remarks against this card — `withDirLockAsync` inherited the `held` short-circuit that is sound only for a synchronous frame; the stand held its window on a wall-clock budget and never awaited the hook's promise; `blobNamed` re-read every record per call under the lock — plus the `orphanBlobs` docstring that still described the old meaning and a figure quoted two ways; all closed in `3163821`. Round 2 raised two — `senderStillHeld` read a mark one line before the parent wrote it, so the check was true by construction, and the self-async refusal threw a bare `Error` past the `DirLockOptions` contract, which hands refusal wording to the caller — closed in `7dc22d9` together with the `sleepSync` freeze. Round 3 raised one: `assert.ok(before >= 5)` was a threshold about **scheduling**, not about the lock — Node does not catch up missed `setInterval` periods, so one loop hiccup coalesces them and the check goes red with no defect behind it. One tick carries the whole claim, and probe 11 was re-run on the amended head to show the threshold plays no part in catching the defect: under the mutation the take sits out the full 5000 ms and throws `busy` before any assertion is reached.

**What is left open.**

- **`send` reads a record file twice** — once for the schema check and once for the blob write. Bounded by the schema and inside the 0.45 ms measured above, but it is a second read of the same file.
- **`lock-self-async` has no caller in the tree that can reach it.** That is the design — no lawful case exists — so the test plants the state directly; the refusal text is what a future caller would have to read.
- **The `nlink` branch on a filesystem without hard links is untested.** The count is omitted and the twin's name still reported; the suite has no portable way to produce such a filesystem.
- **Three comment runs of this code stand over the owner's two-line limit** on the merged tree — `src/fs/lock.ts:57`, `src/fs/lock.ts:161`, `src/v1/artifacts.ts:243`. They are the text the review asked for, in files the PB-227 sweep had cleared; filed with its measurement as PB-208.2.
