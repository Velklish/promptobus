# PB-159.1 · Result

**Closed 2026-09-16, by the first of the card's three options, and narrowed where it could not be met.** The card asked to pick a policy for a shared machine: the runner reports the load beside a red, or worker regulation limits full gates to one per machine, or budgets scale with a declared load factor. The first is taken — the second and third change how a run is scheduled and are the owner's. Four of the five named sites stopped depending on their neighbours; the fifth did not, and it left as its own finding rather than as a claim.

**The runner now says what the machine was doing.** `test/run.mjs` prints the core count and the load average before the pool, the load average before the serial group, and, for every failed file, the load when it started and when it finished — with the sentence `the load average is the MACHINE, not this run` beside it and the discharge it demands: that file standalone twice AND on the base commit, exit codes for each. The load is a candidate explanation and never a verdict. On a platform with no load average `os.loadavg()` answers three zeros; that is the answer, and it is printed as one rather than hidden.

**The classifier the card's wording invites was deliberately not written.** A runner cannot see the form of an assertion from the outside, and a hand list of "files with budgets" would rot exactly the way the sweep prefix lists do, with no sentinel able to catch it. So the runner records what it can measure and leaves the reading to the person. This is a narrowing of the card, stated rather than slipped past.

**Four of the five sites stopped measuring their neighbours.**

- `test/promptobus-driver-codex.test.mjs`, the `long-first` lift window: the fixture's own 3000 ms budget is gone and the stand's 20 s applies. The subject there is that the lift SUCCEEDS; a 3 s window measured the machine instead.
- `test/promptobus-cursor-wake.test.mjs`, step 5: the wake one step above holds the inject lock through its own pauses, and under load it still held it when the delivery ran — so the refusal spoke about a neighbour's clock rather than about queueing. The file now waits until no live process holds the lock, the rule `takeLock` itself uses, and asserts that on a line of its own. The lock path comes from production — `lockFile` is exported from `lib/cursor-persist.js` for it — rather than being spelled in the test, because a drifted suffix would make every poll read nothing and pass the precondition on the first one. What the wait cannot do is close the window: the warden is alive beside the test and may take the lock again between the last poll and the call, so the title claims only what a poll proves — the previous writer let it go before this delivery.
- `test/model-routing-adapter-cursor.test.mjs`, the probe budget: the shared default becomes `VERDICT_BUDGET_MS` of 60 s, because these checks' subject is the VERDICT and 10 s did not let them see it — under load the probe answered past it and `quota_unknown` came back as `probe_timeout`, which is a statement about the neighbours. One probe costs about 0.5 s idle on this tree, so 60 s is a hundredfold margin, and a genuinely hung probe still reddens as `probe_timeout` well inside the file watchdog of 240 s rather than taking the file down.
- The same file's checks whose subject IS the deadline are untouched: **three** of them carry their own 300, 700 and 2000 ms and the new default cannot reach them. A fourth check has a wall-clock assertion and takes the default on purpose — `the probe does not block the event loop` asserts a counted tick and a LOWER bound on elapsed time, neither of which raising an upper bound can break.

**The fifth site is not closed, and it is not one defect.** Step 7 of `promptobus-mixed` has two different reds under one title: a verdict that races the re-knock — a candidate in the mechanism, in `stallStands` for `stall.kind === 'unknown'`, which is a hypothesis and not a reproduction — and a tmux server that vanished under a persist session on a clean CI runner, which is a different class entirely. There is no reproduction for either, so nothing was changed there; both are written up with their evidence as **PB-159.3**, which stays in `triage/`.

**Verification.** Mutation probes, taken after the commits on a clean tree:

- silencing the runner's load lines — `npm run probe -- test/run.mjs --mutate 's@load average @load avg @g'` — mutated → exit 1, restored → exit 0, reddening both new runner checks.
- removing the lock release — `npm run probe -- lib/cursor-persist.js --mutate 's@    rmSync\(lock, \{ force: true \}\);@    /* probe: the lock is not dropped */@g'` — mutated → exit 1, restored → exit 0, and the FIRST thing to redden is step 5's new precondition, which is the check claiming that property.

**The raised budgets are not provable by a probe, and that is a property of what they are.** A probe shows a check has a subject; raising an upper bound removes a failure mode rather than adding an assertion, so there is nothing for a mutation to break. What stands in its place is measurement: one probe costs 481 ms on an idle machine, so the old 10 000 ms was a twenty-fold margin that load still ate, and the new one is a hundredfold. The raise costs nothing in wall time — the file runs 46 of 46 in 16 198 ms after the change against 16 333 ms before it, both idle. The `long-first` window is the same case — the stand's 20 s is the budget the stand already declares.
