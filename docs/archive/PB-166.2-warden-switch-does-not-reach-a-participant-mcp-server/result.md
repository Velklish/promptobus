# PB-166.2 · Result

**Исход:** закрыта.

**Что сделано.** `mcpConfig` в `lib/driver-codex.js` собирает `env` записи шинного MCP-сервера, а не наследует его, поэтому переключатель, стоявший на поднимающей команде, до этого ребёнка не доезжал. В `extra` добавлены `WARDEN_ENV_VARS` — `PROMPTOBUS_WARDEN` и `PROMPTOBUS_WARDEN_TRACE` — рядом с файлом сессии и условным `PROMPTOBUS_CODEX_HOME`. Имя пишется только если оно стоит в поднимающем процессе: незаданное не появляется в записи, поэтому боевой прогон не меняется. Граница изоляции набора записана в `contributing.md` § Suite isolation.

**Чем проверено.** `test/promptobus-driver-codex.test.mjs:1262–1284`: при `PROMPTOBUS_WARDEN=off` и сентинеле трассы на поднимающем процессе запись шины несёт оба имени; при снятых — `!('PROMPTOBUS_WARDEN' in wardenOffBus) && !('PROMPTOBUS_WARDEN_TRACE' in wardenOffBus)`. До правки — живой замер, с которого карточка началась: родитель warden'а (PID 7662) это MCP-сервер участника (7656), и `ps eww` по нему не показал ни одного из двух имён.

**Что осталось за карточкой.** Claude не несёт эти имена и не должен: его MCP-ребёнок наследует окружение слиянием, 99 имён — измерено в `PB-171`. Cursor закрыт там же.
