## Context

### `test/promptobus-host.test.mjs` — a dead Russian-localized bus-hook header

Found while translating this file for PB-9. Two `check()` conditions accept either the real
English bus-hook header or a hypothetical Russian one:

```js
check('bus hook substitutes host commandName, not a hardcoded name',
  hookA.includes('Generated by alpha sync') && hookB.includes('Generated by beta sync')
  || hookA.includes('Сгенерирован alpha sync') && hookB.includes('Сгенерирован beta sync'),
  hookA.split('\n')[1]);

const planned = planPromptobusHooks(hostA);
check('hook plan writes the standalone bus-hook path',
  planned.rel === path.join('.promptobus', 'hooks', 'bus.mjs')
  && (planned.text.includes('Generated by alpha sync') || planned.text.includes('Сгенерирован alpha sync')),
  planned.rel);
```

Evidence that the Russian branch is unreachable, run in this tree:

```text
$ grep -n "Generated by\|Сгенерирован" templates/bus-hook.mjs src/hooks.ts
templates/bus-hook.mjs:2:// Generated by __COMMAND__ sync. Edits are overwritten — the source lives in the Promptobus package.
```

`renderBusHook` (`src/hooks.ts`) substitutes `__COMMAND__` into this one English template; there is
no localization branch anywhere in `src/` or `lib/` that would ever produce the Russian header. The
Cyrillic half of each `||` is not a fixture standing in for a person's words or for real mechanism
output — it is dead test logic that has never been exercisable, most likely a leftover from before
the project standardized on English output.

Translating it in place (PB-9's usual move) would keep asserting on a string the code can never
produce; deleting the dead branch instead changes what the check accepts, which PB-9 draws out of a
worker's scope ("a check whose translation would change its meaning is a finding, not a rewrite").

### `test/promptobus-mcp.test.mjs` — a dead "re-arm the wait" hint, seven checks

Found the same class of problem during review of PB-9: seven negations across six `check()` calls
assert that the mailbox/task/send responses do **not** contain a since-removed Russian hint
("run the wait again" / "mailbox taken"):

```text
$ grep -n "запусти ожидание снова\|mailbox забран" test/promptobus-mcp.test.mjs
246:  !/запусти ожидание снова/.test(text(got)) && !/mailbox забран/.test(text(got)), text(got));
248:  !/запусти ожидание снова/.test(text(again)), text(again));
258:  && !/запусти ожидание снова/.test(text(onlyChannel)), text(onlyChannel));
265:  !/запусти ожидание снова/.test(text(taskNoHint)) && !/запусти ожидание снова/.test(text(sendNoHint)),
512:  !/запусти ожидание снова/.test(text(alienInbox)), text(alienInbox));
808:  !/запусти ожидание снова/.test(stalledInbox), stalledInbox);
```

```text
$ grep -rn "re-arm\|rearm\|wait again\|запусти ожидание\|mailbox забран" lib/ src/
(no output)
```

The hint text exists in neither language anywhere in the current mechanism (the file's own
comment at line 241 confirms it by design: "nobody carries the ... hint anymore"). A negation
against a string that never occurs in any language is vacuous — it passes regardless of what the
tool actually prints, so it does not guard against the hint's reintroduction the way its title
claims. Per review decision, these seven were left as dead branches rather than rewritten or
deleted: each check title now carries "(dead branch, PB-9.1)" and each site got a `// dead: ...`
comment, but the checks and their vacuous conditions are otherwise untouched, awaiting the same
call as the host-test branch.
