# PB-157 · Result

**Closed 2026-09-07.** Completed. `planReview` now takes the patch, the stat and the tracked-tree state from a single `git diff --raw --stat --patch <base>`: the raw records of that same read say which tracked paths differed from `HEAD`, so the state cannot describe a different moment than the diff. That single-pass property is the whole repair — the defect survived a caller's own `git status` check taken seconds earlier, because the check and the diff were two reads of a tree the author keeps moving. The comparison still runs base against the working tree, so reviewing purely uncommitted work remains supported, and the separate `git diff --stat` call is gone.

The state now reaches all three readers: the command warns when it snapshots over a dirty tracked tree, on the plain run, the dry run and the re-review path; the reviewer prompt states it in words; and the participant journal carries `diffClean` and `diffModifiedTracked` beside the `diffAt` / `diffHead` pair, so `promptobus status` and `promptobus_task` can answer later what the terminal said once.

The reviewer's prompt was corrected in the direction that caused the damage. It previously modelled only staleness — content committed *after* the snapshot being absent — and told a reviewer to verify against the working copy, which is exactly backwards when a probe has the change reverted. It now warns in both directions, unconditionally rather than only on a dirty snapshot, and tells a reviewer that a contradiction between snapshot and working copy is not evidence of an uncommitted change: report it unresolved and hand the orchestrator `git show <sha> -- <path>` with the values substituted. That wording is deliberate — reviewer sessions on this bus commonly have command execution disabled, so an instruction to run Git themselves is one they cannot follow.

Two review rounds shaped it. The first found that the direction warning sat only in the dirty branch, leaving the clean-snapshot case — reviewer verifies later, author is mid-probe — producing the same false finding; that the stat and the untracked listing were still separate reads of the moving tree; that the reference promised prompt tokens the prompt does not emit; and that the journal was missing the third fact. The second pinned the relocated stat byte-for-byte and filled the escalation command's placeholders.
