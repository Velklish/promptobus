# PB-215 · Result

**Closed 2026-09-16, completed.** Every fail-open picker of a participant's status line is gone. A picker now compares the START of the line with the WHOLE address followed by the `·` separator — `line.trimStart().startsWith(`${WORKER} ·`)` — and a miss falls back to `''` instead of to the whole output, so it reddens rather than letting the regexps find their text on a neighbour's line. Matching the whole address is not decoration: one address contains another (`worker:hang` is a prefix of `worker:hangchild` and `worker:hangwrite`), and the order of the journal is not the suite's to rely on, because `upsertParticipant` moves a touched record to the tail. Where the fallback is `''`, the miss is given its own evidence — an empty string in the third argument of `check` says nothing about what the output did hold — so each of those sites passes `no "<address> ·" line in:` with the tail of the output.
