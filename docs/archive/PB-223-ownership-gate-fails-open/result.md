# PB-223 · Result

**Closed 2026-09-16, completed.** `ownership` answered `gated: false` — pass — whenever it had nothing to compare, so a shell carrying no harness identity variable reached `done` over **any** task in the store, a live foreign one included: the close stops participant sessions, removes their worktrees and deletes branches it judged merged. The answer now carries two fields that are not each other's negation. `allowed` is the right, granted only when the call names a session and that session is the recorded owner; `gated` keeps its old meaning — the call names a session, the task names an owner, and the two differ — byte for byte. `right` names which of `owner`, `ownerless`, `no-identity`, `foreign` and `other-address` the answer is, and both refusal builders are built from it: `unprovenOwnerLine` says what could not be proven instead of what was missing, and every branch of `ownerRoute` is walkable by the caller that gets it. The decision is [ADR-017](../../adr/adr-017-the-owner-gate-is-a-positive-proof.md).

**Why `gated` was kept unchanged.** `ownership` has two classes of reader with opposite defaults. The advisory ones — the foreign-mailbox heading, the unread tail, the `status` warning, the attach gates of `spawn` and `review`, the restamp door of `retitleTask`, the successor hint in `lib/guard.js` — must stay silent where nothing can be compared; the destructive ones must refuse. One field cannot carry both questions, and reversing the direction of `gated` would have moved the defect rather than removed it. A side effect worth naming: `lib/guard.js` needed no edit at all.

**A task with no recorded owner belongs to nobody, and the exception is named rather than silent.** The owner is written only when the environment supplied identity at creation, so nothing beyond "the caller named itself" can be proven about such a task, and exactly that much is asked: a session naming itself passes, a call naming nothing does not. The rejected alternative — refuse everyone — was rejected by measurement, not by taste: `claim` exists only in the MCP tool `promptobus_mailbox {claim: true}` and has no CLI verb (`grep -n "case '" lib/cli.js` lists 20 commands, `claim` not among them), so an ownerless task would have stayed unclosable forever together with its worktrees. Tasks opened before the owner mechanism existed need no migration for the same reason. `other-address` grants no right at all and has no refusal text either: the gate never looked the owner up, so `unprovenOwnerLine` and `ownerRoute` throw through the shared `requireOwnerGateAnswer` rather than print "records no mailbox owner" about a task that has one.

**The cost is named.** A shell with no harness identity can no longer run `done`, `stop` or `dismiss` — on any task. The route out is a session that names itself. This is written in ADR-017 § Consequences and in `docs/reference/03-cli.md`.

**Four suite files were given a stand identity, and that is a repair rather than a workaround.** `test/promptobus-done.test.mjs`, `test/promptobus-stop.test.mjs`, `test/promptobus-host.test.mjs` and `test/model-routing-telemetry.test.mjs` called `done`, `stop` and `dismiss` from a stand whose `test/hygiene.mjs` strips the harness identity variables, and they passed precisely because the gate opened outward. Each was given a stand identity, as `test/promptobus-sweep.test.mjs` already had. The coverage was measured, not asserted: base `3db1cc3` was exported with `git archive` into a separate directory, built, and the files run — 34/34, 17/17, 17/17, 80/80 on the base and the same on HEAD; the lists of check names matched under `diff`, 148 before and 148 after.
