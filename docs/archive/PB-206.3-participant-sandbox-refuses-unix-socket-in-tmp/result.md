# PB-206.3 · Result

**Closed 2026-09-13.** Completed, and the card's subject more than doubled on measurement. A participant sandbox refuses `listen` on a unix socket, so suite files that need one aborted mid-file and the participant could not run the gates at all — the gate was unreachable by construction, not merely red. The card named three files; measurement found **seven** (`promptobus-guard`, `promptobus-e2e`, `promptobus-mixed`, `promptobus-warden`, `tmpdir-sweep`, `promptobus-driver-codex`, `promptobus-harness`), and two of them show two independent boundaries depending on the working directory. The closure is a named skip: a check that hits `EPERM`/`EACCES` **from `listen`** is declared skipped rather than passed or failed; any other bind error stays a loud failure.

**What the measurement killed, and it was the obvious fix.** Relocating the socket under a writable root does not help: bind fails inside the already-writable `/private/tmp` by relative path and by absolute path alike, and `promptobus-driver-codex` fails on a socket in the system temp (`/var/folders/…`). What the sandbox forbids is the operation, not the directory — so adding another writable root would have been a repair that changed a path permission while the capability stayed denied.

**Verification.** Gates on the merged tree, commit `6a1d3e4`. On the worker's final HEAD `91da4b1`, outside the sandbox: `npm test` code 0, `65/65 test files passed`, and **zero** runtime skips — verified by grepping the log for the skip markers rather than by assertion; `audit`, `pins`, `lint` code 0. Inside the sandbox the same tree: `runner` 50/50, `warden` 247/260 with 13 skips, `tmpdir-sweep` 38/39, `driver-codex` 119/120, and the same files outside the sandbox give `warden` 264/264, `tmpdir-sweep` 39/39, `driver-codex` 201/201 — the skips exist only where bind is denied.

**Documentation in the same pass.** `docs/reference/03-cli.md`, `docs/reference/10-validation.md`, `CHANGELOG.md`, and the card itself, which now records seven files instead of three.

**What review cost, and it earned its place.** Two rounds, six findings, five of them one class — **the skip taken wider than the socket**. The first round's major was the sharpest: after a failed bind the STALLED block kept treating `knocks.length === 0` as a pass against a socket nobody was listening on, so seven assertions passed *vacuously* instead of skipping, and a regression that reused another task's wake endpoint would have been green. The rest were assertions swept under the skip that never needed a socket at all — an error on a non-existent socket, the `GONE` journal write, a stubbed knock, `stat.isSocket()`, an empty directory, an `inspect` of a synthetic `state: dead` record. The sixth was mine to answer for: I made the invariant `exit 0 iff failed === 0` an acceptance condition, and the test guarding it ran the failure and the skip **in different processes**, so a mutation where `skip()` cleared the exit code would have passed both probes. All six closed; the counts above are the evidence that the skips narrowed while live checks grew.

**Left open.** Two things, both named rather than worked around. The skip rests on an errno pair measured in one sandbox — a harness that refuses `listen` with a different code would fall through to a loud failure, which is the safe direction but not a proven one. And a bootstrap hole found along the way is fixed but worth remembering: a mutation probe whose verdict travels through the helper being mutated cannot see that helper break, which is why the verdict path now sets its exit code outside `check`.
