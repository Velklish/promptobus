# PB-50 · Result

**Closed 2026-09-07.** Completed. `run` now applies `timeout: PROC_TIMEOUT_MS` (60 s) and `maxBuffer: GIT_MAX_OUTPUT` (32 MiB) to every launch, so no harness call can reach `spawnSync` without a ceiling again. Both defaults sit before the caller's `...options`, so an explicit value still wins and `runProc`, `lib/worktree.js` and `lib/spawn.js` behave exactly as before — `worktree.js` keeps its ten-minute install timeout through the same two-level chain. The constants moved to the launch boundary in `lib/exec.js` and are re-exported from `lib/util.js`, keeping the established import surface. No consumer needed changing: a timed-out `run` still arrives as `error.code === 'ETIMEDOUT'`, which `bgSessions` already maps to `unknown`, a state the engine models explicitly.

The shared minute was accepted at both `lib/liftoff.js` call sites after checking them, as the task required, and that judgement is now recorded in the code rather than left implicit: the lift bounds the `--bg` registration and not the session's life, because session appearance is retried separately, and the registry read is measured at 0.34–0.41 s, so sixty seconds is a wedge ceiling and not a latency budget.

One effect outside the listed call sites, noted during review and kept: `worktreeTouchedMs` in `lib/cursor-persist.js` already carried a timeout but no output budget, so it moves from Node's 1 MiB default to 32 MiB. That is on the Cursor beat path and is an improvement — a dirty worktree whose `ls-files -mo` overflowed the megabyte used to read as "no writes", silencing the third liveness signal exactly when the participant was busiest.

Renaming `GIT_MAX_OUTPUT` was proposed in review and deliberately not done here: the name was already wider than git before this change, so it is not part of the smallest repair. Filed as PB-50.1.

**Verification.** A stand-in binary on the sealed PATH, driven through `bgSessions`, returns within the ceiling instead of hanging. Mutation probe with both defaults removed: exit 1, 15/17 — the timeout verdict red at 30.35 s and the output-budget verdict red; restored, exit 0, 17/17. The timeout verdict was hardened during review: its named half (`timed === null`) passed either way because empty stdout also yields `null`, so the discriminating half is the elapsed bound, now `sleep 30` against a 10 s line instead of `sleep 3` against 2 s, and the file says so. All three gates green on the branch tip: `npm test` exit 0 (48/48), `backslop lint` exit 0, `npm run audit` exit 0.

**Documentation in the same pass.** `docs/reference/03-cli.md` § Guard and warden — no driver call on the beat path may block without a ceiling; the reviewer walked that path looking for a counterexample and found none. Comments in `lib/exec.js` carry back the consequence sentence the move had dropped (an overflow makes a dirty clone read as "clean tree" or "state unknown", and the latter decides whether to clean a worker directory), and `lib/util.js`'s `runProc` header no longer claims the ceilings as its own contribution. `CHANGELOG.md` — an entry under `[Unreleased]`, including the Cursor effect above.
