# PB-213 · Result

**Closed 2026-09-16, completed.** The participant preamble already asked for the hand-off form and, since PB-201, for a machine gate record; what it never named were the checks that make a green run mean anything. Those checks are now a second document with its own shape — `schemas/v1/handover-record.schema.json`, beside `gate-record.schema.json` rather than folded into it, because "what I ran" and "what makes that run worth reading" are two different claims and a reader should not have to tell them apart by which fields happen to be present. The record binds to one tree and one base, both shas at full length, and carries five checks: the difference of verdict **names** against the base commit, the mutation probe with the `file:line` it broke and the names that reddened, `git status --porcelain` at both ends of that probe, every red called environmental with the same verdicts run on the base commit and the symmetric difference of the failure sets, and every gate command that was not run with its reason. All five are required. A check left out is not a check passed, and the only way past one is its own `notRun` branch carrying a reason — a check honestly declared impossible passes, because a form with no such branch rewards invented numbers.

**Each check refuses its own defeat in the schema rather than in prose.** A removed verdict name with no reason, a mutation that never applied, a probe that reddened nothing, a dirty tree at either end of the probe, a claim of "environmental" whose base run came back green, and a skipped gate with no reason are all refused by the document's own shape. Two choices inside that are worth naming. `mutatedRunExit` (`minimum: 1`, `maximum: 255`) records the exit code **of the run made with the mutation in place**, not of the probe tool around it: `npm run probe` exits 0 on its single passing outcome (`scripts/mutation-probe.mjs`), so its code says "the probe behaved" and nothing about the tree — and a run whose mutation reddened at least one verdict cannot have exited 0. And the interrupted run — the one that prints `0/1` against a base of 26 and reads as catastrophe when it means the run stopped — is caught by `verdicts.unaccounted`, a `const 0` the author computes and states: JSON Schema cannot compare two of its own fields, and PB-201 had already refused to pair a second validator with a schema here, so the remainder is made explicit by the author instead of inferred by the reader.

**The requirement reaches two preambles of the three, and that asymmetry is deliberate.** The worker attaches `handover-<slug>.json`; the reviewer is told to read it and to name the checks that are missing or marked `notRun`, running nothing itself (ADR-009) and producing no record of its own. The approver carries the gate record alone: an approver merges rather than writes code, and its own gate run **is** the integration gate, so the absence of a handover record under an approver hand-off is an expected state rather than a defect — the reviewer prompt says so out loud. `review` resolves `handover-*.json` into both the first prompt and the re-review prompt by the same mechanism that resolves `gates-*.json`, and keeps the two kinds apart; the "no record carries this sha" branch reads as a gap to name rather than as a green.

**The turn no longer ends free after a handover record.** `isHandoverRecordName` sits in `lib/handoff.js` beside `isGateRecordName`, and `handoffPendingVerdict` in `lib/guard.js` holds the turn on **either** record sent without a result — six lines, the narrowest edit that closes the hole, since a participant could otherwise send the new record and walk away from the result that names it.

**Verification.** Gates on the worker's head, on a still and fully committed tree: `npx github:Velklish/backslop#v0.8.0 gates` exit 0 — gates 4, green 4; `npm test` 69 of 69 test files, 2197 of 2197 checks; `backslop lint` exit 0, no errors, 1 warning; `npm run audit` exit 0 over 941 tracked text files and 134 packed entries; `npm run pins` exit 0, 941 of 941 read, 49 live refs in 13 files. `test/handover-record.test.mjs` is new and carries 18 ajv checks, including the negative control — an impossible check honestly declared passes — exercised on every one of the five; `test/promptobus-spawn.test.mjs` gained 6 (four on the preamble text, two on the guard), `test/promptobus-review.test.mjs` gained 4. The difference of verdict names against the base was measured rather than asserted, by `git show <ref>:<file>` over every `test/*.test.mjs` of both commits without switching branches: base 2369 names, branch 2400, **none removed**, 31 added.

Three mutation probes, each after a commit, each restored from the pre-mutation snapshot:

- `npm run probe -- schemas/v1/handover-record.schema.json --mutate 's/"const": 0/"const": 99/' --run 'node --test test/handover-record.test.mjs'` → exit 0. The refusal marker for the interrupted run was switched off; five checks went red, among them `PB-213: a probe that stopped before the base total is refused — the remainder is stated, not inferred`, assert `an interrupted run was accepted as a probe`.
- `npm run probe -- schemas/v1/handover-record.schema.json --mutate 's/"minimum": 1,/"minimum": 0,/' --run 'node --test test/handover-record.test.mjs'` → exit 0. The floor under `mutatedRunExit` was removed; red: `PB-213: the exit recorded is the mutated run's, and a mutated run that exited 0 saw nothing`, assert `the probe tool's own exit code was accepted in place of the mutated run's`.
- `npm run probe -- lib/guard.js --mutate 's/isGateRecordName\(name\) \|\| isHandoverRecordName\(name\)/isGateRecordName(name)/' --run 'node test/promptobus-spawn.test.mjs'` → exit 0. The guard stopped recognising the handover record; red: `PB-213: a handover-record artifact without a result blocks the turn too`, verdict `null`.

**One probe is recorded because it failed for the wrong reason.** The first attempt at the `mutatedRunExit` probe used a replacement containing `\n`, and the file went red on broken JSON rather than on the rule under test. Red for the wrong reason looks exactly like red for the right one, so the attempt was discarded and replaced by a mutation that breaks precisely the rule — which is the class of loss this task exists to catch.

Two review rounds ran before acceptance. The first returned 7 findings on this task — 4 major, 3 minor; the second returned 1 minor. All are closed.

**What is left open.** `verdicts.passed` is not tied to `baseTotal` by the schema: `unaccounted: const 0` forces the author to do the subtraction but does not stop `passed: 0, unaccounted: 0` under `baseTotal: 26`. JSON Schema has no arithmetic and, by the PB-201 decision, no second validator is paired with a schema here, so that one is caught by reading. The approver preamble still says nothing about the handover record — neither that it is needed nor that it is not; the reference states the decision, the preamble does not, and extending it is a separate owner decision. The test covering the "no record carries this sha" branch asserts the phrase in the reviewer prompt rather than the reviewer's behaviour, which is not mechanically checkable — the reviewer is a live session. `lib/guard.js` belongs to another track running in parallel and was edited here by explicit review request; the six lines are narrow, but whoever merges that track next meets them.
