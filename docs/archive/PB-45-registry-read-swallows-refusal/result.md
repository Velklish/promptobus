# PB-45 · Result

**Closed 2026-09-07.** Completed. The three catch-all blocks on the registry read path — `readSession` in both `lib/cursor-persist.js` and `lib/codex-session.js`, and `listSessions` in the latter — now test `e instanceof GateError` and rethrow, so a caller with no declared harness home gets the refusal that names `PROMPTOBUS_<HARNESS>_HOME` and `harnessStateHome` instead of a quiet `null` or `[]`. `GateError` is imported from `'../dist/index.js'`, the same module that throws it and that the suite imports, so `instanceof` cannot split across two copies of the class. The missing-file case is untouched: an ENOENT or a malformed record still yields `null` / `[]`, and `inspect` still answers `gone` with its original wording.

The decision the task required is recorded rather than implied, in `lib/harness-home.js`, `docs/reference/02-host.md` and the headers of both drivers and both registry modules: refusals reach direct driver calls — `inspect`, `stop` and `activate` — while `gone`, `null`, `[]` and "no session record in the registry" are reserved for a home that was resolved and then held no matching record.

Review narrowed that statement to what the code actually does, and this is the important part of the outcome. Every production reader of `inspect` goes through `snapshotSessions`, which catches any driver error and substitutes a reasonless `unknown` so one participant cannot take down `promptobus status`, the `done` walk or the supervisor. So on the path an operator actually uses, the refusal is still not surfaced — the row changed label, not audibility. Letting the `GateError` through that aggregate was rejected: the decision recorded at `src/driver.ts` exists precisely to stop one foreign harness felling those three commands, and trading a silent row for a dead command is worse. The reference now names that exception, and the two deliberate wake-side catches (`registerWake` in both drivers, `sessionPrefix` in the Codex driver), as the current boundary. Surfacing the refusal on the snapshot path is filed as PB-45.1, which works within the same constraint by carrying the reason into the unknown rather than propagating past it.

Two smaller review findings were also closed: the documentation claimed the wake path propagates, which is true of `activate` and false of `registerWake` and `sessionPrefix` — the code is right there and the sentence was wrong; and the test's "empty registry" half pointed at a directory that was never created, so it exercised ENOENT rather than an existing empty directory and never ran the `names.filter` branch at all.

**Verification.** `node --test test/host.test.mjs` exit 0, 11/11. The refusal half is asserted at seven points — `readSession` for both harnesses, `listSessions`, and `inspect`, `stop`, `activate` on both drivers — with a predicate that checks the type and that the message names both the variable and `harnessStateHome`. The reverse half asserts `null`, `null`, `[]` and `gone` with the original `stall.reason` once the home exists but is empty. Mutation probes: removing the Cursor rethrow gives a missing-exception failure at the new assertion; forcing a non-empty `readdirSync` result reddens the empty-registry assertion, proving the fixture reaches the real empty directory rather than the ENOENT catch. The full suite caught one further defect the targeted runs could not — the new fixture's temp-directory prefix fell outside `SUITE_PREFIXES` and failed `tmpdir-sweep.test.mjs`; it was renamed into the existing `promptobus-host-` family rather than widening the sweep list. Gates green on the assembled `main`.
