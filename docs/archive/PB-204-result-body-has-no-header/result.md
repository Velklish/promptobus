# PB-204 · Result

**Closed 2026-09-12.** Done. A result now opens with four lines — what was done, the gate command with its exit code, what is still open, what needs a decision — and everything past them goes as an artifact the header names. The rule lives in the two preambles of this package, where a lifted participant actually reads it, rather than in a consumer's own rules where it would never reach a participant raised elsewhere. `RESULT_BODY_MAX` and the gate-record bounds live in one file and are interpolated into both preambles: a number written twice drifts, and the drift would leave a reviewer holding a different rule from the worker it reviews.

**The bound is derived from live samples, not chosen round.** Five result bodies of this run, already written in the shape being specified: 1 035, 1 389, 1 674, 2 045 and 2 100 characters, median 1 674, against a median of 5 254 over 1 151 free-text results. 2 400 stands above the largest that worked, because this card's own check declares a header over the bound a defect of the **rule** — so the bound has to sit above what already worked, not below. The sixth sample is the author's own hand-off, the first written under the rule rather than before it: 1 916 characters, 484 to spare.

**The card's letter was widened for the reviewer, deliberately.** The card names both preambles for the header, but a reviewer's four facts are not a worker's, and a literal copy would have told it to report a gate it is forbidden to run. Its header carries the same four names with different contents, and its gate line is fixed text — "not run, because a reviewer runs nothing". That turns the card's worry about an escape hatch inside out: the line with a reason is the normal state of one of the two roles on every report it ever sends, so it cannot read as an excuse when a worker uses it.

**One defect of this widening was found by review and is worth recording, because the author named it better than the reviewer did.** The same session wrote the reviewer's gate line as the admission that it cannot run, and two paragraphs later told it to attach an artifact when its report exceeds the bound — which its isolation forbids. In the author's words: the session held both halves and did not put them together. The fix keeps the bound on the header alone; the findings follow it unbounded in the same body, the asymmetry is stated in the preamble and the reference, and a check asserts the reviewer is never told to attach. Giving a read-only session a write door was refused instead: that is [ADR-009](../../adr/adr-009-reviewer-resolves-no-discrepancy.md)'s whole subject, and it would have bought nothing.

**Checks.** Gates on `2daef5d`: exit 0, gates 4, green 4, `npm test` 65 of 65 files and 1 927 verdicts. The schema is untouched — `git diff` over `schemas/v1/message.schema.json` and `src/` is empty and the file is byte-identical, so the frozen type list of [PB-131](../PB-131-message-types-mutable-array/task.md) stands and the header remains a convention inside `body`. The first reviewer to work under the new rule returned its report in exactly this shape, with the fixed gate line, one round after the rule was written.

**Left open.** The card's before-and-after measurement — a live run showing how many bodies the orchestrator had to open beyond the header — is not closed, and no number was invented for it: it needs a comparable run, and the author was inside the one available. The cross-harness half is untouched: whether a Codex or a Cursor participant produces the same header shape is unmeasured.
