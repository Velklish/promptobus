# PB-206.6 · Result

**Closed 2026-09-13.** The direct `worker`↔`approver` route shipped in PB-206 was fail-closed on an identity the participant's MCP server cannot obtain at all: `resolveIdentity()` reads a harness variable from its own process environment, and this repository's own measurement says a Codex MCP child is handed eleven variables with nothing harness-specific among them — "identity from the environment is impossible, not merely unsupported". So `requireDirectSender` received `null` and refused every real call, while the suite stayed green because its test supplied a synthetic `CLAUDE_CODE_SESSION_ID`. The tool advertised traffic it could never carry.

The closure keeps the gate closed and gives the honest sender something to show: a driver contract member `mcpIdentity {recordVar, idField} | null` beside `identityVar`; a shared resolver that reads the session-record pointer **only** when command-path identity is absent, and accepts the record only when home, task and address all match. ADR-014 records it as a boundary refinement of ADR-010.

**Two things the work found that the card did not know.** First, a Codex MCP child can connect **before** `threadId` appears in the record, while the server used to cache identity at startup — so the proof is now re-read on every `tools/call`, and without that refresh the named Codex check goes red. Second, and found by review: the fix itself was welded shut by the same class it was fixing. `resolveIdentity` canonicalizes `scope.home`, while `spawn` and `review` persist the raw `host.promptobusHome()`; an exact string comparison meant that a home written through a symlink produced two spellings of one physical directory and the proof was refused. A card about "the route is welded shut" had its repair welded shut the same way.

**Verification.** Gates on the merged tree, commit after acceptance. On the worker's final tree `7c37768`: `npm test` code 0 with `65/65 test files passed`, `promptobus-mcp` 116/116 against a 109/109 baseline, `session-identity` 15/15, Cursor 127/127, Codex 202/202, adapter 76/76; `audit` and `pins` code 0. Five mutation probes across the two commits, each restored green: disabling record candidates reddens the real-shape MCP check; removing the per-`tools/call` refresh reddens the late Codex `threadId`; stripping the pointer from the Cursor MCP config reddens the driver check; reverting to the raw home comparison reddens the symlink success; removing the home gate reddens the foreign-home refusal. The last pair is the one that matters — it separates normalisation from a weakened gate.

The tests deliberately stand on the measured shape: the MCP child is lifted on exactly the eleven generic variables with no harness identity, plus negative cases for a missing pointer, a foreign task and a foreign address. The synthetic environment that hid the defect is gone rather than supplemented.

**Documentation in the same pass.** `docs/adr/adr-014-mcp-identity-from-session-records.md`, `docs/reference/02-host.md`, `README.md`, `README.ru.md`, `CHANGELOG.md`.

**Left open.** The audit the reviewer asked for came back exact: the changed path holds **three** coordinate comparisons, all in `mcpIdentityCandidates` — `home` normalised physically on both sides, `task` and `address` left exact because their protocol grammars are ASCII and have no alias form. The regression is built on an explicit symlink alias rather than the platform's `/var`→`/private/var`, so a platform-specific spelling remains untested by design. Lifting an approver is still unimplemented — that is PB-206.5, and until it lands this route has no second party to exercise it in production.
