# PB-204.1 · Result

**Closed 2026-09-13.** Completed by ordering rather than by renaming. The result header must quote the artifact's landed filename, but the header was composed before the send that reveals it — and the landed name can differ from the one offered, because a colliding stem lands as `<stem>-2`. The closure chosen: the participant sends the artifact in its own `artifact` message first, reads the landed name from the immediate reply to **its own** `promptobus_send` call, and does not end the turn before putting that name in the header. Gate records follow the same order; review states explicitly that it has no artifact filename. The wording names whose reply is meant, so a participant cannot mistake the orchestrator's reply for the bus's. Protocol reference, both participant preambles and both READMEs were brought to one formulation.

**Verification.** Gates on the merged tree, commit `0b67ddf`, tracked tree clean — numbers below cover both cards of this merge. Target suite `promptobus-spawn` 131/131 → 133/133; the added case is a regression at the tool boundary, not in the preamble text: `createMcpServer` is called twice with the same `handoff-gate.patch`, the replies are asserted to carry `handoff-gate.patch` and `handoff-gate-2.patch`, and the result header is composed from the returned second name. Reviewed twice by an isolated reviewer; its first pass showed the original check only regexed the generated preamble, so removing the single landed-name source in `src/mcp/server.ts` would have left it green while making the prescribed hand-off impossible. The second pass confirmed the replacement closes that: both names now come solely from the send reply text.

**Documentation in the same pass.** `docs/reference/04-protocol.md`, `docs/reference/03-cli.md`, `README.md`, `README.ru.md`, `CHANGELOG.md`, and both participant preambles in `lib/spawn.js` / `lib/review.js`.

**Left open — the decision and its residue.** The order-first closure was accepted over a unique per-attempt stem, on the orchestrator's ruling: the residual defect is a wrong name in a header, the true name is always visible in the artifact message itself, so no data is lost, while a unique stem would change the naming scheme and `placeFile`. The residue is that **nothing machine-visible enforces the order** — a participant that sends the result first, or sends the artifact and ends the turn without a result, produces a silently wrong hand-off that only the header's reader notices. That is recorded as `PB-204.2`, whose scope was corrected on the reviewer's second pass: the invariant may judge only results that *claim* an artifact (an artifactless result is lawful), and it must cover both order violations — the second one is invisible to any rule built on answer expectation, because any send clears `answerOwedSince`.
