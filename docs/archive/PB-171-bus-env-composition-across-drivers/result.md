# PB-171 · Result

**Исход.** Имя, стоящее на команде подъёма, доходит до процесса MCP-сервера участника по-разному
у трёх харнессов, и это измерено живьём, по участнику на харнесс: Claude **сливает** окружение
(99 имён у MCP-ребёнка, среди них `GITLAB_TOKEN`, определённый на машине только в
`workspace/.env` и ни в одном из трёх rc-файлов zsh — то есть прийти он мог только цепочкой
подъёма), Codex и Cursor **заменяют** его (11 и 9 имён). У Cursor замер доказывает механизм, а не
размер: сентинель `PB171_MARK`, поставленный на команду подъёма, есть у процесса харнесса
(103 имени) и отсутствует у его MCP-ребёнка — окружение не теряется по дороге к харнессу, его
подменяют на слое MCP. Метод один для всех трёх: `ps eww -p <pid>` по ребёнку, отобранному по
`PROMPTOBUS_ROLE`, а не по имени программы — все участники запускают один и тот же бинарь.

**Что сделано.** Под заменяющим харнессом обе половины правила автоподъёма едут только если
запись драйвера их называет, поэтому запись Cursor теперь несёт `PROMPTOBUS_WARDEN` и
`PROMPTOBUS_WARDEN_TRACE` ровно так же, как запись Codex с `PB-166.2`. Список, из которого они
берутся, переехал в `lib/session-env.js`: константу, которую читают два драйвера, не держит ни
один. Туда же добавлено `CLAUDE_CODE_HOST_SESSION_ID` — живой участник Claude нёс значение
оркестратора, а список этого имени не знал. Драйвер Claude в этой карточке не трогали.

**Граница, и она была предсказана карточкой до замера.** Стенд не поднимает MCP-сервер вовсе,
поэтому этой разницы не увидит ни один стенд — нужен живой подъём на каждый харнесс. Записано в
`contributing.md` рядом с тем, что стенды доказывают. Следствие сформулировано не шире замера:
сервер, который драйвер объявляет **без** явного `env`, получает от workspace ничего на Codex и
Cursor и всё на Claude — при этом ни один из тринадцати таких серверов в момент замера локально
не поднимался (у всех трёх харнессов ровно один локальный MCP-ребёнок), несколько из них
удалённые или ленивые, так что «тринадцать серверов сломаны» не утверждается.

**Чем проверено.** `test/promptobus-driver-cursor.test.mjs`: сентинельные значения (под раннером
оба имени и так стоят, сверка с ними прошла бы и на захардкодившем драйвере) плюс отрицательный
контроль через `in`, а не через сравнение значения — безусловный проброс кладёт `undefined`.
120/120. Гейты на `00e0639`: `npm test` exit 0 (57/57 файлов), `backslop lint` exit 0,
`npm run audit` exit 0, load 8.78 → 7.46. На сведённом дереве `npm test` 62/62 файла.

**Что осталось за карточкой.** Живого замера **после** правки не делалось: проверка опирается на
композицию записи, а не на подъём. Замер до правки — оркестратора, и он в тексте выше.
