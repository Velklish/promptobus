**One behaviour was lost in the extraction and restored under review: `readKeychainSecret`'s `timeoutMs <= 0` guard.** Without it a caller asking with a zero or negative budget reached `security find-generic-password` anyway. The guard is back as the function's first line.

**The kill had no check at all, and that is the substantive addition.** `spawnAndCapture`'s timeout handler calls `child.kill('SIGKILL')`, and nothing observed whether the child actually died — a verdict returning on time looks identical whether the child was killed or merely outlived. The check in `test/model-routing-adapter-cursor.test.mjs` reads **growth**: the stub appends to a marker file once a second, up to ten times, using only `sh`, `sleep` and shell builtins; after the verdict the check snapshots the marker's size, waits, and asserts it did not grow. A killed child stops appending wherever the kill lands; an unkilled one keeps its own cadence. There is no fixed race to win in either direction, which is what the first two attempts got wrong: the original design asked the stub to write once after a 1 s sleep and asserted on a 1300 ms deadline — a 5x margin on a file that runs in the parallel pool, where precedent (`PB-159.1`) wants 20x — and an earlier attempt used `touch`, which is not on this suite's sealed `PATH`, so the child died at exit 127 for a reason unrelated to the kill and the probe came back a false negative.

**Verification.** `npm run probe -- lib/model-routing/adapter-common.js --mutate "s/child\.kill\('SIGKILL'\);//" --run "node --test test/model-routing-adapter-cursor.test.mjs"` — the kill removed — mutated exit 1, restored exit 0, reddening `a timed-out child is actually killed, not just outlived by the verdict` on `the marker kept growing past the deadline — the child was not actually killed`.
