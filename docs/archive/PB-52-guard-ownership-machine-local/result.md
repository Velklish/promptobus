A guard hook group in project settings is recognised as Promptobus's own first by the exact ids of the machine-local install manifest and, when the manifest is absent (a checkout copied from another machine, a deleted `.promptobus/`), by a portable signature of the command the package itself renders — an anchored regex `GUARD_SIGNATURE` in `lib/install.js`: two quoted launch elements, optional bare host-prefix words, the bare `guard` word, then nothing or exactly `--role <value> --task <value> --home <value>` with shell-quoted values — never by this machine's absolute node and binary paths and never by a bare substring. A foreign-path guard is therefore replaced on install and removed on uninstall instead of duplicated and orphaned; wrappers such as `"/bin/sh" "-c" node hook.js guard`, a quoted `guard`, unknown or incomplete tails and unterminated quotes stay foreign. The accepted false-positive class is named in the guides: any Stop/SessionStart (Cursor `stop`) command of that exact shape is treated as ours whatever binary it launches.
