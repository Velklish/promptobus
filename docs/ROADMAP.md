# Roadmap

Where promptobus is going: goals and their rationale. This is a living document: a goal is direction, not a commitment; user signals determine priority and scope, not this list. Concrete tasks with statuses are in `npx --no-install backslop status`.

## Goals

1. **Host-neutral bus.** A third party runs the CLI and embeds the library without another product's layout. The host contract in [adr-002-standalone-host-contract.md](adr/adr-002-standalone-host-contract.md) is the boundary. Evidence: `src/host.ts`, `src/standalone.ts`.
2. **Four harnesses in one CLI.** Claude Code (`claude`), Cursor (`cursor`), Codex (`codex`), and OpenCode (`opencode`) share the same task store and MCP tools. The registry is `REGISTRY` in `lib/drivers.ts`; role and hook support still differ by driver ([driver reference](reference/05-drivers.md)).
3. **Project-level hook installer.** A person opts in with `promptobus install --harnesses …`. npm `postinstall` does not edit harness files. Evidence: `promptobus help` lists `install` and `uninstall`; their flags are in [guides/install.md](guides/install.md).
4. **Routed model choice instead of a blind flag.** A person or an agent names an intent — a strategy — and the CLI picks the `role + harness + model + effort` tuple from a rated catalog intersected with account availability, explains the pick, and never silently replaces an explicit `--harness`, `--model` or `--effort`. The current `models/catalog.json` has 82 rated tuples across the four registered harnesses; this is a source inventory, not a live availability measurement. The implementation of [ADR-005](adr/adr-005-ten-point-scale-absolute-bands-calibrate.md) includes the contracts in `schemas/model-routing/`, the routing libraries and availability adapters in `lib/model-routing/`, and the host's `routingPaths()` in `src/host.ts`. `promptobus status` prints a routed lift's `metadata.routing` per participant. Measured on 2026-09-05 with all three accounts in that run logged in: one `promptobus models --refresh` probed the three harnesses in 2.6 s and chose `codex-luna-medium` at 73.10, naming every one of the 19 candidates with its score components or its exclusion reason.
5. **English throughout.** Runtime output, scripts, tests, docs and what ships are English, and the Russian literals inherited from the transferred code are gone. Evidence: `npm run audit` runs in CI over every tracked text file and the packed tarball; Cyrillic passes only in the snapshots it names, such as `src/protocol.ts`'s Cyrillic-to-Latin transliteration table, and in test inputs a file marks with their reason.
6. **Spend subscriptions evenly, not one first.** `balance` compares eligible subscriptions against the pace of their own windows instead of draining the best-rated account first. The 2026-09-06 spike covered three accounts: Claude Code, Cursor, and Codex read their own tier and windows from local credentials without a paid turn, making `available` (auth, model and limit confirmed) reachable for each. OpenCode's later adapter reports local estimates that do not enter the pace comparison ([routing guide](guides/model-routing.md#opencode-adapter-what-the-probe-reads)). The decision is [ADR-005](adr/adr-005-ten-point-scale-absolute-bands-calibrate.md). The schema version 2 snapshot records tier and each window's `kind`, `lengthSec` and `scope`. The quality floors remain `qualityFloor: { worker: 5, reviewer: 9, approver: 7 }`; overlay `deny` lists are unioned across layers, including the `byRole` and `flags` selectors. `HostRoutingOverlay.writable` marks the one layer `models strategy --set` writes, and `promptobus done` records local telemetry. Measured against the suite's own snapshot fixture with the shipped catalog on 2026-09-06: `models --strategy balance --role worker` chose `codex-sol-medium` at 78.10 over `claude-opus-medium` at 74.25 on pace alone — codex `+15.25` effective against claude `+9.23` and cursor `−15.33` — and, with codex staged as exhausted, the same command moved the pick to `claude-opus-medium` and the pace table to two rows.

## Prioritisation principle

The queue is ordered by cost label: `critical` first, then `major`, then `minor`. Within a label, a live break or a missing command that a published guide already names comes first. Owner requests next. The backlog order field is the queue, not this list.
