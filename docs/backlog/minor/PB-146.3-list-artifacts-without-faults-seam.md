# PB-146.3 · listArtifacts calls the bulk artifact reader without the engine's faults hook, so the artifact-read seam cannot be reached through the bulk path
- **Scope:** `src/v1/engine.ts` (`listArtifacts`), `src/v1/artifacts.ts` (`listArtifacts`), [04-protocol](../../reference/04-protocol.md) § Fault injection
- **Created:** 2026-09-10
- **Dependencies:** PB-146.1
- **Cost:** minor

## Context

Finding of the PB-146.1 review (isolated reviewer, run `pb-run-0910-t20260910-085454`), from the source. PB-146.1 threads the engine's `faults` hook into `readArtifact` and `readArtifactContent` (`src/v1/engine.ts:366-367`), but `listArtifacts: (task) => listArtifacts(home, task)` on the next line still calls the bulk reader without it, so the `artifact-read` seam cannot be reached through the bulk path — unlike the task side, where `listTasks` passes the hook (`src/v1/store.ts:225`) and PB-146's bulk test runs through it. Today this costs no coverage: `listArtifacts` accumulates `broken: string[]` — messages, not codes — so there is no taxonomy to prove on that path. It becomes a gap the day the bulk artifact listing gains a `code` the way `BrokenTask` did.

## Work to do

- Either pass `faults` into `listArtifacts` and give the bulk listing the same `code` a `BrokenTask` carries (a scoped contract change: an `Added` entry, the exported type updated), or state in 04-protocol § Fault injection that the artifact seam covers the direct reads only.
