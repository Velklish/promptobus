# PB-259.1 · Measure historical owner refresh-token rotation with the owner present

- **Scope:** `lib/driver-codex.js` (`makeParticipantHome`), [05-drivers](../../reference/05-drivers.md), [03-cli](../../reference/03-cli.md) § The Codex holder
- **Created:** 2026-10-26
- **Parent:** PB-259
- **Cost:** major (hypothesis)

## Evidence

Finding discovered while working on PB-259.

Evidence: on 2026-09-25, Codex CLI 0.156.1 and Promptobus 0.17.0 completed three copied-home turns, then a second three-participant lift failed before the model with `Your access token could not be refreshed because you have since logged out or signed in to another account`. The owner's login status still reported ChatGPT. This did not establish which process refreshed first or prove refresh-token rotation.

## Hypothesis and return condition

A shared refresh token may rotate in one copied home and become unusable in another. This remains unmeasured. The owner approved access-only fail-closed/new-lift acceptance for PB-259 on 2026-10-26; that mitigation does not accept or refute this hypothesis.

Before taking this experiment, a person must be present and ready to sign in again, and explicitly approve the bounded real-owner refresh operation. Use two disposable homes from the same authorized input, force a refresh in one, then test the other and the owner's remaining usability. Cite the refresh path at the installed Codex source tag; retain exact failures and never expose token contents.

Acceptance requires the actual rotation measurement or an actual measurement that refutes it. Synthetic cached-account metadata and the historical 0.159.2 reload fixture do not satisfy that criterion. No real-owner refresh, login/logout or credential mutation is authorized by this open finding.
