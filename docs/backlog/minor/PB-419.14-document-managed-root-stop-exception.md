## Managed tree shutdown sequence observed on 2026-11-13

Evidence: private workspace consumer smoke on Promptobus 0.32.9 / Host 0.107.0 / Codex 0.167.2. Both child-owner `done --keep-sessions` operations before normal Stop exited 1 with `participant orchestrator: native work is active or unresolved; confirm Stop before done or recovery.` This was a test-instruction mistake; the gate behaved as documented.

The corrected finite sequence was: root calls `stop teamlead:alpha` and `stop teamlead:beta` on its own root task, each exit 0, records results, then requests `stop orchestrator` on itself. The independent parent checked the pending self-Stop after that command completed. In the final control run, all three retained hashes matched, all three receipts contained `stop/confirmed`, each app-server closed with code 0, and terminal command accounting was 15/15, 5/5 and 3/3. Original local artifacts: `/private/tmp/promptobus-smoke-20261113/root-result-attempt3.json` and `verified-result.json`.

Extend this existing task to give the managed-root/teamlead sequence and its boundaries in the orchestration instructions: native Stop, task metadata closure and service shutdown are separate. Do not prescribe `done --keep-sessions` as a bypass of Stop, and do not imply a foreign controller gains owner rights after self-Stop. Task/service closure still failed in the measured run and belongs to PB-416.26; documentation must state a supported route only when that route is verified. Add a documentation check that rejects the old blanket root refusal and premature done-before-Stop recipe. Permanent documentation edits and post-change checks remain **notRun**.
