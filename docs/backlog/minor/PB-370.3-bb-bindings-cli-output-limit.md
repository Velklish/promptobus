# PB-370.3 · BB bindings inventory can exceed the plugin CLI output limit

- **Scope:** BB host integration: public bindings inventory and command output limits, docs/reference/02-host.md.
- **Created:** 2026-10-12
- **Parent:** PB-370
- **Cost:** minor

## Evidence

Finding discovered while working on PB-370.

Evidence: Observed public bb promptobus bindings exit 1: Plugin CLI output is 1058894 bytes (1058894 stdout + 0 stderr), exceeding the 1048576-byte limit. Narrow the query, request a smaller page, or use a file/streaming command. Original failed receipt is retained privately. The current public bindings CLI exposed no verified filter, pagination or streaming route usable for this readback; targeted public participant and thread reads were used separately without private binding-store access. Native API/root cause and a supported narrow alternative remain unmeasured. Planning only: no output-limit, identity or global settings changes.

## Acceptance criteria

- Provide and document a supported bounded bindings readback for inventories exceeding the command output limit.
- Preserve authenticated task/participant identity and unrelated bindings; do not use private binding storage or global output-limit overrides.
- Retain the original failure and prove complete bounded readback on an isolated large-inventory fixture.

This minor is planning-only and nonblocking for the six-card run. Its implementation is outside the run.
