# PB-246.3 · The gpt-5.6-* and gpt-5.5 ladders carry no low rung although the 0.156.1 listing offers one

- **Scope:** `models/catalog.json`, [guides/model-routing](../../guides/model-routing.md)
- **Created:** 2026-09-23
- **Parent:** PB-246
- **Cost:** minor

## Evidence

Finding discovered while working on PB-246.

Evidence: codex debug models on codex-cli 0.156.1, 2026-09-23, owner and participant homes byte-identical (sha256 dba45a6b…): gpt-5.6-sol and gpt-5.6-terra offer low…ultra, gpt-5.6-luna low…max, gpt-5.5 low…xhigh; models/catalog.json carries no low rung for any of them, and codex-luna-* has no xhigh rung

The GPT-5.6 and GPT-5.5 ladders came from the PB-29 spike document, not from a listing. [03-cli](../../reference/03-cli.md) § Codex says so. The GPT-6 rows of PB-246 take the full ladders the 0.156.1 listing offers. So a person can pass `--effort low` to a GPT-6 model and cannot pass it to a GPT-5.6 one, although the binary takes both. Adding the missing rungs is ladder arithmetic from each existing base row. It moves no base rating, but it adds rows, the pinned counts and the Codex priority block.
