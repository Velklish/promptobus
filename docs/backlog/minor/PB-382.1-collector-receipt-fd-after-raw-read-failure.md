## Evidence

Finding discovered while working on PB-382.

Evidence: lib/bb-direct-command.js:76-85 computes raw stream hashes before the receipt descriptor close finally; raw read failure preserves outcome but leaves that descriptor open in a long-lived exported collector caller; independent source review, no runtime descriptor-count probe

## Context

The exported recordBbDirectCommand opens the original receipt descriptor before child spawn. After child close it computes raw stdout/stderr hashes before entering the receipt write/close try/finally. If readFileSync throws there, the outer catch preserves the executed outcome but does not close that descriptor. The CLI process exit releases it; repeated calls from a longer-lived consumer can retain one descriptor per such failure.

Evidence: lib/bb-direct-command.js:76-85 on reviewed source 6296f18e150fcc8dea8dc88d6531d83ea7631bfd. Source-only independent review established the control-flow gap; a descriptor-count runtime regression has not been run. Existing fault regression proves original outcome preservation, not descriptor closure.

The owner requires minor findings to remain in backlog. PB-382 keeps its outcome-preservation fix and does not change this path further.
