# PB-326.1 · A crashed node generator is reported by its last stderr line, not by its cause

- **Scope:** [CLI: repository generator](../../reference/03-cli.md)
- **Created:** 2026-10-04
- **Parent:** PB-326
- **Cost:** minor

## Evidence

Finding discovered while working on PB-326.

Evidence: PB-326 worker, 2026-10-04 (evidence pb326-evidence.md §11, not re-run by the orchestrator): a repository generator that is a node script crashing with 'Cannot find module' is reported by the run classifier as 'exited with code 1:  Node.js v25.2.1'; the cause is only in the generator log.

## Work to do

Reproduce the reported symptom with a synthetic Node repository generator failing with `Cannot find module`. Keep the complete generator stdout/stderr log and choose a cause-bearing generator failure summary instead of the trailing blank/version lines. Change other command classification only if the demonstrated generator case requires it.

## Verification

- A focused generator-failure regression in `test/promptobus-spawn.test.mjs` fails on the old summary behavior and passes with `Cannot find module` visible in the summary and full diagnostics retained in the log.
- Preserve existing non-generator command summaries and exact exit reporting; record command, source identity, counts and exits for any checks run.
