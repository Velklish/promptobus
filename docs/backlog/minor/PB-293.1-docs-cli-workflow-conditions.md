# PB-293.1 · Correct unconditional CLI claims in review and orchestration recipes

- **Created:** 2026-09-27
- **Parent:** PB-293
- **Cost:** minor

## Context

Three short recipes overstate CLI defaults or availability, potentially selecting the wrong harness/task or sending readers through an unnecessary manual protocol.

## Evidence

- At b3d4a387, docs/reference/03-cli.md:491 says promptobus send is not a command, although lib/cli.js:375-386 dispatches it and reference :1067-1093 documents it.

- skills/orchestrate/SKILL.md:82 says omission of --harness always selects Claude; lib/spawn.js:933-954 prefers routed.harness, including strategy defaults from lib/models.js:319-337. Claude is only the no-routing fallback (lib/drivers.js:50-52). README.md:69 and README.ru.md:64 repeat the same unconditional default and must be corrected in the same pass.

- skills/solo-review/SKILL.md:58 says a leftover active task makes every future command require --task. lib/store.js:669-687 resolves an explicit/declared task, then binding, then the sole active task; ambiguity requires multiple unbound tasks. A single leftover task can instead be silently selected.

## Work to do

- State the routed/default-strategy choice before the legacy Claude fallback. Apply the clarification to both READMEs as well as the orchestrate skill.
- Explain bound, sole-active and ambiguous task resolution as the reason to finish a review task.

## Out of scope
