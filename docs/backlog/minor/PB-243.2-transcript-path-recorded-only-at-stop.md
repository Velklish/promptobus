# PB-243.2 · The transcript path is recorded only at a Stop, so a question in a session's first turn still gets the old re-knocks

- **Scope:** [hooks-and-trust](../../guides/hooks-and-trust.md)
- **Created:** 2026-09-25
- **Parent:** PB-243.1
- **Cost:** minor

## Evidence

Finding discovered while working on PB-243.1.

Evidence: lib/guard.js:459 reads event.transcript_path only on the Stop path (the turn-end mark); SessionStart records nothing, so a question asked in a session's first turn, before any Stop, gets the old re-knocks — named as open by the PB-243.1 worker and its approver (result 2026-09-25)

## Work to do

- Record `transcript_path` on `SessionStart` as well, the same failure-tolerant way the Stop path does, so the warden can see an open question from the first turn on; the first turn after a session change is covered by the same record.
