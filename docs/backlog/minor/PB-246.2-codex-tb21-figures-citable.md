# PB-246.2 · codex-terra-max and codex-gpt55-medium can cite their Terminal-Bench 2.1 Codex CLI figures instead of stating them as hypotheses

- **Scope:** `models/catalog.json`, [guides/model-routing](../../guides/model-routing.md)
- **Created:** 2026-09-23
- **Parent:** PB-246
- **Cost:** minor

## Evidence

Finding discovered while working on PB-246.

Evidence: https://snorkel.ai/leaderboard/terminal-bench-2-1/ opened 2026-09-23: GPT-5.6 Terra, Codex CLI, 78.4 % ±1.3; GPT-5.5, Codex CLI, 83.1 % ±1.1; codex-terra-max and codex-gpt55-medium keep both as hypotheses at the same bands (7 and 8)

The page is the archived Terminal-Bench 2.1 leaderboard, with 18 rows, and it names no effort. ADR-005 has a Codex CLI pair for 2.1, 60 → 1 and 90 → 10. On it, 78.4 gives 1 + round-half-up(5.52) = 7, and 83.1 gives 1 + round-half-up(6.93) = 8. Those are the bands both rows already hold. So citing the figures changes no rating and no routing. It only turns two hypotheses into citations, as PB-246 did for `codex-luna-max` from the same page. After that, eleven of the twenty-two base models would carry a `quality` hypothesis, and the guide's count would follow.

A related note on the same rows: `codex-gpt55-medium` places its `speed` hypothesis "beside the measured 90 tokens/s Sol row". In PB-246, `codex-sol-max` now cites 72.6 tokens/s at max, which is band 2. That sentence names a figure the catalog no longer carries. The band, 3, is still a hypothesis. Re-placing it is a rating decision.
