Finding discovered while working on PB-239.2.

Evidence: lib/cursor-persist.js readTmuxSessions on c6114ea8: 'if (r.status !== 0) return { sessions: [], missing: null }' treats every non-zero exit as no server, which is right for a server that is not there: measured 2026-09-24 on tmux 3.6b, `TMUX_TMPDIR=/tmp tmux -L pb2392-none list-sessions` → 'error connecting to /private/tmp/tmux-501/pb2392-none (No such file or directory)', exit 1; after a kill-server it printed 'no server running on /private/tmp/tmux-501/pb2392-probe' (exit not recorded). Assumption, not run: a client of another protocol version than the running cursor-agent server (a tmux upgraded under a live server) exits non-zero with a protocol-mismatch line; then inspect answers stale for live sessions, liveParticipant reads dead, and stop and sweep act on them as PB-239.2 described.
