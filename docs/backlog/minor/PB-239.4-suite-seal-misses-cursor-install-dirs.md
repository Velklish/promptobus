# PB-239.4 · A Cursor binary search handed an environment without the suite's install-directory seal still reaches /usr/local/bin, where `cursor` is the Cursor app CLI

- **Scope:** `test/hygiene.mjs`, `test/promptobus-driver-cursor.test.mjs` (the PB-93 checks), [05-drivers § Cursor: tmux by absolute path](../../reference/05-drivers.md#cursor-tmux-by-absolute-path)
- **Created:** 2026-09-24
- **Parent:** PB-239.2
- **Cost:** minor

## Evidence

Finding discovered while working on PB-239.2.

Evidence: the tmux half of the gap is closed in PB-239.2. `applyHygiene` (`test/hygiene.mjs`) now sets `PROMPTOBUS_CURSOR_INSTALL_DIRS=~/.local/bin` in the environment it seals, and `test/runner.test.mjs` checks from inside a sealed suite file that `tmuxBin()` finds nothing and that every directory `searchPath()` walks lies inside the run. The Cursor-binary half remains. `searchPath` (`lib/cursor-persist.js`) reads the list from the environment it is HANDED, and the PB-93 checks in `test/promptobus-driver-cursor.test.mjs` call `findCursorBin({ env: { PATH: … } })` and `liveBin('recorded-cursor', { env: { PATH: … } })` with an environment that does not carry the seal. For those calls the default list applies: `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`. On this machine, `ls -la /usr/local/bin/cursor` (2026-09-24) shows a symlink to `/Applications/Cursor.app/Contents/Resources/app/bin/code`, and `CURSOR_BINS` includes `cursor`. Those checks find their stub on PATH first, so nothing reached the app CLI; the gap is latent, not observed. The runner's escape gate (`test/run.mjs`) would name it only after the binary had run.
