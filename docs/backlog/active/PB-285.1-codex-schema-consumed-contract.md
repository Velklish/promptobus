# PB-285.1 · Replace the full Codex schema snapshots with a generated consumed contract for the minimum and current versions

- **Parent:** PB-285
- **Cost:** major
- **Taken:** 2026-10-28

## Context

Finding discovered while working on PB-285.

`test/fixtures/codex-app-server/` keeps a full `generate-json-schema` capture per Codex version. Evidence, 2026-10-28: `du -sh test/fixtures/codex-app-server/*` → 0.158.0 to 0.164.0 at 4.3–4.5 MB each, 31 MB in total; PB-285 alone added 334 files and 147 514 lines (`git show --stat 3a31d483`). The runtime driver reads none of it (`grep fixtures lib/*.js` → nothing; `package.json` `files` excludes `test/`). Tests and `npm run codex-schema` read it.

What is actually consumed is a fixed set: 16 requests and 7 approval kinds named in `scripts/codex-schema-contract.mjs`, plus `ClientRequest`, `ServerRequest`, `ServerNotification`, `v1/InitializeParams` and a few v2 Params/Response/Notification types — about 50–55 of ~320 files per version. The other files, including the two aggregate schema files of 600–700 KB, are kept for inventory, hash and "historical capture unchanged" checks (`test/codex-fixtures.test.mjs`). Eight versions are kept although the driver supports a range: `MIN_CODEX_VERSION` 0.158.0 and `PROVEN_CODEX_VERSION` 0.164.0 (`lib/driver-codex.js`). The 0.162.0 directory is referenced by no code, test or document (`git grep 0.162.0` outside the fixtures, excluding the alpha version string → nothing).

The schemas cannot be dropped altogether: CI has no Codex binary, and the Codex stub tests need a committed oracle of the protocol shapes, or the stub would validate against itself.

Owner decision, 2026-10-28: replace the snapshots with a small generated contract in this run; nothing goes to GitHub before this card is accepted.

## Work to do

- A script that, from a live `codex app-server generate-json-schema` output, writes a consumed contract: exactly the schemas the driver and tests consume, each with the closure of its local `definitions`/`$ref`, plus a provenance file naming the binary version and the generator command.
- Keep the contract for `MIN_CODEX_VERSION` and `PROVEN_CODEX_VERSION` only; remove the full captures, including 0.162.0. Regenerate the minimum version's contract from its committed capture before deleting it, so no live old binary is needed.
- Move the dated live-evidence JSON and READMEs that documentation links to (0.146.0, 0.156.1, 0.158.0, 0.159.2 and others) under `docs/evidence/` or keep them in a small evidence directory; update every inbound link.
- Rewrite the tests that pin file counts, inventories, diffs between versions and historical hashes to assert the contract instead; keep the semantic checks (holder shapes, approval replies, interrupt, steer, method lists, `notRun` without a binary).
- `npm run codex-schema` validates the live binary against the contract and, when a binary is present, fails if the regenerated contract differs from the committed one.
- Update contributing, 05-drivers and CHANGELOG with the new procedure for raising `PROVEN_CODEX_VERSION`.

## Out of scope

- Rewriting git history: the earlier captures stay in history.
- Changing the driver's protocol behaviour.

## Verification

- `du -sh test/fixtures/codex-app-server` is under 2 MB; only the two contract versions remain.
- Every test that read a capture passes against the contract; a mutation that drops a consumed schema from the contract reddens a named verdict.
- `npm run codex-schema` on the installed 0.164.0 exits 0, and reports `notRun` and exits 0 when the binary is absent.
- No documentation link points at a removed file (`backslop lint`, docs-links).
