## Context

A probe can correctly redden a link-consistency verdict while the accompanying edit also changes recipe semantics. The recorded result is real, but its guarantee is narrower than the edit. The closed mutationProbe definition has no representation for that semantic coverage boundary. This is a request to choose that representation, not evidence of falsely executed tests.

Evidence: the installed 0.29.0 reader (32fc9e2e2b8e2514faf9e374e6b640ca214a9c86) and local source b4769a64bbf385c9f9b99294168735239ee50ccf accept a valid mutationProbe control and reject the same object with scope='Covers link consistency, not recipe semantics'. A deterministic node source control asserts an empty control error array and one scope error; exit 0. No live model was launched.

Duplicate review: PB-234 covers expected versus reddened verdicts; PB-234.2 covers installed/schema skew; PB-234.3 covers tree lag; PB-234.4 covers numeric/exit consistency; PB-328 covers the single-probe slot. None defines the semantic coverage claim. Current backlog/journal coverage and boundary searches found no matching request.

## Work to do

- Define a mandatory, visible semantic coverage boundary beside the probe, including what it does not establish. Preserve that requirement unless the owner explicitly decides and records a weaker contract. Choose its representation and meaning.
- Preserve expected-verdict validation and distinguish a genuine narrow probe from notRun or an ineffective mutation.
- Define author/reader/send-time compatibility and release ordering. A source-only new field must not be sent to an older installed reader.
- Document bounded positive and negative examples.

## Out of scope

- A gate's clean-state interval guarantee or filesystem collector.
- Replacing expected/reddened, tree-lag or numeric/exit checks; adding a probe slot; changing historical results.
- Implementing this request or launching live model sessions during its filing.

## Verification
