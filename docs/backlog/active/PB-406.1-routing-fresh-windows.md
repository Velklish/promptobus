# PB-406.1 · Routing windows stay current, and an expired probe keeps its last windows with their age

- **Scope:** [03. CLI § Model routing](../../reference/03-cli.md#model-routing)
- **Created:** 2026-10-28
- **Dependencies:** none
- **Parent:** PB-406
- **Cost:** major
- **Taken:** 2026-10-28

## Context

Finding discovered while working on PB-406. Evidence: windows are cached for 60 s (`lib/model-routing/cache.js`); `promptobus models` without `--refresh` runs with `dryRun: !refresh` and never probes (`lib/models.js`); an expired entry that no probe replaces becomes `unknown/stale_cache` with no windows (`lib/model-routing/preflight.js`), so the harness loses its pace and pool data. Snapshot age is the oldest `checkedAt` across harnesses, so a one-hour inventory entry or a held exhaustion reads as staleness of windows.

## Work to do

- `models` probes by default (the flag that skips probing is explicit), and every routing decision prints the age of the windows it used, per harness.
- When a probe fails or is skipped, keep the last known windows marked with their `checkedAt` instead of dropping them; the resolver treats an old window by its age, not as `unknown`.
- Age is reported per harness and per kind (windows vs inventory), not as one oldest number.
- An exhaustion held until `resetAt` is re-probed on a lift, so a plan upgrade is seen without `--refresh`.

## Out of scope

- Changing TTL defaults beyond what the above needs.

## Verification

- A test with an expired cache entry and a failing probe: the resolver still sees that harness's windows with their age; today they disappear.
- `promptobus models` with no flags probes (a stub adapter records the call); the old behaviour fails the test.
