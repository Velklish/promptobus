## Context

PB-354's exhaustive validation of holder requests against the installed Codex protocol found an existing invalid outgoing shutdown request. This is not a new 0.160.0 schema change: the required fields are identical in the old and new captures. The shutdown path catches interruption errors and proceeds to kill the child, so this finding establishes a protocol-contract violation; it does not claim a measured failure of final child termination or a live model-turn reproduction.

The holder tracks `currentTurnId` and `activeTurns`, including response and notification paths. Choosing the target during overlapping response/notification/completion races needs a concrete acceptance recipe before runtime adaptation. PB-354 currently permits a proven-version/fixture update and validation, with runtime changes outside its approved scope. Its acceptance must not silently omit the invalid request or weaken the generated schema.

## Approved work

Root authorizes the existing PB-354 worker to implement this dependent fix as a separately numbered, identifiable commit. Preserve bounded best-effort interruption followed by unconditional child cleanup. Target only nonempty real IDs from accepted `activeTurns`; never select a stale `currentTurnId` just because `busy` is true, and never fabricate an ID. Multiple known active IDs must share the existing bounded shutdown allowance rather than extending it per ID.

Use deterministic actual-holder mock interleavings to cover completed A/reserved B, notification before response, completion before response, no known ID while a request is in flight, interruption errors/timeouts and multiple known active IDs. Never interrupt completed A, lose cleanup or exceed the existing bound. If existing state cannot establish these invariants, send the concrete bounded-interruption/late-response recipe for a decision before committing runtime changes. Approval, ownership and refusal safeguards remain intact. Parent and child outcomes are recorded separately through the full worker, isolated reviewer and approver pipeline.
