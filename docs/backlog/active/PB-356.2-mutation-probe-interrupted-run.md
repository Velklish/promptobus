# PB-356.2 · Mutation probe counts a signalled probe as successful proof

- **Scope:** [Mutation probes](../../guides/contributing.md)
- **Created:** 2026-10-10
- **Dependencies:** none
- **Cost:** major
- **Previous order:** 70
- **Taken:** 2026-10-10

## Context

Discovered during the publication check of PB-356. The full suite refused two signal verdicts in `test/mutation-probe.test.mjs`: the fixtures signal the probe itself with SIGINT or SIGTERM during the mutated run, but the probe reports successful red/green proof with exit 0 instead of refusing the interrupted run with exit 2.

Evidence on macOS with Node v23.11.0, 2026-10-10: `node test/mutation-probe.test.mjs` exits 1 with 67/69 passed twice on the publication branch and once in a fresh worktree at upstream main `0e734c97bc0ef009850cdc3bf368b1c25324ef49`, after `npm ci`. The same two named signal verdicts fail in each run. The relevant script, test and isolation helpers are unchanged from that base. The initial full `npm test` also observes both failures. This proves the failure predates PB-356; the cause of the missed signal is not established.

## Work to do

- Reproduce the signal delivery and event-loop ordering in the probe on supported Node versions.
- Make a probe interrupted during its mutated run refuse proof, restore all bytes and exit 2.
- Keep ordinary harmful, equivalent and quoted-output outcomes distinct; update the contributing guide if the signal contract changes.

## Out of scope

## Verification

- Both named SIGINT/SIGTERM verdicts pass, with actual interrupted-run counterfacts and byte restoration.
- Harmful mutations fail the named checks; an equivalent edit stays green.
- Run the repository gates on the final clean commit and report their actual exit codes.
