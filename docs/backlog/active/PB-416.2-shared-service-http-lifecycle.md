# PB-416.2 · Own one workspace service process and isolated HTTP MCP clients

- **Scope:** [MCP](../../reference/01-overview.md), [Host](../../reference/02-host.md), [CLI](../../reference/03-cli.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-415.5
- **Cost:** major
- **Taken:** 2026-10-30

## Context

First shared-service implementation stage after the accepted TypeScript runtime. One physical service is keyed by the canonical Host workspace/store pair. It serves isolated bus and reviewer_files connections over loopback Streamable HTTP and retains explicit consumer-owned Host context.

Evidence: lib/server.ts serve accepts env/cwd but joinBus still reads process defaults through driver callbacks; lib/harness-home.ts has first-wins process bindings. src/mcp/server.ts keeps joined state per connection. lib/reviewer-files.ts grants canonical directory/exact-file reads. These facts require immutable client contexts, common checked harness homes/binaries, and credentials outside every reviewer read grant rather than an HTTP wrapper around process.env.

## Work to do

- Implement canonical discovery, atomic concurrent startup, runtime identity checks, private control/client credentials, stable endpoint reuse, crash recovery and idle lifetime. Discovery contains no bearer. Refuse incompatible owners or an occupied retained endpoint rather than start a second service.
- Add CLI service ensure/run/status/stop through the existing CLI entry point. Add a consumer-owned Host factory to CLI options without changing PromptobusHost or existing exports/runtime paths; keep help/version minimal Hosts valid. Per-client contexts retain cwd/env/Host and immutable authority coordinates; no global environment or harness-binding switch.
- Serve negotiated bus and reviewer_files protocols in the same process with separate connection state and rights. Validate loopback authority/Origin, authentication, protocol/session headers and request shape before dispatch. Preserve original logical tool names and file boundaries.
- Persist grants and resumable connection identity outside all canonical reviewer roots/exact files; refuse unsafe overlapping grants. Preserve in-progress mutation uncertainty across a crash so retrying the same request cannot duplicate a journal side effect. Do not claim general exactly-once execution across unrelated requests.
- Track startup reservations and actual client lifetime independently of HTTP requests or optional SSE/DELETE. Root launcher PID/birth and managed provider launch/session ownership have different evidence; neither a transient launch PID nor wall-clock startedAt is a managed process birth.

## Out of scope

- Replacing the warden loops, switching generated harness configs or retiring the old CLI stdio route; those follow in separate stages. No consumer edit, release, or model turn.

## Verification

- Ordinary public service commands and concurrent processes demonstrate one owner, restart at the retained endpoint, version/identity refusal, and clean idle shutdown. Preserve a live client with no in-flight request and the readiness-to-initialize reservation.
- Real HTTP bus/file calls reject foreign/expired/replaced/scoped credentials before effects; file tools cannot read owner or foreign credentials, including through traversal, symlink, direct reads or search. Concurrent clients never share roots or task/address context.
- Crash/reconnect tests distinguish completed, unstarted and uncertain mutation outcomes without duplicate message commits. Required gates, committed mutation probes and independent review pass; minor findings have evidence-bearing backlog entries.
