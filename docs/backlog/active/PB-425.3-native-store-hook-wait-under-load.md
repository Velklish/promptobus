## Context

Finding discovered while working on PB-425.1.

Evidence: 2026-11-05, official Node 26.13.0, 8 cores. The full gate on `161b26e9` (base `2bb2d3f5`), `npx --no-install backslop gates --require-clean --base 2bb2d3f5`, exit 1, gates 5, green 0, not run 4. Only `test/shared-service-native-store.test.mjs` failed: 4/4 passed, then the file aborted with exit 1, `Error: Owned native-store fixture did not reach its hook receipt` at the `until` helper of the file (a fixed 5000 ms deadline), load average 14.86 at its start and 46.15 at its end.

Standalone at load 9–11: `161b26e9` exit 0, 7/7, twice; base `2bb2d3f5` exit 0, 7/7, twice. With 56 CPU burners (perl busy loops), load1 50–135, alternating base and `161b26e9`: all six runs exit 1, 0/0 passed before abort — three on the base, three on the change. The abort text was the same `did not reach its hook receipt` in three runs and `Shared service still has live clients or active work [clients: 0, activeWork: false, pendingObservations: 0, requests: 2]` in the others. The file goes red on the base commit under load, so the gate red is not a product of the PB-425.1 change.

The abort comes from the file's own `until` wait, which throws out of the file instead of giving a red verdict; the verdict-before-abort rule of the suite is [Contributing § Suite isolation](../../guides/contributing.md#suite-isolation). The second message is a different failure; whether it follows the first run's leftover owned service is not established.
