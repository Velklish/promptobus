# PB-406.5 · OpenCode gets a quota source and catalog tuples, so routing can see and choose it

- **Scope:** [03. CLI § Model routing](../../reference/03-cli.md#model-routing)
- **Created:** 2026-10-28
- **Dependencies:** PB-406.3
- **Parent:** PB-406
- **Cost:** major
- **Taken:** 2026-10-28

## Context

Finding discovered while working on PB-406. Evidence: `lib/model-routing/adapter-opencode.js` reads only `opencode --version`, so `models` shows OpenCode with no windows; the catalog has no OpenCode tuples, so no strategy ever picks it. OpenCode Go documents per-model limits (5-hour window 20 % of the monthly allowance, weekly 50 %), and `opencode stats --days N --models` prints per-model token and step counts locally (verified 2026-10-27).

## Work to do

- An OpenCode availability source: local usage from `opencode stats` per model, turned into windows against an owner-declared allowance in the overlay (PB-406.3 capacity), with the documented 5-hour and weekly shares; mark the source as local estimate.
- Catalog tuples for the OpenCode models the owner uses, with ratings; deny `*-free` and `*-contributor` models by a flag the overlay can extend.

## Out of scope

- Reading OpenCode's server-side quota (no public API is known).

## Verification

- With a stub `opencode stats` output and a declared allowance, `models` shows OpenCode windows with a local-estimate source; a `*-free` model is never chosen automatically; tests fail on the current adapter.
