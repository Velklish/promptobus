# PB-416.13 · Align driver lookup and tool version declarations with existing consumer values

- **Scope:** [Host tool resolution](../../reference/02-host.md), [Driver lookup](../../reference/05-drivers.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-415.5
- **Cost:** major
- **Taken:** 2026-10-30

## Context

Evidence: during strict TypeScript migration the private workspace consumer reported two existing declaration mismatches against installed Promptobus 0.31.0. Its liftDriver calls driverFor(DRIVER_DECLARATIONS, harness) and reads only options, but src/driver.ts currently accepts Registry<full Driver> and requires phrases which the declared registry does not promise. The lookup body only indexes registry.drivers and rejects an absent harness. src/host.ts declares HostToolBin.version as string?, while the consumer preserves version:null after an unavailable or unparsed probe. Current maintained declarations still contain both restrictions; no runtime API change is needed.

## Work to do

- Make driverFor preserve the actual registry element type and accept the existing driver-declarations registry. Use a small generic/overload; do not claim phrases or operations absent from declarations, generalize unrelated registry APIs or introduce any/casts masking the mismatch.
- Represent HostToolBin.version as optional string or null, aligning any directly affected internal type boundaries without normalizing existing runtime values.
- Add consumer-shaped compile-time regressions against emitted public declarations: declarations lookup/options accepted without invented phrases, full driver lookup retains its operations, null/string/omitted versions accepted and wrong value types rejected.
- Keep runtime lookup behavior, errors and emitted JavaScript bytes unchanged. Update the relevant reference/CHANGELOG with the declaration correction.

## Out of scope

- Changing runtime API, task/actor permissions, availability/probe behavior, other deferred declaration contracts, the consumer source/pin, daemon flags, release or broad type cleanup.

## Verification

- Show both consumer-shaped compile failures before the correction and passing strict declaration checks afterward, including negative type assertions. Compare relevant emitted JavaScript bytes before/after.
- Strict build, existing driver/type checks, meaningful committed mutation probes and five repository gates pass. Fresh independent review reports zero critical/major; remaining minors have evidence.
