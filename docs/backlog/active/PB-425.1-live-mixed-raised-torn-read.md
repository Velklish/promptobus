# PB-425.1 · Two live-mixed fixtures parse the raised-file once and abort on a torn read under load

- **Scope:** [Suite isolation](../../guides/contributing.md#suite-isolation)
- **Created:** 2026-11-05
- **Dependencies:** none
- **Cost:** major
- **Previous order:** 70
- **Taken:** 2026-11-05

## Context

`live-mixed-normal-cleanup.test.mjs` and `live-mixed-timeout-retention.test.mjs` wait for the fixture's raised-file with `waitFor(() => existsSync(raisedFile) ? JSON.parse(readFileSync(raisedFile, 'utf8')) : …)`. The file exists before its writer has finished it, and a parse of the partial content throws out of `waitFor` instead of retrying, so the whole file aborts before its first verdict. [Suite isolation](../../guides/contributing.md#suite-isolation) names this shape: a read of anything another process produces goes through a retried wait.

Evidence: 2026-11-05, gates on `45dcf4d5` under official Node 26.13.0, eight cores, load average 53.4 at the file's start: `live-mixed-normal-cleanup.test.mjs` exit 1, "0/0 passed before abort", `SyntaxError: Unexpected end of JSON input` at `JSON.parse` inside the `waitFor` predicate of `runCase`. Standalone on `45dcf4d5` twice exit 0, 7/7, at load 15–17; on base `3fbd604c` exit 0, 7/7. `live-mixed-timeout-retention.test.mjs` has the same predicate in its `runCase`.

Next step: let the predicate treat an unparsable raised-file as not ready yet, so the wait retries until the file is complete or the bound runs out.

## Work to do

- Retry a torn raised-file read in both fixtures.

## Verification
