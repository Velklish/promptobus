- **Scope:** [Shared transport](../../reference/03-cli.md), [Native identity](../../reference/05-drivers.md)

## Context

Extract the transport-side native binding prerequisite from the approved launch/configuration stage. An HTTP bearer identifies a client grant, while a Codex app-server can host multiple native threads. Native tool metadata must verify an owner-established thread identity; it must not select an actor or become first-writer authorization.

Evidence: lib/service.ts presently constructs the client Host and busConnection before dispatch; initialize reaches joinDeclared and joinBus in src/mcp/server.ts and lib/server.ts, which can hand over contact and request a warden. That behavior cannot be used for an unbound startup credential. Official Codex 0.164/0.165 source stamps tools/call params._meta.threadId with the actual native thread and sessionId with a potentially shared root. Local zero-external-model native research establishes helper initialization before SessionStart; profile eligibility and managed launch classification remain separate owner obligations.

## Work to do

- Add an explicit optional Codex native binding to private owner-created service grants: pending or bound to one exact native thread. Existing non-Codex and legacy owner-created grants retain their behavior.
- Pending credentials may initialize, negotiate, ping and discover the existing tool declarations without creating a per-client Host, resolving identity, joining a task, handing over contact, starting a task warden or reading files. Deny tool calls until owner realization.
- Provide an owner-only realization operation which binds once, is idempotent for the same native ID and refuses another ID. Native identity fields in effective client env come from that binding, never inherited ancestor values or caller role headers. Do not expose realization through MCP.
- Require actual tools/call _meta.threadId to match the bound thread on both bus and reviewer_files before dispatch and before returning a cached mutation receipt. Missing, malformed, foreign, revoked or replaced proof is refused without side effects.
- After realization, create the ordinary full consumer Host with frozen lexical env. Preserve transport sessions, protocol state and durable RPC receipts; avoid stale asynchronous Host creation reinstalling pending or replaced context. Revalidate authoritative grant after asynchronous work.
- Add focused regressions through real owned HTTP service and owner controls. Update transport/native references and CHANGELOG; preserve public Host, package exports, runtime paths and pure planning.

## Out of scope

- Root profile installation, native transcript/process proof, BB managed-launch exclusion, native hook/helper integration, driver launch/config activation, root launcher verbs, consumer changes, stdio retirement and release. This task provides no root eligibility decision and does not certify a native workflow.

- Wrong or missing native metadata fails for bus and file tools, including a reused request ID with a saved successful response. Concurrent realization/revoke and deferred Host creation cannot restore stale authority. Reviewer grants remain isolated.
- Full five repository gates, meaningful committed mutation probes, fresh independent review to zero critical/major, and evidence-backed remaining minor entries. No external model call is needed for transport fixtures.
