# PB-373.17 · An OpenCode holder reports a running turn while an external-directory ask has nobody to answer it

- **Scope:** [05. Drivers](../../reference/05-drivers.md)
- **Created:** 2026-10-28
- **Dependencies:** none
- **Parent:** PB-373.6
- **Cost:** major — the participant never finishes a model call, so a lift whose first read is outside its session directory does no work and still reads as `turn running`; the holder stays up, which keeps it short of critical.
- **Previous order:** 317
- **Taken:** 2026-10-28

## Context

Finding discovered while working on PB-373.6, measured by a separate investigation of a consumer workspace's run on 2026-10-27/28.

Two OpenCode 2.0.20 workers lifted by `spawn` with model `opencode-go/minimax-m3` sat in a running turn and never finished a model request (the first for 33 minutes, the second for 10). Evidence: the OpenCode server log for both runs (`run=54c099fe`, `run=34569ac4`) shows `serve --port 0 --hostname 127.0.0.1`, connected tool servers and a snapshot `write-tree`, then only `provider.updated` / `model.updated` every five minutes; no session id, no `Failed to drain Session`, no permission line. `opencode stats --days 1 --models` → `opencode-go/minimax-m3 0 tokens, 1 step`. `promptobus status` said `turn running` throughout, and neither worker sent its first bus message. Watcher volume is not the cause: the second run had 91 watcher events and the same silence.

The lift treats an HTTP 200 on the first prompt as a started turn and never reads pending permissions:

<!-- quote:../../../lib/opencode-session.js -->
export const sendPrompt = (url, password, sessionId, text, fetchFn = call) => fetchFn(
  url, password, 'POST', `/api/session/${sessionId}/prompt`, { text },
);
<!-- /quote -->

<!-- quote:../../../lib/driver-opencode.js -->
    const sent = await sendPrompt(url, password, sessionId, plan.prompt);
    if (sent?.status !== 200) fail(`the first turn answered ${sent?.status ?? 'nothing'}`);
<!-- /quote -->

<!-- quote:../../../lib/driver-opencode.js -->
  const busy = !hit?.time?.idle;
  return { state: 'alive', busy, stall: null, id: record.sessionId, note: busy ? 'turn running' : 'idle' };
<!-- /quote -->

The written config carries `model`, `mcp` and only a deny map from `permissionDeny`; it has no grant for directories outside the session cwd. OpenCode 2.0.20's primary agent asks on `external_directory` for every outside path, and `Permission.reply` is reachable only through the HTTP reply route, which a headless `serve` has no client for. The server log does not record the ask.

Reproduction, 2026-10-28, OpenCode 2.0.20, one holder, config `model` `opencode-go/minimax-m3`, `enabled_providers` `["opencode-go"]`, cwd a fresh git directory: `POST /api/session/:id/prompt` with one line asking to read a file outside the cwd returned 200 in 1.16 s; at 3.2 s `GET /api/session/:id/permission` returned one ask, action `external_directory`, resource the outside directory with `/*`; `time.idle` null, tokens input 0 / output 0. Control, the same holder with a prompt naming no outside path: idle in about 5.7 s, tokens input 13497 / output 2, no permission ask. The 05-drivers reference already names the symlinked-cwd form of this stall; the lifts here ran in real paths, and any outside path triggers it.

An empty OpenCode data directory is a different failure, not this one: there the binary selected a deprecated free model and failed at once.

## Work to do

- A headless holder must not leave an `external_directory` ask unanswered: grant the lift's declared roots in the config permission map, or poll the permission route and reply for those roots only.
- An ask still pending fails the turn or the lift and is reported as such; `viewOf` distinguishes a pending ask from a model call instead of `turn running`.
- Update the 05-drivers OpenCode section and the CHANGELOG.

## Out of scope

- Watcher churn, the tool-server set, model choice, and the empty-data-directory fallback to a free model.

## Verification

- A no-model stub holder that answers 200 to the prompt and returns a non-empty permission list: current `spawn` succeeds and `viewOf` says `turn running`; after the change the ask is answered for declared roots or the lift fails naming it. A test fails on the current code.
