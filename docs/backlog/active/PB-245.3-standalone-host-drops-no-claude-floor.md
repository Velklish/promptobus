# PB-245.3 · Under the standalone host the Claude version floor drops nothing: the host hands over no binary version, so a build older than 2.1.280 is still routed to Opus 5.5

- **Scope:** [02-host](../../reference/02-host.md), `src/standalone.ts`
- **Created:** 2026-09-24
- **Dependencies:** none
- **Parent:** PB-245.1
- **Cost:** major
- **Previous order:** 75
- **Taken:** 2026-09-25

## Context

Finding discovered while working on PB-245.1, by its isolated review.
Evidence: the chain below is read in the source, and the unit is pinned by `test/model-routing-adapter-claude.test.mjs`. The host resolves the binary without a version:

<!-- quote:before:../../../src/standalone.ts -->
    resolveToolBin: (name): HostToolBin => ({ ok: true, bin: name }),
<!-- /quote -->

The Claude adapter hands that missing field to the driver's inventory:

<!-- quote:before:../../../lib/model-routing/adapter-claude.js -->
  const models = inventoryOf(tool.version);
<!-- /quote -->

`inventoryFor` keeps every id when `versionLess(undefined, '2.1.280')` is false, because `parseVersion` returns `null` for an absent value. So under the standalone host, which is the package's default, `claude-opus-5-5` stays in the inventory whatever build is installed. A build older than 2.1.280 then gets an Opus 5.5 tuple routed to it and refuses it: on 2.1.263, `claude -p --model claude-opus-5-5 --max-turns 1 --output-format json 'reply with the single word ok'` exits 1 with `API Error: 400 Claude Code 2.1.263 does not support this model; version 2.1.280 or newer is required`, and its `modelUsage` is empty (PB-245.1, 2026-09-23). A host that reads the version gets the floor: a workspace host whose `resolveToolBin` runs `--version` hands `HostToolBin.version` over.

The fix belongs to the host, not to the driver. The floor, its table and the adapter already work on any host that hands over the version. What is missing is the version itself, and the standalone host leaves it out on purpose: it does not search for or probe the binary, and its `resolveToolBin` is synchronous ([02-host](../../reference/02-host.md) § the standalone host). Reading it would cost one `claude --version` subprocess per preflight, on every routed pick under the default host, and would change that host's design. That is a cost and design choice for the owner, outside PB-245.1's brief. Until then the reference points a person on an older build under the standalone host to an overlay `deny: { models: ["claude-opus-5-5"] }` or to `claude update`.

## Work to do

- **The owner's decision, 2026-09-24:** the standalone host reads the binary's version — `claude --version` once per preflight, with a ceiling — so that the Claude floor and the other version readers (`optionRefusal`, the proven-version warnings) work under it.
- Hand the version over from `resolveToolBin` or from the preflight, update [02-host](../../reference/02-host.md) § the standalone host and the floor paragraph of [03-cli](../../reference/03-cli.md), and pin that a standalone preflight drops `claude-opus-5-5` below 2.1.280.

## Out of scope

- The floor's table and `inventoryFor` (PB-245.1).

## Verification

- Under the standalone host with a stub `claude` answering `2.1.263 (Claude Code)`, `promptobus models --refresh` excludes the Opus 5.5 rows as `model-not-in-inventory`, and on `2.1.280` it keeps them.
