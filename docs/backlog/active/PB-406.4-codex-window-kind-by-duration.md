# PB-406.4 · A Codex window's kind follows its duration, not its slot name

- **Scope:** [03. CLI § Model routing](../../reference/03-cli.md#model-routing)
- **Created:** 2026-10-28
- **Dependencies:** none
- **Parent:** PB-406
- **Cost:** major
- **Taken:** 2026-10-28

## Context

Finding discovered while working on PB-406. Evidence: `lib/model-routing/adapter-codex.js` maps `WINDOW_KIND_BY_ID = { primary: 'session', secondary: 'weekly' }`; on 2026-10-28 the owner's Codex account returned only `primary` with `lengthSec` 604800 (a weekly window), which routing labelled `session`.

## Work to do

- Derive `kind` from the window's duration (`windowDurationMins` or `lengthSec`), falling back to the slot name only when the duration is missing; document the mapping.

## Out of scope

- Changing other harnesses' window kinds.

## Verification

- A `primary` window of 604800 s is reported as `weekly`, one of 18000 s as `session`; a test fails on the current mapping.
