# PB-416.11 · Adapt the BB integration to the installed SDK Git read contract

- **Scope:** [BB Host integration](../../reference/02-host.md), [BB integration](../../../integrations/bb/README.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-416.2
- **Cost:** major
- **Parent:** PB-416.4
- **Taken:** 2026-10-30

## Context

The approved shared transport must retain the installed BB root and managed ownership paths. The current integration declares exact BB 0.47.1 and Plugin SDK 0.6.79 while the installed app is BB 0.48.0/SDK 0.6.94. Its plugin is incompatible before activation. Root admission requires a functioning supported BB Host integration; changing the engine number alone is insufficient verification.

Evidence: the existing integration compiles on SDK 0.6.79, exit 0. A declaration-only SDK 0.6.94 overlay fails with the same ten diagnostics in three runs, exit 1 each: five environments.status calls, one environments.diffPatch call and four resulting implicit-any bindings in lifecycle.ts/runtime.ts. The official installed plugin-authoring reference replaces these reads with bb--git workspaceStatus and files/patches RPC. The current SDK already supports typed thread/identity event queries, so that lookup itself is not the reason to widen another interface.

## Work to do

- Update the integration's exact supported BB/SDK profile to the installed official pair and pinned package lock. Use current public SDK declarations and official plugin-authoring guidance; no old API casts or private BB dependencies.
- Replace the six retired Git reads through a small typed adapter over the official Git plugin RPC contracts. Copy only consumed schema fields, validate freeform results and propagate cancellation. Preserve environment/host/path/HEAD/base identity, complete file and patch correspondence, binary/submodule/truncation refusals and the existing two-read snapshot consistency rule.
- Update affected integration fixtures and current-profile documentation. Historical measured profiles remain labelled historical; compilation and fixtures do not certify live Stop or native workflow behavior.
- Run the unchanged integration baseline before source edits, then integration check/test/build, public SDK scan where available and current CLI type/build checks. Fix relevant failures with exact evidence. Commit and freeze the independently reviewable change.

## Out of scope

- Root admission/helper/guard wiring, managed launch exclusion calls, shared HTTP driver activation, consumer pin or plugin installation/reload, native model turns, changing native Stop semantics or widening privileges. Activation and live proof belong to the subsequent integration stage.

## Verification

- Current SDK compiles without casts around removed methods. Existing integration tests retain identity, patch preservation, incomplete result and changed-during-capture assertions. Add focused RPC validation/cancellation coverage only where the new adapter creates a failure boundary.
- Strict TypeScript, current SDK/plugin build checks, full integration tests, five root repository gates and meaningful committed mutation probes pass. Fresh independent review has zero critical/major; remaining minor findings have evidence-backed entries.
