# PB-416.15 · Admit approved Codex exec control flags as standalone NEW and refuse unsupported NEW before exec

- **Scope:** [Host](../../reference/02-host.md#standalone-root-profiles)
- **Created:** 2026-11-03
- **Dependencies:** none
- **Cost:** major
- **Previous order:** 410
- **Taken:** 2026-11-03

## Context

The consumer's standalone Codex root on the published 0.32.1 passes preflight and starts the native process, records its hook identity, then revokes its client: the first tool call returns HTTP 401 `Client binding is absent or expired`. Its approved invocation is `exec` with read-only sandbox, model, strict and user-config isolation, invocation-only hook trust for its reviewed owned hooks, every foreign hook disabled, one trusted project and one exposed, approved bus tool.

Evidence: at 3fcdbed262ba06190c13847f89097f869f3577c8, `claimStandaloneIdentity` in `lib/standalone-root-state.ts` treats Codex as NEW only for exactly `exec -- <prompt>` or the two `--no-daemon` forms; preflight in `lib/standalone-root.ts` checks only the first argument and the remote/daemon refusals. A static replay of the consumer's 21-argument command is accepted by preflight and refused by first binding. The consumer's original hook stderr was not captured; the revoke-then-401 sequence is observed, its first exception is inferred from source.

Source facts, codex rust-v0.166.0 (6ff1e1ca3b30fc8b914720681fcf5fe62e95f856): `exec` subcommands are `resume`, `fork` and `review`; `PROMPT` is an optional positional and `-` reads stdin (`codex-rs/exec/src/cli.rs`). `--model/-m` and `--sandbox/-s` take one value; `-c/--config` is global, splits on the first `=` and parses the value as TOML (`codex-rs/utils/cli/src/shared_options.rs`, `config_override.rs`). Without a subcommand `exec` always calls `thread/start`, whose parameters carry no session selector (`codex-rs/exec/src/lib.rs`, `start_thread`).

## Work to do

- One Codex NEW exec classifier shared by preflight and first binding. It admits exactly the approved control subset, each at most once: `--strict-config`, `--ignore-user-config`, `--dangerously-bypass-hook-trust`, `--skip-git-repo-check`, `--json`, `--sandbox read-only`, `--model <id>`, and `-c` for `model_reasoning_effort` (known effort names), `projects` (one entry: the launch's canonical cwd, `trust_level="trusted"`), `hooks.state` (entries that are exactly `{enabled=false}`), `mcp_servers.promptobus.tools` (entries exactly `{approval_mode="approve"}` for enabled tools only) and `mcp_servers.promptobus.enabled_tools` (unique `promptobus_*` names), followed by one nonempty final prompt that is not `-`, not a subcommand and not option-like, optionally after `--`. Every other token, duplicate, `=`-joined form, subcommand or missing prompt is not NEW.
- Preflight refuses a Codex `exec` command that is neither NEW nor a `resume`/`fork` selection before it writes the exec plan, so no native process, model turn or client grant is spent.
- Document the accepted NEW argv in the Host reference, ADR-040 and README, and the change in CHANGELOG.

## Out of scope

- Any other Codex flag or config key, other harnesses, `--no-daemon` TUI forms, hook trust policy, personal native configuration, account copies, and weakening process, image, hook-origin, SessionMeta or thread-ID checks.

## Verification

- Classifier unit checks: the consumer's exact argv is NEW; each refused shape is not.
- Fixture end-to-end: the consumer-shaped argv is admitted and its tool call succeeds; an unsupported `exec` argv refuses before the native child starts, with no grant or binding.
- Mutation probes on the classifier and the preflight refusal; affected standalone tests; final configured commands on Node 26, Linux CI, package and one joint native acceptance run by the consumer's owner on the candidate artifact.
