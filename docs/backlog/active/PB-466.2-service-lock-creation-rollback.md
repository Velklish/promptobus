### PQA-2008 - Release the newly created service lock after owner publication fails

Audit priority: medium. Evidence status: confirmed.

Evidence: lib/service-state.ts:332,344 creates the lock directory before writing owner.json. A write failure before rename returns before a release is available. src/fs/atomic.ts:23-28 cleans up the temporary file only. A later attempt sees an ownerless directory and refuses at lib/service-state.ts:339. The startup client and daemon use this path at lib/service-client.ts:109 and lib/service.ts:96. test/service-lock-release.test.mjs:135-144 deliberately protects pre-existing ownerless locks.

Acceptance: Inject a failure before owner publication. Preserve the original error and verify that a normal retry can acquire the lock after the transient failure clears. Restrict cleanup to the same newly created, still-empty directory. Keep replacement directories, nonempty directories and pre-existing ownerless locks intact. Run node test/service-lock-release.test.mjs on a platform with process birth information.
