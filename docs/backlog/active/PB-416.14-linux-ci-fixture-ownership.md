## Context

The published 0.32.0 candidate passes its local macOS Node 20 full run, but the Node 22 Ubuntu job rejects four standalone fixture paths that approve global `process.execPath` as their fake native executable. The failure proves the strict regular-file/write-mode branch was reached; the actual global Node mode was not captured. Fixtures must provide their own approved executable rather than depend on the CI toolcache's permissions.

The controlled service-state comparer also mocks Darwin process calls while retaining the outer Linux run's execution trace. Its synthetic `/bin/ps` observation contaminates the run's real-command hygiene verdict.

Evidence: [Node 22 Ubuntu job](https://github.com/Velklish/promptobus/actions/runs/41450582660/job/125294497628), commit c62077becbb52e04201f8eac8ea96ec1672bf9b8: 256/260 files, four standalone executable refusals and one PATH-seal entry. `test/service-state-comparability.test.mjs` mocks spawn while switching platform to Darwin; `lib/exec.ts` still records to the inherited trace.

The second Node 22 Ubuntu run additionally fails Cursor startup; Node 20 Ubuntu runs fail managed-launch cleanup or the mixed stand. Both Cursor traces first fail `notifications/initialized` with the managed-observation revision 409 before later native/Stop failures. The source permits startup publication during that asynchronous observation; the exact historical writer remains unknown. Moving the fixture's HTTP bootstrap behind its binding ACK would conceal that client-visible startup boundary, so the service must obtain a fresh complete proof before dispatch when the same authority's record revision changes. A separate cleanup fixture can observe a published holder failure before physical exit/RPC availability; its cleanup must wait for its own lifecycle proof rather than mask the primary assertions.

## Work to do

- Give the three standalone process fixtures and installed consumer fixture their own native Node copy with mode 0700. Use that same file in approval, native launch and expected process-image proof. Keep ordinary helper/CLI Node and product authority checks unchanged.
- Isolate the comparer mock trace inside its sandbox and restore its inherited environment. Check that synthetic observations are present locally and absent from the outer run trace.
- Bound managed observation refresh to three complete attempts before dispatch. Every successful attempt must establish its own stable revision, current original grant, unchanged participant/native launch, process lifetime, native binding and live observation. Credential, identity, generation, dead/unknown and sustained-drift failures retain their refusals; effects are never retried.
- Make failed-launch fixture cleanup wait within its existing deadline for exact owned natural exit or a responding holder, then attempt public cleanup once. Unknown outcomes retain record and home.

## Out of scope

- Accepting a stale observation, broadening authority or PATH allowlists, changing global toolchain permissions, native account/configuration, consumers or the existing published tag.

## Verification

- Sequential affected fixture and installed-consumer checks, controlled writable-executable refusal and secure-copy success, meaningful mutation probes and independent changed-file review.
- Final configured commands and CI matrix on a frozen patch candidate. Retain exact original CI failures and do not claim their missing file-mode or trace operands were observed.
- Real HTTP single-drift recovery after a fresh stable observation, sustained-drift refusal, unchanged identity/credential/dead/unknown negatives, exactly one tool effect and an independent final security review.
