# PB-416.7 · Preserve authenticated HTTP MCP fields in driver configurations

- **Scope:** [Native drivers](../../reference/05-drivers.md), [Host MCP contract](../../reference/02-host.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-416.2
- **Cost:** major
- **Previous order:** 410
- **Taken:** 2026-10-30

## Context

Extract the existing HTTP configuration gap from the approved launcher stage so it can be verified independently of launch ownership. This stage preserves caller-supplied HTTP auth references; it does not activate shared transport for managed sessions.

Evidence: lib/codex-session.ts codexMcpServers copies url, literal headers and disabled tools but drops bearer_token_env_var and env_http_headers. lib/driver-opencode.ts mcpConfig copies remote url/headers but drops oauth:false. Real manual private configurations initialized the shared service with Claude 2.1.308, Cursor 2026.10.22-27dcf5f, private Codex 0.164.0 and OpenCode 2.0.20 using protocol 2025-06-18 and zero model turns. These probes bypassed the converters and therefore do not certify them. The separate launcher stage must provide actual runtime credentials, native identity and coordinated install/sync behavior.

## Work to do

- Preserve demonstrated native HTTP auth fields through the Codex namespace/config and private-home TOML paths: bearer_token_env_var and env_http_headers, together with existing literal headers and disabled tools.
- Preserve explicit OpenCode oauth:false through remote config conversion, retaining headers, URLs and local stdio behavior. Do not turn false into an absent value through a truthiness check.
- Give maintained internal TypeScript fields concrete types where consumed. Keep existing package specifiers, tool namespaces and the public Host interface. Retain references as references without expanding secrets during planning.
- Add focused regressions for the actual converter and driver-prepare output; retain Claude/Cursor HTTP auth/helper fields and all existing stdio cases. Update the relevant driver reference.

## Out of scope

- New launcher verbs or flags, service startup or client registration in prepare/dry-run, managed launch/session publication, root launchers, default transport changes, product stdio retirement, account/model changes and consumer repins.
- Inventing a future header-helper format, implementing unrelated native configuration fields, or substituting manual native configs for converter tests.

## Verification

- New focused cases fail on the old converter, then pass through the actual generated config path. Verify environment-name references remain literal, native oauth:false survives, input objects remain unchanged, namespaces/disabled-tools stay correct, and stdio output remains unchanged.
- Five repository gates, committed meaningful mutation probes and fresh independent subagent review. No model turn is needed; prior native auth/init proof remains separate from generated config and launcher acceptance.
