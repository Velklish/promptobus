# PB-334.1 · A repository promptobus.json that holds only repository declarations does not become the standalone root

- **Scope:** [02-host § Standalone host](../../reference/02-host.md#standalone-host)
- **Created:** 2026-10-04
- **Dependencies:** none
- **Cost:** major
- **Previous order:** 5
- **Taken:** 2026-10-04

## Context

Finding discovered while working on PB-334.
Evidence: the PB-334 worker measured on its branch (head `ecfd9e88`) that a repository `promptobus.json` holding only `trustedHooks` becomes the standalone root, the default store and the install root; a unit check at the end of `test/project-hooks.test.mjs` on that branch pins it. The reviewer of that branch traced the consequence from code, not from a live lift: `src/standalone.ts` finds the root by the nearest `promptobus.json` from the working directory and takes `pipeline` from it, `bin/promptobus.js` builds the host from `process.cwd()`, the registry is built from `host.pipeline()`, and `resolveIdentity` in `lib/store.js` refuses an address the registry lacks. So a participant of a pipeline step declared only in the install root's file, lifted in a worktree whose repository commits `{ "trustedHooks": … }`, gets its MCP server and guard refused: the bus is unreachable for it.

PB-334 makes the repository `promptobus.json` the place for `trustedHooks`, and PB-326 makes it the place for `generate`. Both are declarations a repository owns; neither is meant to move the install root. The same shadowing already applied to `generate` before PB-334.

## Work to do

- Root discovery skips a `promptobus.json` that carries only repository declarations (`trustedHooks`, `generate`), or an equivalent rule that keeps the install root where it is; record the rule in the standalone-host reference.
- Repository declarations are still read from the repository's own file by the code that reads them today.
- Remove the consequence that PB-334 documented as a limit from ADR-025, the hooks guide and the CHANGELOG migration note once it no longer holds.

## Out of scope

- The `trustedHooks` contract itself (PB-334) and the generator order (PB-326).

## Verification

- With an install-root `promptobus.json` declaring a pipeline step and a nested repository `promptobus.json` holding only `trustedHooks`, `createStandaloneHost({ cwd: <repository> })` keeps the install root and its registry admits the step address; a test fails on the old discovery.
- A repository `promptobus.json` with host fields keeps today's behaviour, named in the reference.
