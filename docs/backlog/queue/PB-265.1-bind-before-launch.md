# PB-265.1 · A lifted participant's first send can land before its lift binds the record: bind it before launch

- **Order:** 320
- **Scope:** [04-protocol § Addresses](../../reference/04-protocol.md#addresses), [ADR-014](../../adr/adr-014-mcp-session-proof.md)
- **Created:** 2026-09-26
- **Dependencies:** none
- **Cost:** major

## Context

Finding discovered while working on PB-265.
Evidence: `npm test` under the machine lease on the PB-265 branch, before the stands were taught to wait — `promptobus-harness`, `promptobus-driver-cursor` and `promptobus-cursor-wake` red, `promptobus-driver-codex` green.

A send is made only as a record the calling session provably holds (PB-265), and a lift binds the record only after the session is already running. The order is: the record is written unbound before launch —

<!-- quote:../../../lib/spawn.js -->
    session: null,
<!-- /quote -->

— the session is launched, and the binding comes on the second pass, after the lift has seen the session:

<!-- quote:../../../lib/liftoff.js -->
  persist(session, unbound ? 'dead' : seen.state, full);
<!-- /quote -->

<!-- quote:../../../lib/driver-cursor.js -->
  persist(name, 'alive', chatId);
<!-- /quote -->

A session that sends inside that window is refused. Measured on the stands, which play turn 0 the moment the session is up:

- Claude stand (`promptobus-harness`): the MCP child names its session, the record is not bound yet — measured before the refusal gained its retry sentence, `error: «worker:probe» of task harness-t20260901-000000 carries no session binding — its record is legal to read and illegal to send as, and only a lift binds it`.
- Cursor stand (`promptobus-driver-cursor`, `promptobus-cursor-wake`): the session-record pointer is in the child's environment, but `chatId` is patched into that record only after `liftSession` returns, so the child has no identity at all — `error: this process cannot name its own session — no declared harness names itself in this environment (looked at CLAUDE_CODE_SESSION_ID, CURSOR_CONVERSATION_ID, CODEX_THREAD_ID), so no address it claims in task cursorbus-t20260903-000000 can be checked, and none is given to it`.
- Codex, the measured contrast: `promptobus-driver-codex` stayed green, because its persist follows `waitReady` — the thread id is known before the lift returns.

<!-- quote:../../../lib/driver-codex.js -->
  persist(rec.threadId, 'alive', rec.threadId);
<!-- /quote -->

PB-265 fails this closed: the refusal tells a session whose lift is still running to send again after the next turn, a lift that returns without a binding is itself refused, and the stands wait, bounded, for the binding before their first send (`test/harness-shared.mjs`, `awaitBinding`). The pre-launch binding closes the remaining window between launch and persist. In production the window is short against a model's first tool call — an inference, not a measurement: no live lift was timed for this card.

Closing it means binding before launch. For Claude, a session id chosen before launch and handed to the harness, written on the record with the rest of it. For Codex and Cursor, the ADR-014 session-record pointer written on the participant record before launch and accepted as the binding without the id — which amends ADR-014:

<!-- quote:../../../docs/adr/adr-014-mcp-session-proof.md -->
- Removing the pointer or presenting a record before its id exists leaves the route closed.
<!-- /quote -->

That change reaches `lib/drivers.js` (`mcpIdentityCandidates`) and the three drivers, none of which PB-265 touched.

## Work to do

- Write a participant binding before launch on every lift: a pre-set session id for Claude, the session-record pointer for Codex and Cursor.
- Accept the pointer as the binding while its id is still null, and amend ADR-014 by name.
- Drop the stands' wait (`awaitBinding`) once a send inside the window is no longer refused.

## Out of scope

- The proof rule of PB-265 itself: a record bound to no session stays unsendable.

## Verification

- A stand that sends at turn 0, with no wait, reaches the orchestrator on Claude, Cursor and Codex.
- A record whose pointer names another home, task or address still proves nothing.
