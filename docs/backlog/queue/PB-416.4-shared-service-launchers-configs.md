# PB-416.4 · Launch harness clients through authenticated shared HTTP configurations

- **Order:** 390
- **Scope:** [CLI](../../reference/03-cli.md), [Drivers](../../reference/05-drivers.md), [Install](../../reference/02-host.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-416.1, PB-416.3, PB-416.6
- **Cost:** major

## Context

The owner selected launcher-based cold start with idle exit and coordinated HTTP migration. Managed launches ensure readiness immediately before real harness start. Root sessions use a package/consumer launcher; ordinary HTTP configuration cannot start an absent listener.

Evidence: all four current drivers render MCP configuration separately; codexMcpServers currently drops env bearer/header fields and the OpenCode converter drops oauth:false. Existing prepare/dry-run paths must not start a service. Native HTTP identity cannot be inferred from stdio child environment: Codex 0.164 reads env_http_headers process-wide and its headers helper excludes CODEX_THREAD_ID.

## Work to do

- Render authenticated HTTP bus/reviewer_files configs for every supported harness/role; keep credential references as references rather than writing runtime bearers into project/task files. Remove inherited owner/foreign credential variables before assigning a child's own binding.
- Integrate startup reservation, grant realization and provider ownership publication into real worker/teamlead/review/approver/reporter/root launch paths. Planning and dry-run remain pure. Preserve native session IDs and existing task/launch proof; do not invent an interchangeable synthetic session ID.
- Provide the chosen root launcher and a stable public consumer boundary. Preserve minimum Node support and existing package paths; avoid a permanent per-root Node proxy. Verify platform-specific execution behavior explicitly.
- Update managed install/sync plans, diagnostics and reconnect instructions. Retire the former CLI stdio invocation with actionable upgrade guidance, without a persistent fallback process. Send the exact accepted CLI/HTTP/Host-factory contract to the parallel consumer owner only when concrete.

## Out of scope

- Consumer implementation/pin changes, publication, new model policies and reducing the number of agent harness/model sessions.

## Verification

- Cold root launch, managed launch and reconnect use the same service owner; no extra permanent MCP/proxy processes. A live client remains connected across idle periods. Unsupported profile/platform evidence stays explicit.
- Generated configs contain no live bearer; actual native clients authenticate with their own identity and cannot borrow ancestor/foreign grants. Required fixture, package, install and lifecycle checks, gates, mutation probes and independent review pass.
