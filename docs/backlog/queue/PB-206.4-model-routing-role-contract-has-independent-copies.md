# PB-206.4 · Model-routing role contract still has independent copies

- **Order:** 290
- **Scope:** `lib/model-routing/catalog.js`, `lib/model-routing/resolver.js`, `lib/model-routing/telemetry.js`, `schemas/model-routing/*`, [model-routing guide](../../guides/model-routing.md)
- **Created:** 2026-09-12
- **Dependencies:** none

## Context

Finding discovered while adding `approver` in PB-206. The runtime has three independent closed role-list projections:

<!-- quote:../../../lib/model-routing/catalog.js -->
export const RULE_ROLES = ['worker', 'reviewer', 'approver'];
<!-- /quote -->

<!-- quote:../../../lib/model-routing/resolver.js -->
export const ROLES = ['worker', 'reviewer', 'approver'];
<!-- /quote -->

<!-- quote:../../../lib/model-routing/telemetry.js -->
  if (!['worker', 'reviewer', 'approver'].includes(p?.role)) return false;
<!-- /quote -->

Two closed maps in `DEFAULT_POLICY` must repeat the same keys too:

<!-- quote:../../../lib/model-routing/catalog.js -->
  qualityFloor: Object.freeze({ worker: 5, reviewer: 9, approver: 7 }),
<!-- /quote -->

<!-- quote:../../../lib/model-routing/catalog.js -->
  byRole: Object.freeze({
    worker: Object.freeze({ allow: Object.freeze({}), deny: Object.freeze({}) }),
    reviewer: Object.freeze({ allow: Object.freeze({}), deny: Object.freeze({}) }),
    approver: Object.freeze({ allow: Object.freeze({}), deny: Object.freeze({}) }),
  }),
<!-- /quote -->

Four JSON schemas repeat the same contract as enums or closed property maps. The
parity check added in PB-206 found two pre-existing disagreements within ten minutes:
`overlay.schema.json` rejected an approver `byRole` block that runtime accepted, and
`DEFAULT_POLICY.byRole` lacked the role so merge crashed before schema validation.
Both would have shipped silently without the new check; this is demonstrated drift,
not a hypothetical cost of a fifth role.

PB-206 leaves consolidation separate because introducing one role and changing the
dependency or generation boundary of every runtime and JSON-schema consumer are
different contract changes. In exchange, one parity test now compares the runtime
role lists, both default maps, catalog role surfaces, overlay floor and `byRole`
maps, decision role and telemetry role so the remaining copies fail together.

The protocol address roles are not automatically the right source. Model routing
excludes `orchestrator`, and a future addressed participant may deliberately be
unrouted. The canonical value therefore has to mean “routed participant roles”, not
“every address except the orchestrator”.

## Work to do

- Choose one canonical runtime export for routed participant roles.
- Make catalog merge, validation, resolution, live-tuple accounting and telemetry
  consume it rather than keeping independent arrays.
- Decide whether the JSON schemas are generated from that source or remain static
  artifacts guarded by one explicit parity test; document the chosen boundary.
- Make an unknown or deliberately unrouted participant role an explicit outcome at
  every projection instead of an accidental omission.

## Out of scope

- Adding another participant role.
- Changing the `approver` floor, permissions or routing policy decided by ADR-013.
- Treating all non-orchestrator addresses as routed without deciding that contract.

## Verification

- A mutation that adds a fixture role at the canonical runtime seam turns every
  stale schema or projection check red; after the corresponding contract update,
  catalog validation, resolver choice and telemetry projection all cover it.
- `npm test` and `npx github:Velklish/backslop#v0.7.0 lint` exit 0.
