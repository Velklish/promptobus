# PB-159.2 · В пуле persist-сессия Cursor осталась без метки задачи, и это не бюджет настенных часов

- **Order:** 100
- **Scope:** [03-cli](../../reference/03-cli.md), `lib/cursor-persist.js` (`liftSession`, `tmuxSessions`), `test/promptobus-driver-cursor.test.mjs` (step 1)

- **Dependencies:** none
- **Cost:** major
- **Parent:** PB-159.1

## Context

Finding discovered while working on PB-223 and PB-218 (прогон очередей 2026-09-16).

Родительская карточка объясняет каждую свою красноту **бюджетом настенных часов**: классификатор простоя, бюджет пробы, окно подъёма заглушки, удерживаемый замок инъекции. Этот случай другой формы, и потому вынесен отдельно: бюджета в упавшей проверке нет вовсе.

`npx github:Velklish/backslop#v0.8.0 gates --keep-going --require-clean` на коммите `51cb9d67f43263e7c2a00cdd94b015618d05878b`, дерево чистое, exit 1: `gates 4, green 3`. Красный только `npm test` (code 1, 205623 ms), в нём один файл из 68 — `test/promptobus-driver-cursor.test.mjs`, 126/127. Упала проверка «step 1: the persist session lives on the shared server and is marked with the mechanism task and address», деталь целиком:

```
[{"name":"cursor-promptobus-cur-t20260903-000000-e0db0eb3f6-1-915c73","attached":0,"created":1789565305,"panePid":35231,"managed":true,"hash":"e0db0eb3f6","chatId":"6badc2b9-226d-45b7-a097-4358a8f95031","task":null,"address":"worker:cur"}]
```

Сессия на месте, `managed` стоит, `chatId` совпал, `address` проставлен — **не проставлен только `task`**.

Метка задачи не имеет отношения ни к резолверу идентичности, ни к часам: это опция tmux, которую читает разбор списка сессий,

<!-- quote:../../../lib/cursor-persist.js -->
      task: task || null,
<!-- /quote -->

и которую ставят двумя соседними вызовами, сначала задачу, потом адрес:

<!-- quote:../../../lib/cursor-persist.js -->
    if (task) tmux(['set-option', '-t', seen.name, TASK_OPT, task], { env });
<!-- /quote -->

<!-- quote:../../../lib/cursor-persist.js -->
    if (address) tmux(['set-option', '-t', seen.name, ADDRESS_OPT, address], { env });
<!-- /quote -->

Отсюда главное в наблюдении: **пропала более ранняя из двух опций, а поздняя встала**. Гонка чтения после записи дала бы обратную картину — поставленную первую и отсутствующую вторую. Значит первый `set-option` вернулся, не изменив сессию, и его код возврата никто не читает: оба вызова идут без проверки результата.

Улики о повторяемости, все на том же коммите `51cb9d6`:

- полный `npm test` в составе гейтов — красный один раз (выше);
- полный `npm test` за 15 минут до него, на том же дереве до правки реестра песочниц — этот файл зелёный;
- повторный `npx ... gates --keep-going --require-clean` на том же коммите — exit 0, `gates 4, green 4`, `npm test` code 0, 68/68 files passed;
- отдельный `node test/promptobus-driver-cursor.test.mjs` — exit 0 и exit 0, 127/127 оба раза.

Итого: один красный из четырёх измерений одного кода, и все зелёные — после красного.

Проверенные и **не подтвердившиеся** объяснения:

- *столкновение двух прогонов suite на общем tmux-сервере между воркдеревьями.* Ведущий прогон проверил: в этом репозитории в те минуты других `npm test` не было, а наборы соседних репозиториев на общий сервер `cursor-agent` не ходят — живых `tmux new-session` в них нет;
- *регрессия резолвера идентичности из PB-218.* Поле `task` в этой записи приходит из опции tmux (цитаты выше), а не из `resolveSessionIdentity`; ни один коммит прогона не трогает `lib/cursor-persist.js` и путь метки.

> Источник: 2026-09-16, два полных прогона гейтов и два отдельных прогона файла на `51cb9d6`; текст проверки и деталь сняты из вывода прогона, путь метки прочитан в `lib/cursor-persist.js`.

## Work to do

- Решить, что делает механизм с непоставленной меткой. Непомеченная сессия на общем сервере неотличима от чужой — это написано рядом в коде, — значит молчаливый пропуск метки дороже отказа подъёма.
- Проверку step 1 привести к форме, которая различает «метка не встала» и «список прочитан слишком рано»: сегодня обе читаются одинаково.

## Verification

- `tmux set-option` для метки задачи проверяется по коду возврата, и неуспех виден в результате подъёма, а не только в падении теста через несколько шагов.
- Мутационная проба: убрать установку `@promptobus_task` — step 1 краснеет с текстом, который называет именно непоставленную метку.
