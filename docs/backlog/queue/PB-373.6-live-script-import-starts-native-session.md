# PB-373.6 · Importing a live entry point accidentally starts a native harness session

- **Order:** 260
- **Scope:** [Live smoke runs](../../reference/02-host.md)
- **Created:** 2026-10-16
- **Dependencies:** none
- **Cost:** major

## Context

An agent attempted a module-load check during a stub-only correctness phase and imported the executable `scripts/live-mixed.mjs`. Its top-level code started a real native Cursor persist session. This is an observed execution mistake; whether an entry-point guard or a tooling instruction is the right product change remains to be decided. Importing an executable is not a syntax check.

Evidence: original BB thread `thr_uxrkbuuynz`, 2026-10-16, command event 41431 imports the live scripts without installing the test harness and times out at 60000 ms. Event 41451 observes the real installed Cursor binary and session `cursor-promptobus-livemixed-c96-3b471b01db-1-f26c93`; event 41578 reads its real-binary session record with `lastTurnAt: null`. That field does not prove zero model spend. Event 41737 reports targeted session/record/sandbox cleanup, exit 0. The final provider error at 41738 is OpenCode `provider.quota`; causation between the unintended Cursor launch and OpenCode quota exhaustion is not claimed. Original events and a binary patch of the interrupted work are preserved by the run owner.

## Work to do

- Review how contributors and agents validate executable scripts without running their top-level live actions; document syntax-only checks and approved stub entry points.
- Decide whether explicit live opt-in or an entry-point guard is warranted. Preserve deliberate CLI execution and existing supported public behavior.
- Make the test path prove it selects isolated stub binaries and state homes before launching any scenario. Treat missing isolation as a refusal, without silently selecting installed real binaries.

## Out of scope

- Resuming the interrupted implementation or treating this incident as live workflow acceptance.
- Expanding model/provider authority, changing subscription limits, or claiming measured zero spend.

## Verification

- A no-model fixture reproduces accidental module loading and detects any attempted real-binary launch without contacting a provider.
- The chosen guard or workflow prevents that launch; the deliberate documented live route remains available only under its explicit authorization.
- Interrupted fixture cleanup preserves unrelated sessions and records.
