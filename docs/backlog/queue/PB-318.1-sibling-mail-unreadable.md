# PB-318.1 · Sibling mail to a teamlead lands in a root slot its Claude Code tools cannot read

- **Order:** 140
- **Scope:** [04. Protocol](../../reference/04-protocol.md#addresses)
- **Created:** 2026-10-04
- **Dependencies:** PB-331
- **Cost:** major

## Context

Finding discovered while working on PB-318. PB-318 routes root-orchestrator mail to `teamlead:<slug>` into the child task's `orchestrator` mailbox and leaves sibling traffic out of scope. A sibling's `question`, `answer`, `status` or `artifact` to `teamlead:<slug>` still lands in the root task at `inbox/teamlead-<slug>/`. A Claude Code teamlead's bus entry reads only its child task's `orchestrator` mailbox, so it has the same cost PB-318 removed for root mail: unread mail the teamlead cannot mark, a warden knocking on it, and a Stop guard returning the turn on it. A Codex teamlead reads that slot through its separate root MCP entry.

Evidence: a test stand on the PB-318 branch with a root task and two linked children `a` and `b`. `promptobus send teamlead:a --task <root> --type question` from the `teamlead:b` session exited 0 with `sent question → teamlead:a · from teamlead:b · task <root>`. The `teamlead:a` session's `promptobus_mailbox {}` answered `empty · … task=<child a> … address=orchestrator`; `promptobus_mailbox {task: <root>}` answered `FOREIGN MAILBOX: the orchestrator address of task <root> is bound to session root-session, this one is lead-a`. After both reads `countInbox(<root>, teamlead:a)` was 1.

## Work to do

- Owner decision 2026-10-04: no second forwarding rule. Sibling mail reaches a teamlead through the participant mailbox of PB-331, and this entry closes with it.

## Out of scope

- Root-orchestrator mail, which PB-318 routes.

## Verification

- A sibling message to `teamlead:<slug>` is read and marked by `promptobus_mailbox` in that teamlead's session, and no unread count remains for it in either task.
