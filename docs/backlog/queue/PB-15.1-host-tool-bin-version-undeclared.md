# PB-15.1 · `HostToolBin.version` is read by every driver and declared by none

- **Order:** 270
- **Scope:** [02-host](../../reference/02-host.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

`HostToolBin` (`src/host.ts` lines 67–86) declares `ok`, `bin`, `note`, `warn` and `reason`. It does not declare `version`. Every driver reads one anyway:

- `lib/driver-claude.js` `optionRefusal` — `tool?.version` against `ULTRACODE_MIN_VERSION`;
- `lib/driver-cursor.js` — `tool?.version` against `PROVEN_CURSOR_VERSION`;
- `lib/driver-codex.js` — `tool?.version` against `PROVEN_CODEX_VERSION`;
- `lib/model-routing/adapter-claude.js` (PB-15) — reports it as the verdict's `version`, the field the availability snapshot and `promptobus models` show a person.

`createStandaloneHost` returns `{ ok: true, bin: name }` (`src/standalone.ts` line 262), so under the standalone host none of those branches ever fires: the `ultracode` refusal never refuses, the two proven-version warnings never warn, and the availability verdict carries no version at all. Nothing says so — the branches are written as "version unread, we do not refuse", which reads as a rare case and is in fact the standalone default.

This is the class `src/host.ts` already names in the `bin` doc comment: the extract shipped a host returning `path` where consumers read `bin`, and `lib/**` is JavaScript, so the drift lived until the first live run. `version` is the same shape of drift, one field over, and it is load-bearing for a person's diagnosis rather than for a launch — which is why it survived.

## Work to do

- Declare `version?: string` on `HostToolBin` with the doc comment saying what it holds (the binary's own version string, as the host read it) and that it is optional: a host that does not probe versions returns none, and a consumer must treat its absence as "unread", never as "old".
- Decide and write down what `createStandaloneHost` does — probe `--version` itself, or keep returning none deliberately, with the consequence named.
- If it keeps returning none: say so in [02-host](../../reference/02-host.md) beside `resolveToolBin`, so a reader of the driver's "version unread — we do not refuse" comments knows which hosts that is.

## Out of scope

- Changing any of the version comparisons themselves; they are correct on a host that answers.
- The availability adapters, which report whatever the host gives them.

## Verification

- `grep -n "tool?.version" lib/driver-*.js lib/model-routing/adapter-*.js` — every reader is covered by the declaration.
- A host implementation that returns a version type-checks; one that returns `version: 2` does not.
