# PB-373.13 · Preserve observed command termination across BB Stop signals

- **Order:** 520
- **Scope:** [BB command grant delivery](../../reference/02-host.md#bb-command-grant-delivery)
- **Created:** 2026-10-23
- **Dependencies:** none
- **Cost:** major
- **Parent:** PB-373.2

## Context

The direct recorder has no signal forwarding while its child runs. A Stop signal can terminate the recorder before it retains the child's outcome. A signalled child also leaves incomplete evidence that the current command accounting cannot distinguish from an unknown call.
Evidence: `lib/bb-direct-command.ts` waits for child close without installing signal handlers; `integrations/bb/control.ts` requires `complete === true` for terminal accounting. The historical interrupted call with empty streams remains unresolved; its exact failure mechanism is not established by these source observations.

## Work to do

- Forward catchable Stop signals to the exact owned child and retain the recorder through child close, stream finalization and receipt publication.
- Distinguish observed termination from complete gate evidence, including a child that handles a signal and exits zero.
- Allow checked resource accounting to consume only exact verified termination receipts; retain unknown calls and failed finalization.
- Publish an exact-receipt finalization acknowledgment only after the callback returns; a callback lock-release failure must retain the resource even if it already wrote a terminal call record.

## Out of scope

- Historical call reconstruction, global process attribution, permission changes, full BB task close and live matrix acceptance.

## Verification

- Real child-process regressions for catchable signals, nested recorders, repeated signals and cooperative exit zero; no passing evidence from interruption.

- Fault injection after terminal publication and before lock release leaves no acknowledgment. Receipt/ack write, close and pre-rename failures retain interruption and blockers; exact post-rename readback preserves the explicit commit outcome and warning.
