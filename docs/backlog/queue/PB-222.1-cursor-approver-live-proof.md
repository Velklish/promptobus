# PB-222.1 · Prove Cursor approver launch layer in a live worktree

- **Order:** 330
- **Scope:** [05-drivers § Approver worktree, project layer and publication](../../reference/05-drivers.md#approver-worktree-project-layer-and-publication)
- **Created:** 2026-09-26
- **Dependencies:** none
- **Cost:** major

## Context

PB-222 moves the approver session into its own worktree, so the Cursor driver
can place `.cursor/` launch files in the selected working project without
touching the clone root. The project-file plan in `lib/driver-cursor.js` now
names that worktree. `lib/drivers.js` still refuses Cursor approver lift because
the transport of its MCP configuration, write denies and hooks has no live
proof for this role. The changed layout removes the old placement blocker; it
does not prove the layer executes.

## Work to do

- Lift a Cursor approver in a throwaway clone and task from this tree's CLI.
- Show a hook event from a file naming `--role approver:…`; separately show the
  MCP bus and write deny behavior in the live session.
- Compare the clone root before and after: tracked tree clean and untracked
  project content byte-identical. Test a pre-existing project file in the
  approver worktree and refuse overwrite.
- Only after the proof, enable `approverLift` and catalog tuples whose assessed
  base row meets the approver floor; update routing docs.

## Out of scope

- Codex and Claude Code approver lifts; PB-222 covers those.

## Verification

- A live holder or hook journal records the approver-addressed event, and a
  bus call plus write-deny attempt demonstrates the other two layer parts.
- The throwaway clone's tracked and untracked content matches before and after.
- A refusal leaves existing worktree project content intact.
