# PB-215 · Выборка строки участника в тестах падает fail-open: промах отдаёт весь вывод, и проверка зеленеет, ничего не выбрав

- **Order:** 30
- **Scope:** `test/promptobus-driver-codex.test.mjs` (1703, 1735), `test/promptobus-driver-cursor.test.mjs` (1059, 1264, 1295, 1337)
- **Created:** 2026-09-13
- **Dependencies:** PB-159.1

## Context

Проверки статуса устроены так: из вывода `promptobus status` берётся строка нужного участника, и по ней гоняются регулярки. Строка берётся так:

```js
const idleLine = idleStatus.out.split('\n').find((l) => l.includes(WORKER)) ?? idleStatus.out;
```

Хвост `?? …out` — это fail-open. Промах выборки не краснеет: вместо строки участника в проверку уезжает **весь вывод**, где искомая подстрока найдётся у кого угодно. Проверка проходит, не выбрав ничего.

Дефект доказан мутационной пробой на дереве `8452e1c` — обе выборки в codex-файле обезврежены разом, файл остался зелёным:

```
npm run probe -- test/promptobus-driver-codex.test.mjs \
  --mutate 's@\(l\) => l\.includes\(WORKER\)@(l) => false@g' \
  --run 'node test/promptobus-driver-codex.test.mjs'
mutated → exit 0          ← «passed WITH the mutation in place»
```

У отрицательных регулярок направление обратное и тоже неверное: `!/STALLED/.test(idleLine)` по всему выводу покраснеет, если STALLED окажется у любого соседа. То есть промах выборки даёт либо ложную зелень, либо ложную красноту — но в обоих случаях не о предмете.

Выборок строки в `test/` тридцать девять, и делятся они на три группы, а не на две:

- **шесть** роняют выбранную строку в **утверждение** при fallback на весь вывод — это предмет карточки, перечислены в Scope;
- **двенадцать** при том же fallback уезжают третьим аргументом `check`, то есть в улику: вердикт от них не зависит, и чинить там нечего;
- **семнадцать** уже fail-closed — `?? ''` или `?? null`, — и промах у них краснеет сам; неважно, утверждение это или улика. Например `test/promptobus-dismiss.test.mjs:190` строит утверждение по выбранной строке и безопасен именно fallback'ом, а не тем, что строка «всего лишь улика».

Ещё четыре совпадения к этому виду не относятся вовсе: `find((l) => l.id === …)` в `model-routing-command.test.mjs:215` и `model-routing-calibrate.test.mjs:437,603,649` ищут объект overlay, а не строку вывода.

Вне `test/` приёма нет: два совпадения в `lib/models.js` (`:597`, `:653`) — тот же поиск слоя по `id`.

Отдельно от fallback стоит вопрос выборки подстрокой: адрес соседа может содержать адрес предмета. Единственная такая пара сегодня — `worker:cdx` и `worker:cdx-second`, и она починена в PB-159.1 выборкой по полному адресу. Остальные адреса в этих файлах не сталкиваются, но инвариант «порядок журнала = порядок подъёма, предмет печатается раньше» нигде не объявлен, а PB-159.1 показала, как сломать его одной строкой: `upsertParticipant` переносит запись в хвост.

## Work to do

- Шесть мест из Scope: выборка по полному адресу — сравнением начала строки с адресом и разделителем `·`, как сделано в PB-159.1, — и fallback `?? ''`, чтобы промах краснел. Улику при промахе подавать отдельно — пустая строка в третьем аргументе `check` бесполезна.
- Решить, нужен ли общий помощник в `test/` вместо шести одинаковых выражений. Помощник соблазнителен, но прячет, что именно проверяется; решение — за исполнителем, с причиной в результате.
