# PB-15.6 · markExhausted derives the reason from resetAt alone, so a subscription limit with an unparsed reset cannot be written through it

- **Order:** 320
- **Scope:** `lib/model-routing/cache.js`, [03-cli](../../reference/03-cli.md) § Availability
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

Reported by the Claude adapter track on 2026-09-05. `markExhausted(host, harness, { resetAt })` chooses `subscription_exhausted` when `resetAt` is given and `manual_exhaustion` otherwise. A late-start refusal that names a reset the adapter refuses to parse ("resets at 3pm") is a subscription limit with `resetAt: null`, which the helper cannot express; the Claude driver therefore writes the entry through `writeEntries` directly. Two doors into the cache for one fact.

## Work to do

- Give `markExhausted` a `reason` argument (`subscription_exhausted` | `manual_exhaustion`, default derived as today) and route the Claude driver's mark through it; say in the reference which reason a late-start mark carries and why it is sticky either way.

## Out of scope

- Parsing reset times out of a harness's prose.

## Verification

- The Claude adapter's exhaustion checks unchanged and green after the switch; probe: drop the argument → the `subscription_exhausted` check goes red.
