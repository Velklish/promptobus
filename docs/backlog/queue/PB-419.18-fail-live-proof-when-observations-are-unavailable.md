## Context

Evidence: `scripts/live-codex.mjs:96-99` and `scripts/live-mixed.mjs:135-138` return the parsed `pgrep` stdout without checking spawn error or exit status. Their before/after comparisons can therefore report no new process when observation failed. An audit probe of the extracted functions with injected `spawnSync` returned empty arrays for exit 2, ENOENT and normal no-match exit 1, in both scripts (6 cases, probe exit 0). This is a function-level injection, not live cleanup proof. Separately, `scripts/codex-config.mjs:19-24` maps every read error to null and both scripts compare the two snapshots: two read failures can look like unchanged configuration. That second path was established by source inspection, not a functional probe.

## Work to do

Make both process snapshots distinguish normal `pgrep` no-match exit 1 from spawn errors, signals and other failing exits. Treat failed observation at either snapshot as unknown or failure, never PASS. Distinguish missing configuration (`ENOENT`) from other read failures at both snapshots. Preserve foreign-process baseline subtraction.

## Acceptance criteria

- Stubbed no-match is accepted, while spawn error and failing exit at either snapshot cannot produce PASS; an actual newly observed process fails the comparison and existing foreign processes retain their baseline behavior.
- Missing config remains an allowed state; read errors at either point cannot prove unchanged config.

## Verification

After implementation, add targeted stub regressions and run `npm run build` followed by `npm test` from the repository root; **notRun**.

## Dependencies and limits

None. The audit did not run a live workflow, read real personal configuration or establish actual cleanup failure. Live proof needs its own authorization.

A failed snapshot cannot yield PASS. Do this before relying on those scripts for future live proof; no live workflow or owner config access is authorized here.
