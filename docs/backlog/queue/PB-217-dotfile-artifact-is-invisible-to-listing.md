# PB-217 · Артефакт с точки в начале имени невидим тому, кто читает каталог

- **Order:** 50
- **Область:** `placeFile` и `numberedName` в `lib/store.js` — имя, под которым файл ложится в каталог артефактов задачи; [protocol Artifacts](../../reference/04-protocol.md#artifacts)
- **Создана:** 2026-09-13
- **Зависимости:** нет

## Контекст

Имя приземлившегося артефакта берётся из базового имени присланного пути. Ведущая точка при этом не трогается, и файл становится скрытым: обычное перечисление каталога его не показывает, glob `*.json` его не берёт.

Замерено живьём 2026-09-13. Участник прислал запись гейтов под именем `.gates-artifact-pb2042-r2.json`. Проверка на диске:

```
ls <каталог артефактов> | grep -c gates-artifact-pb2042-r2   → 0
ls -a <каталог артефактов> | grep gates-artifact-pb2042-r2   → .gates-artifact-pb2042-r2.json
```

**Цена не гипотетическая.** Ревьюер, которому этот же каталог отдан как источник улик, перечислил артефакты, файла не увидел и записал в формальный вердикт: «of the four cases, this is no record at all — none of the ten attached records carries tree …». Запись существовала, дерево в ней было верное, обе её части несли нужный коммит. То есть вердикт о доказательствах был вынесен по неполному перечню, и неполным его сделало одно имя.

Отдельная ирония: предмет карточки, в ревью которой это случилось, — сделать передачу артефакта **машинно-видимой**. Улика оказалась невидимой ровно в том механизме, который видимость и обеспечивает.

> Источник: 2026-09-13, живой прогон; имя файла и обе команды `ls` выше, вердикт ревьюера в переписке задачи.

## Что сделать

- Решить, что делать с ведущей точкой при укладке файла: снимать её, заменять или отказывать отправителю. Нормализация уместна там же, где уже живёт защита от совпадения имён, — этот путь уже переписывает имя, когда оно занято.
- Сказать выбранное правило в справочнике протокола, рядом с тем, как формируется имя приземлившегося файла.
- Проверить, нет ли соседних имён с тем же свойством: имя из одних точек, имя, совпадающее со служебным файлом каталога.

## Не входит

- Защита от совпадения имён: она верна и не пересматривается.
- Правила чтения на стороне потребителя («перечисляй скрытые файлы тоже»): лечит следствие, а причина в имени. Это не запрещает потребителю быть аккуратным — но карточка не про него.

## Проверки

- Артефакт, присланный под именем с ведущей точкой, виден обычным перечислением каталога.
- Отрицательный контроль: обычное имя не изменилось ни на байт.
- Защита от совпадения имён продолжает работать на нормализованном имени: два файла, отличавшиеся только ведущей точкой, не затирают друг друга.
