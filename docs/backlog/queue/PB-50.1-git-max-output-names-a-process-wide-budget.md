# PB-50.1 · `GIT_MAX_OUTPUT` names a process-wide output budget that was never git-specific

- **Order:** 1050
- **Scope:** `lib/exec.js`, `lib/util.js`, `lib/review.js`, `lib/worktree.js`, `lib/spawn.js`
- **Created:** 2026-09-07
- **Dependencies:** PB-50

## Context

The name has been wider than git for as long as it has existed. Before PB-50 the constant lived in `lib/util.js` and was applied by `runProc` — "single child-process wrapper", not a git wrapper — and by `lib/spawn.js:169` and `lib/worktree.js:42`, of which only the latter two are git calls. PB-50 moved the definition to `lib/exec.js` and gave it to every launch through `run`, so the mismatch grew, but it did not create it. That is why this is a separate entry rather than a widening of PB-50, whose triage note excludes optional cleanup.

The author's own new comment states the wider scope directly (`lib/exec.js:8-10`): "Kept here because every launch through `run` gets it, **not only the git callers**." The name immediately above it still says git.

The move also dropped a sentence that carried the number's justification. The former `util.js` comment explained what an overflow costs: a dirty clone reads as "clean tree" or "state unknown", "and the latter decides whether to clean a worker directory". The relocated comment keeps the size and loses the consequence, so the next reader sees 32 MiB with no reason attached.

Five files reference the name today: `lib/util.js` (re-export), `lib/review.js:4,1115`, `lib/worktree.js:6,42`, `lib/spawn.js:6,169`, plus an unrelated local constant of the same name in `src/standalone.ts:32` that is not imported from anywhere.

## Work to do

- Rename the constant to `PROC_MAX_OUTPUT` at its definition in `lib/exec.js`.
- Keep `export { PROC_MAX_OUTPUT as GIT_MAX_OUTPUT }` in `lib/util.js`, or update the four importing sites — whichever leaves fewer aliases; the decision belongs to whoever takes this.
- Restore the dropped consequence sentence next to the number, so the 32 MiB keeps its justification.

## Out of scope

- `src/standalone.ts:32` — a private constant of the same name in a file that deliberately shares nothing with `lib/`; renaming it is a different question.
- The value itself, and the timeout constant beside it.

## Verification

- `grep -rn 'GIT_MAX_OUTPUT' lib/ src/` returns only the compatibility alias, if one is kept, and the unrelated `standalone.ts` constant.
- The comment next to the number states both the scope (every `run` launch) and the cost of an overflow.
- `npm test` stays green.
