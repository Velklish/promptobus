# PB-34.1 · The Claude inventory is narrower than the binary's baked table — `claude-mythos-5-1` and the `haiku` alias are in it and in neither `MODEL_IDS` nor `MODEL_ALIASES`

- **Order:** 60
- **Scope:** `lib/driver-claude.js` (`MODEL_IDS`, `MODEL_ALIASES`, `MODEL_SCOPE_IDS`), `models/catalog.json`, [03-cli](../../reference/03-cli.md)
- **Created:** 2026-09-06
- **Dependencies:** none

## Context

Found while re-proving the driver against `claude` 2.1.263 (PB-34). The binary's baked model
catalog carries two names the driver's dictionary does not, and both were read out of the
binary offline with no paid turn:

- **A `mythos` family, unaliased.** `{id:"claude-mythos-5-1",family:"mythos",display_name:"Mythos 5.1",knowledge_cutoff:"June 2026",provider_ids:{first_party:"claude-mythos-5-1",…},context:{window:1e6,native_1m:true},max_output_tokens:{default:64000,upper:128000},pricing:"tier_10_50_cache_read_0_25"}`, and `claude-mythos-5` beside it. Both are in the binary's own array of ids it accepts, and the alias→id table maps `mythos-5-1` → `claude-mythos-5-1`. But the `aliases:{…}` block holds exactly `opus`, `sonnet`, `haiku` and `fable` — **no `mythos`** — so the only way to reach it is to type the full id. Its `pricing` tier is the same string Fable 5.1 carries, and the binary's own release note names one page for both: `claude-fable-5-mythos-5`.
- **`haiku` is an alias the binary publishes and the driver does not.** `aliases.haiku:{default:"claude-haiku-4-5"}` and `latest_per_family.haiku:"claude-haiku-4-5"`. It is absent from the `--model` help sentence, which is where `MODEL_ALIASES` is read from, so the driver's list is right about what the harness *tells a person to type* and short of what its table can *resolve*.

Neither is a defect in what PB-34 landed: `MODEL_IDS` is the rated half of the inventory,
and a model nobody assessed correctly has no row. What is unsettled is whether the owner's
account can start either one, and therefore whether they are candidate rated rows or noise.
**Unverified: no turn was run on `claude-mythos-5-1`, and nothing here checks entitlement.**
A model the table knows is not a model the plan serves.

## Work to do

- Establish, for `claude-mythos-5-1` and `claude-haiku-4-5`, whether this account can start them: the cheapest check is one `claude -p --model <id> --max-turns 1 'reply with the single word ok'` each, which is also the check PB-29 named for a name the baked table cannot answer for.
- If startable and worth rating, add rows under the ADR-005 rule and put the ids in `MODEL_IDS`; `claude-haiku-4-5` would also make `haiku` an entry of `MODEL_ALIASES` and of `MODEL_SCOPE_IDS` (the harness prints a scoped weekly window per family).
- Say in the reference why `MODEL_ALIASES` is read from the help sentence rather than from the baked `aliases` block, since the two now demonstrably differ.

## Out of scope

- Rating either model before it is shown to start on this account.
- Changing where `MODEL_ALIASES` is read from without a decision recorded for it.
