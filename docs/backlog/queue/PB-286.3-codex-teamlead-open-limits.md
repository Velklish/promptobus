# PB-286.3 · Measure the open limits of the Codex teamlead admission

- **Order:** 560
- **Scope:** [05-drivers](../../reference/05-drivers.md)
- **Created:** 2026-09-27
- **Dependencies:** PB-286.1

- **Cost:** major

## Context

PB-286.1 admitted a Codex teamlead at the install root, and the owner accepted the ADR amendments "Codex at the install root" on the condition that this card measures the three limits the live proof left open. The proof itself (throwaway stands `live.ej1Piv`, `live.Tz69RX`, `live.Ezz5vp`) showed the outcome: no foreign hook marker, install-root bytes and git status unchanged, and workers and reviewers of all three harnesses lifted and reporting under `full-access`.

## Evidence

- Hook isolation was observed only as an outcome. The holder logs of the clean run say the install root was untrusted and project-local hooks were disabled. The absent hook marker therefore does not isolate the effect of the teamlead-only `features.hooks = false` thread override.
- Skill loading was not measured. The proof skill was copied into the teamlead's `CODEX_HOME` but rejected for missing YAML frontmatter.
- The applied sandbox was not recorded. The teamlead requested `full-access`, and its launch plan maps that mode to `danger-full-access`; no live artifact records the mode Codex applied.
- Each statement is made in the ADR amendment text, under "Amendment: Codex at the install root" as merged by PB-286.1.

## Work to do

- On a throwaway stand, with the install root **trusted** and project hooks enabled, show that a Codex teamlead thread with the override runs no project hook, while a control thread without the override does.
- Give the proof skill valid frontmatter, and show that the Codex teamlead loads it from its isolated home: the skill named in the session's own log, or used in a turn.
- Record the sandbox mode Codex applied to the teamlead thread from the session's own configuration or log, not from the launch plan.
- Update the ADR text: each limit becomes a measured fact with its stand, version and date, or stays a limit with the reason it could not be measured.

## Out of scope

- Admitting a Cursor teamlead; profiles narrower than `full-access`; changes to the lift path unless a measurement shows a defect, which is then filed as its own card.

## Verification

- Each of the three measurements has its stand, command, exit code and the log line that proves it, and the control run shows the opposite outcome where one exists.
- The stands are removed afterwards, and every session they started is stopped.
