# PB-373.14 · Queue canonical unread mail while a BB participant is active

- **Order:** 530
- **Scope:** [BB command grant delivery](../../reference/02-host.md#bb-command-grant-delivery)
- **Created:** 2026-10-23
- **Dependencies:** none
- **Cost:** major
- **Parent:** PB-373.2

## Context

Delivery rejects every non-idle participant before reading its canonical pending mailbox. An active worker therefore cannot receive a queued mailbox hint, even though the adapter uses queue-if-active. Existing queued-response fixtures begin idle and do not exercise this trigger.
Evidence: `integrations/bb/delivery.ts` returns on `observation.status !== 'idle'` before the pending operation; the queued wake cases in `integrations/bb/test/engine.test.mjs` do not set the worker active before canonical send.

## Work to do

- Allow a verified active participant without background agents or pending interactions to queue canonical unread mail.
- Keep obligation-only continuations restricted to idle turn boundaries, preserving Stop, epoch, queue ownership and duplicate-send guards.
- Prove active queue reconciliation and reload with an accepted or ambiguous queued reply, without acknowledging canonical mail.

## Out of scope

- New SDK APIs, permission changes, implicit resume, task close, journal maintenance and live matrix acceptance.

## Verification

- Reproduce the active unread-mail omission, then prove one owned queued hint and retained canonical unread IDs across reload and duplicate announcements.
- Cover active acknowledgment, idle-only continuation, unavailable actors, foreign queues, Stop races and active resume refusal.
- Run BB source gates, mutation probes on committed code and independent read-only review. Retain unresolved root gates separately.
