## Evidence

Evidence: `test/fixtures/codex-app-server/0.164.0/ClientRequest.json` declares `ThreadStartParams.config` as `{"additionalProperties": true, "type": ["object", "null"]}` (a node one-liner over the fixture, 2026-10-29). `lib/codex-session.js:917-924` (`threadStartConfig`) puts `bypass_hook_trust`, `features.*` and `model_reasoning_effort` into that object, and `:1630-1632` adds `skills.config`. `test/codex-schema-gate.test.mjs` compares the consumed protocol schemas only, so no check names a config key. Presumably a Codex release that changes the config vocabulary is caught only by a live lift refusing; that is not measured, since no such release has been tried.

The remaining choice, if it is confirmed: check the override's keys against what the binary accepts (an isolated `CODEX_HOME` and `codex mcp list` is a cheap stand), or state in the reference that this class is caught only by a live lift.
