# PB-15.5 · An adapter that waits for the child's close event answers late when a grandchild holds the inherited pipe

- **Order:** 310
- **Scope:** `lib/model-routing/adapter-cursor.js`, `lib/model-routing/adapter-codex.js`, [03-cli](../../reference/03-cli.md) § Availability
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

Measured by the Claude adapter track on 2026-09-05: `close` fires when the last stdio pipe closes, not when the child dies, so a wrapper (`sh -c 'sleep 5'` style) whose grandchild inherits the pipe keeps a probe pending past the kill — a 300 ms deadline gave the right verdict 5.2 s late. The Claude adapter now answers on the deadline and releases the pipe and the child handle (a check with a plain `sh` stub that forks and waits; a node stub does not reproduce it because `stubCommand` writes `exec node …`). Hypothesis until measured: the Cursor adapter (`spawn` + `close`) and the Codex adapter (`kill` in `finally`, waiting on the RPC channel) have the same shape.
