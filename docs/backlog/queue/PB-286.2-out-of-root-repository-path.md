## Context

A worker lift named an existing Git repository by an absolute path outside the install root in the 2026-09-27 proof `live.XtOh7N`. Both Cursor and Claude Code spawns exited 1 with `repo is not cloned — the worker has nowhere to work`. The standalone host accepted the path, then reduced it to its basename; spawn resolved that basename under the install root instead of using the repository it had found.

## Work to do

- Decide whether an out-of-root absolute path is supported. Reject it before resolution with its real location, or carry that location consistently through spawn and review.
- Cover an existing out-of-root clone and an in-root clone with verdicts, then update the standalone-host reference and README.

## Out of scope

- Codex teamlead admission and the live proof layout.

## Verification

- An existing out-of-root Git repository never receives a false `not cloned` diagnosis; the command either uses it consistently or refuses its location explicitly.
- In-root repository lifts and review layout still resolve to the intended clone.
