## Context

Evidence: private workspace consumer smoke on 2026-11-13 (2026-11-12 UTC), Promptobus 0.32.9, consumer Host 0.107.0, Codex 0.167.2, macOS. The retained original command log and output are `/private/tmp/promptobus-smoke-20261113/commands.md`, `service-stop.json`, `service-idle-final.json` and `verified-result.json`. These paths are local evidence pointers, not portable attachments. Original commands use the consumer wrapper; the public package operations below name the equivalent CLI surface, not an additional execution.

A managed Codex root and two Codex teamleads completed two computations and a sibling question/answer exchange. All three normal Stops had matching receipt hashes, `stop/confirmed`, complete terminal command accounting (15/15, 5/5, 3/3) and `app-server/close` code 0. Across all attempts, the eight recorded native actors' holder/app PIDs were absent. The independent verifier exited 0 with 7/7 smoke checks; this did not include service shutdown.

The subsequent public `service stop --json` operation exited 1:

```text
Shared service still has live clients or active work [clients: 0, activeWork: true, pendingObservations: 0, requests: 1]
```

Public `service status --json` then exited 0 with `running:true`, `clients:0`, `sessions:0`, `reservations:0`, `unknownClients:0`, `unknownManaged:0`. Two root-task watcher demands remained. Task metadata was still active after the actors' Stop. The parent controller held neither root mailbox and did not claim it or force termination. The exact reason `activeWork` remains true needs a focused regression; do not infer it solely from the task status.

Unlike PB-416.23, this observation has no retained unknown clients. It concerns the terminal task/warden/service lifecycle after confirmed Stops.

## Work to do

- Reproduce the public managed-root/teamlead Stop sequence with all native terminal proof present, zero clients and active task metadata. Identify the remaining service-work predicate.
- Provide and document a supported way for the legitimate owner to complete the run and release its watcher/service work without borrowing a dead root identity or forcing the service process down.
- Keep live participants, pending calls, unresolved receipts and unknown ownership blocking shutdown. Task inactivity or an absent PID alone must not grant terminal authority.
- Preserve journals, receipts and unrelated tasks, clients and service scopes.

## Acceptance criteria

- The documented finite TDM plus two-teamlead workflow reaches confirmed native Stop and successful public service shutdown without a foreign mailbox claim, a replacement recovery actor or a forced kill.
- A stopped root cannot leave an unresolvable task/watch lifetime that permanently prevents idle exit; the supported closure route and its owner are explicit.
- Negative controls retain the service for live or unresolved work. Unrelated task and client state is unchanged.

## Out of scope

- Changing message-type wake policy, BB plugin compatibility or the missing-record retirement repair in PB-416.23.
- Automatically interpreting every active metadata record as abandoned, weakening ownership checks or deleting historical state.
