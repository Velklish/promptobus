# PB-167.2 · The hand-written backslop list in .gitignore now duplicates the managed backslop:start block

- **Order:** 50
- **Scope:** `.gitignore`
- **Created:** 2026-09-12
- **Dependencies:** none

## Context

Found while raising the pin in PB-167. From v0.5.0 backslop's `init` writes its own `.gitignore` block between `# backslop:start` and `# backslop:end` — one `<harness root>/backslop-*` line per selected adapter plus `/CLAUDE.md`. This repository had written that list by hand before the feature existed, so `init` at v0.6.0 appended a block that says the same thing a second time.

Measured on run 0912a after `npx github:Velklish/backslop#v0.6.0 upgrade` (exit 0): the command reported `.gitignore: appended`, and `git diff --numstat -- .gitignore` counted 7 added lines against 0 removed.

The result is 13 hand-written lines that the managed block now covers, and `/CLAUDE.md` listed twice:

<!-- quote:../../../.gitignore -->
# backslop adapter outputs; harness directories remain available for custom files.
.claude/worktrees/
.claude/skills/backslop-task/
.claude/skills/backslop-batch/
.claude/skills/backslop-seed/
.cursor/rules/backslop-task.mdc
.cursor/rules/backslop-task/
.cursor/rules/backslop-batch.mdc
.cursor/rules/backslop-batch/
.cursor/rules/backslop-seed.mdc
.cursor/rules/backslop-seed/
.agents/skills/backslop-task/
.agents/skills/backslop-batch/
.agents/skills/backslop-seed/
/CLAUDE.md

# backslop:start
.claude/skills/backslop-*
.cursor/rules/backslop-*
.agents/skills/backslop-*
/CLAUDE.md
# backslop:end
<!-- /quote -->

Nothing is broken by this: git ignores an already-ignored path idempotently, and `lint` is green on it. It is dead weight, and dead weight in `.gitignore` is the kind that survives for years because no one dares touch it.

PB-167 left it alone on purpose: the hand-written lines are project content, and that card's scope was the pin.

## Work to do

- Drop the hand-written backslop lines and the comment above them, keeping the managed block as the single source.
- Keep `.claude/worktrees/`. It sits under that comment but is not an adapter output — it is where this repository's worktrees live, and the managed block does not cover it. Move it up to the general section rather than deleting it with its neighbours.

## Out of scope

- The content of the managed block: it is generated by `init` and is rewritten on every run.
