# PB-38.2 · The aggregation covers the current billing cycle only, so a Cursor model the bucket list omits is paced against the api pool until its first turn of the cycle

- **Order:** 10
- **Scope:** `lib/model-routing/adapter-cursor.js`, `schemas/model-routing/snapshot.schema.json` (only if the cache is chosen as the carrier), [03-cli](../../reference/03-cli.md)
- **Created:** 2026-09-06
- **Dependencies:** PB-38

## Context

PB-38 made the adapter read the pool per model from `GetAggregatedUsageEvents.tier` because `autoBucketModels` lags Cursor's own billing. That answer is **scoped to the current billing cycle**: a row exists for a model with an event in it, and for no other. So on the first days of a new cycle a model the bucket list still omits — `cursor-grok-4.6-*` today — has no row, and by the union rule it falls back to the `api` pool until its first turn is billed.

The consequence is small but real and it repeats every cycle: under `balance` those tuples are paced against the fuller pool exactly while the account is at its emptiest, which is when a mis-paced tuple changes the pick. PB-38 chose that on purpose — no row is an absent measurement rather than a statement, and `api` is the conservative reading — so this is a refinement and not a defect of that change. It is also **self-healing**: one turn on the model fixes the cycle.

Evidence: `autoTierModels` in `lib/model-routing/adapter-cursor.js` reads `events.aggregations`, and the aggregation the owner measured on 2026-09-06 carried rows for that cycle only; `test/fixtures/model-routing/cursor-aggregated-usage.json` is that shape.

## Work to do

Pick one of the two candidates, or reject both and record why:

- **Carry the last known tier per model id in the availability cache.** The snapshot already holds a Cursor entry per run, and a `tier` learned in one cycle is a fact about how Cursor bills the model rather than about the cycle. Cost: a new field on a cache the schema pins, so `schemas/model-routing/snapshot.schema.json` changes and the cache gains state that outlives what measured it — a model Cursor reclassifies would keep its old pool until something expired the entry, which needs its own rule (an expiry, or a re-read that overwrites).
- **Ask the previous cycle's aggregation once**, when the current one names no row for a model the bucket list omits. Cost: a second POST in the preflight budget on exactly the runs that are already at their tightest, and a request shape nobody has measured — the method took `{}` and answered the current cycle, and whether it accepts a range is unknown. Measure that first.

A third answer is legitimate: leave it, and say in the reference that the pool of a model with no turn this cycle is the bucket list's answer and nothing more. The cost is then one mis-paced tuple per cycle per model family the list omits.

## Out of scope

- The union rule and the exact-id matching PB-38 fixed — this refines when the tier is KNOWN, not how it is read.
