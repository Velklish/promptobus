# PB-239.2 · Cursor state query runs tmux through PATH: a live session reads stale when tmux is off the caller's PATH

- **Order:** 67
- **Scope:** [05-drivers](../../reference/05-drivers.md), `lib/cursor-persist.js`
- **Created:** 2026-09-24
- **Dependencies:** none
- **Parent:** PB-239
- **Cost:** major

## Context

Finding discovered while working on PB-239, in its sweep of the state queries a participant's environment runs.
PB-239 moved the Claude state query and `claude stop` onto the binary the host names. The Cursor driver's
own agent binary is not affected: `stop` re-resolves the recorded path through PATH and the known install
directories (`liveBin`). Its `tmux` is. Every tmux call goes through the bare name:

<!-- quote:before:../../../lib/cursor-persist.js -->
  return run('tmux', ['-u', '-L', server, '-f', '/dev/null', ...args], {
<!-- /quote -->

and a tmux that cannot be started reads as an empty server:

<!-- quote:before:../../../lib/cursor-persist.js -->
  if (r.error || r.status !== 0) return [];
<!-- /quote -->

So `inspect` finds no pane and answers `stale`, and `liveParticipant` (`src/supervisor.ts`) reads
`stale` as `dead`. That is worse than the Claude case PB-239 fixed: there the state was unknown and
`sweep` refused; here a LIVE session reads dead. Read in the code, not run: `sweep` would then remove
its `workers/` files and, on a proven merge, its tree, and `stop` would say "no live session — nothing
to stop" with exit 0.

Evidence, measured 2026-09-24 on this machine (tmux at `/opt/homebrew/bin/tmux`): a tmux session
`probe-sess` started on a private server through the module's own `tmux()`, a Cursor registry record
naming it, then `cursorDriver.inspect` with two PATHs. With `/opt/homebrew/bin:/usr/bin:/bin` →
`alive`. With `/usr/bin:/bin` → `stale — persist session probe-sess is not on the tmux server … it was
stopped from outside or the machine rebooted`, and `findSession` → `null`, while the session ran.

The lift checks tmux differently: `resolveTmux` searches PATH and the Cursor install directories.
Assumption, not measured: the approver's environment usually has tmux on PATH (`/opt/homebrew/bin`
is on the PATH of a lifted Claude session here, and `/usr/bin` on Linux), so the fault needs tmux in a
directory only a terminal's PATH carries.

## Work to do

- Resolve tmux for every call the way the lift's check does, without handing the tmux server a
  changed PATH (the server's environment reaches the pane).
- Tell "tmux could not be started" from "the server has no sessions": the first is an unread state
  (`null` or a named refusal from `inspect`), never `stale`.

## Out of scope

- The Claude driver (PB-239) and the Codex driver, whose `inspect` and `stop` run no binary.

## Verification

- With tmux absent from PATH and present in an install directory, `inspect` of a live Cursor session
  answers `alive`; with tmux absent everywhere, it answers unknown with a reason naming tmux, and
  `sweep` and `stop` refuse instead of treating the session as dead.
