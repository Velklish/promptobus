# PB-416.5 · Verify shared-service workflows recovery and process footprint

- **Order:** 400
- **Scope:** [Workflows](../../reference/03-cli.md), [Drivers](../../reference/05-drivers.md), [Delivery](../../guides/hooks-and-trust.md)
- **Created:** 2026-10-30
- **Dependencies:** PB-416.4
- **Cost:** major

## Context

Final acceptance stage for the shared physical process, after its protocol, warden and launcher/config stages. Configuration syntax and unit fixtures alone do not establish ordinary native workflows or the physical process count.

Evidence: the original mechanism launches stdio MCP per client and warden per task. The approved target shares one physical owner per canonical workspace/store, with separate logical tools and provider harness processes. Measurements must compare the same workload rather than attributing TypeScript erasure to a memory saving.

## Work to do

- Exercise ordinary public workflows for available supported harness/role profiles using subscriptions without PAYG, with task/session/launch ownership and reviewer boundaries intact. Start with small ordinary workflows before broader failure matrices.
- Verify concurrent cold starts, crash/reconnect/journal recovery, startup reservation, idle live clients, separate tasks, rights and cleanup. Distinguish native Stop, process disappearance and forced teardown.
- Measure owned process counts, RSS and command/message latency on identical baseline/new scenarios; record source/runtime identities, workload and cleanup. Do not count unavailable live profiles as passed.
- Complete the consumer handover with the final checked artifact, exact launcher/HTTP contract, stable exports/runtime paths and unresolved limitations. Consumer repin/manifest belongs to its owner; release publication remains separate.

## Out of scope

- New product features, unsupported-profile claims, account/PAYG changes and release publication.

## Verification

- Record exact commands, exit codes, numerical gates/check counts, source identities and measured units. The agreed scope has one MCP/warden service owner, with no owned fixture descendants left behind after cleanup.
- Required gates and independent fresh-context review have zero critical/major findings; remaining minor findings are registered with evidence. Retained unknowns and any workaround are explicit in acceptance and handover.
