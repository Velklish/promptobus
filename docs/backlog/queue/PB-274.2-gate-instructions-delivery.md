# PB-274.2 · Deliver declared gate instructions to its lift

- **Order:** 370
- **Scope:** [02-host § The pipeline declaration](../../reference/02-host.md#the-pipeline-declaration), `src/pipeline.ts`, `src/host.ts`, `lib/review.js`, `lib/approver.js`
- **Created:** 2026-09-27
- **Dependencies:** PB-274
- **Cost:** major

## Context

The pipeline declaration accepts a gate's `instructions` file, but a named gate lift never reads
or delivers it. `src/pipeline.ts` retains the file in the loaded model and strips it from the
`pipelineSteps()` value handed to the host. The lift receives only the step name; neither review
nor approver prompt uses the declared file. The host reference describes the file as text for
that step's lift prompt. A `security` gate declared with `docs/security-review.md` therefore starts
without those review criteria. Evidence: `src/pipeline.ts` (`pipelineSteps()`),
`docs/reference/02-host.md` (§ The pipeline declaration), `lib/review.js` (`step()`, `buildPrompt()`),
and `lib/approver.js` (`buildApproverPrompt()`).

## Work to do

- Carry the selected instruction file through the host and lift contract.
- Include its content in the initial assignment and in repeat assignments for both gate kinds.
- Refuse a file that cannot be read at lift time with a named path and no partial lift.

## Out of scope

- Changes to gate order, owner addressing, cwd or rights.

## Verification

- A `reads-diff` gate and a `writes-main-tree` gate each receive a unique instruction marker
  on their initial lift and on a repeat lift.
- A declared gate with no instructions retains its current prompt.
