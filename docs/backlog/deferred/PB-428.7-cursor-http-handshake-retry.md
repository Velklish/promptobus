- **Scope:** [Suite isolation](../../guides/contributing.md#suite-isolation)
- **Created:** 2026-11-09
- **Dependencies:** none
- **Cost:** major

## Context

The Cursor fixture treats every HTTP refusal as terminal, including a managed
record revision change after authorization returns. A failed initial handshake
ends the synthetic native turn, so launch and wake assertions fail afterwards.

Evidence: on source `8a1b1543dad03df3b5ef171b9cdc6582bf45390f`,
[main CI](https://github.com/Velklish/promptobus/actions/runs/42652903705)
failed `promptobus-driver-cursor.test.mjs` at 166 of 186 checks with
`Cursor fixture HTTP MCP initialize: 409` and `returned fence: authenticate`.
[Tag CI](https://github.com/Velklish/promptobus/actions/runs/42652903902)
passed that file but failed `promptobus-cursor-wake.test.mjs` after
`notifications/initialized: 409` and `returned fence: body`.

A controlled same-identity revision change with the actual production
authorization block and unmodified exported fixture client reproduced both
errors. The focused fixture regression then failed 6 of 32 tests before the
repair (`node test/cursor-http-handshake.test.mjs`, exit 1). Isolated native
HEAD runs twice and base source `2f9435a3a1f1a70cf11345642fbee488251aaf4c`
all passed the driver file (186 of 186) and wake file (21 of 21); those macOS
passes do not establish the exact Linux publication interleaving.
