# PB-406.7 · Activate routing pool deny and live caps after the installed runtime catches up

- **Scope:** [03. CLI § Model routing](../../reference/03-cli.md#model-routing)
- **Created:** 2026-10-28
- **Dependencies:** PB-406.2, PB-406.6
- **Cost:** major

## Context

The owner wants this workspace's routing policy to keep Cursor models charged to the `api` pool out of automatic selection and to cap simultaneous participants by harness. Source changes alone cannot activate those settings in a running workspace: the installed Promptobus package may lag the source clone.

Evidence from the installed 0.30.0 runtime on 2026-10-28: `promptobus models validate` on an isolated candidate overlay containing `deny.pools: ["cursor:api"]` exited 1 with `overlay-invalid · workspace · deny: unknown selector pools`. The same command on a candidate containing `caps.liveParticipants` Codex 6, Cursor 8 and OpenCode 1 exited 0, but PB-406.3's four isolated reviews found that the installed cap admission can be exceeded under concurrent lifts. The running workspace overlay was left unchanged. PB-406.2 provides the source pool-deny contract; PB-406.6 will provide the separate safe live-cap lifecycle.

## Work to do

- Once the workspace-installed Promptobus includes the accepted PB-406.2 pool-deny contract and the accepted PB-406.6 live-cap lifecycle, add `deny.pools: ["cursor:api"]` and `caps.liveParticipants` with Codex 6, Cursor 8 and OpenCode 1 to this workspace's writable overlay. Leave Claude uncapped and all optional account capacity numbers unset.
- Validate candidate content before replacing the live overlay. Run `promptobus models validate` after the write and inspect `models` output for the effective deny and caps. Preserve the existing overlay policy entries.

## Out of scope

- Updating the source catalog or resolver again; this is activation of accepted behavior in the installed runtime.

## Verification

- The installed runtime includes the accepted versions of PB-406.2 and PB-406.6; a candidate overlay with both keys passes `promptobus models validate` (exit 0), and the live overlay remains valid after the atomic write.
- Automatic routing excludes a known Cursor `api` pool tuple while a known `auto` pool tuple remains eligible; a seventh Codex, ninth Cursor or second OpenCode live participant of one task is refused with the cap and overlay path. An explicit named Cursor `api` model follows the documented warning/waiver behavior.

## Deferred

- **Deferred:** 2026-10-28
- **Reason:** Installed 0.30.0 rejects `deny.pools`, and its accepted cap key does not yet guarantee a hard ceiling under concurrent lifts. Activating either as if it were reliable would misstate the live policy.
- **Return condition:** Install a Promptobus runtime that contains accepted PB-406.2 and PB-406.6, then validate and apply the two overlay keys together; perform this in a separate run.
