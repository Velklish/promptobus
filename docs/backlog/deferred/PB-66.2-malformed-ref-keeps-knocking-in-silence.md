## Context

Finding of the PB-66.1 review (isolated reviewer, run `pb-run-0910-t20260910-085454`), from the source. PB-66.1 makes a filesystem refusal on a mailbox ref visible: the postcard and the participant's status line name the errno and the ref while the retry stays unbounded. The other cause of the same symptom is untouched: a ref whose record does not parse is skipped by `glanceInbox` in silence (`src/v1/messages.ts`, the `JSON.parse` catch), `countInbox` still counts its name, so `unread` stays at one or more, and the warden knocks every `KNOCK_RETRY_SEC` with an empty preview — exactly the picture PB-66.1 was opened for, now for a malformed record instead of a refused one. The consuming `readInbox` sets such a record aside in `broken/<participant>` when the participant actually reads, so the loop ends the moment the session fetches its mailbox; until then the postcard says nothing. The silence is pinned by `test/promptobus-warden.test.mjs:508` ("glanceInbox returns the intact messages and stays quiet about the broken one"), so a change here changes a pinned contract on purpose.
