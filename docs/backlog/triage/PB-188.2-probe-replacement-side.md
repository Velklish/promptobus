# PB-188.2 · `--mutate` warns about the pattern and says nothing about the replacement, where three probes died

- **Scope:** `scripts/mutation-probe.mjs`, [contributing](../../guides/contributing.md) § the probe
- **Created:** 2026-09-16
- **Dependencies:** found while probing `PB-188`; the probes themselves are done

## Context

`--mutate` takes `s/<js-regexp>/<replacement>/`, and both halves are JavaScript rather than
`sed`. The tool says so about the first half and nothing about the second:

<!-- quote:../../../scripts/mutation-probe.mjs -->
    die(`--mutate: ${e.message} — the pattern is a JavaScript regexp, so ( ) | { } are operators; escape them or use --stdin-patch`);
<!-- /quote -->

The replacement reaches the file through `String.replace`:

<!-- quote:../../../scripts/mutation-probe.mjs -->
  writeFileSync(abs, before.replace(pattern, repl));
<!-- /quote -->

Three consequences, each demonstrated rather than inferred:

- **`\n` is literal.** `'a; b'.replace(/; /, ';\n  ')` yields `a;\n  b` with a backslash and an
  `n` in the file, not a line break. A multi-line mutation through `--mutate` is impossible by
  construction, and `--stdin-patch` is the only form that can make one.
- **`$` is an operator.** `'x + y'.replace(/\+/, '$&$&')` yields `x ++ y`: `$&`, `$1`, `` $` ``
  and `$'` substitute instead of being written.
- **The shell adds a layer of its own.** A `&` escaped for the shell as `\&` arrives in the
  file as `\&`, because nothing downstream of the shell unescapes it.

## Why it is worth a card rather than a note

The failure disguises itself as a result. A replacement that arrives mangled leaves the file
unparseable, the mutated run dies during module load, and `node --test` reports `tests 2,
fail 2` — two FILES that never loaded, which reads at a glance like two failed verdicts. The
probe's own contract calls a run that stopped early "not a probe", but the number it prints is
the shape of a probe that worked.

Measured on the `PB-188` pass: **three** probes were discarded to this cause — once from `\&` in
the replacement, twice from `\n` in it. The tool exited 0 on one of them, because from its side
the mutation applied and the run went red.

The SYMPTOM is wider than the cause and must not be counted into it. A fourth probe on the same
pass died with the same `tests N, fail N` reading from an ordinary mistake — a mutation naming an
identifier that does not exist — which this card would not have prevented. What the two share is
that a file which fails to LOAD is reported per file, so an interrupted run and a red one look
alike. That is worth its own line in `contributing`, and it is not evidence for this defect.

## Work to do

- Warn symmetrically in `scripts/mutation-probe.mjs`: the replacement is a `String.replace`
  replacement, so `\n` is literal and `$` is an operator. Refusing a replacement that contains
  `\n` outright is the stronger option — there is no lawful use of it — and it points at
  `--stdin-patch`, which is the form that does what the author meant.
- Say the same in one sentence in [contributing](../../guides/contributing.md) § the probe,
  beside the four outcomes it already names.
- Say that the `s/…/…/` separator is arbitrary — `s|…|…|` works where the pattern carries a `/`
  from a path — and that the tool's error names only the pattern half, never the separator.

## Out of scope

- The four outcomes and the snapshot restore, which behaved exactly as documented throughout.
- `PB-188` itself: its probes are re-done and recorded.

## Verification

- A `--mutate` whose replacement contains `\n` is refused by name, and the message names
  `--stdin-patch`.
- The refusal is distinguishable from a red run: it does not leave a file that fails to load.
