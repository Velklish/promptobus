# PB-419.22 · Align BB role mailbox examples with facade schema

- **Scope:** [Drivers reference](../../reference/05-drivers.md)
- **Created:** 2026-11-05
- **Dependencies:** none
- **Cost:** major

## Context

Evidence: the worker, reviewer and approver instructions under `integrations/bb/skills/` show `promptobus_send` with a string recipient, whereas `integrations/bb/protocol.ts:109-113` requires an array. Worker and reviewer instructions also describe fetching body by ID, but the facade mailbox returns bodies with read or peek and exposes no separate body-by-ID operation. The native renderer's communication instructions are reused in the BB renderer. Literal examples are rejected by the BB schema.

## Work to do

Adapt the BB renderer and regenerate the affected skills: use an array recipient, describe read/peek and returned bodies accurately, and preserve the separate native API contract.

## Acceptance criteria

- Examples for each affected role pass the actual BB schema; no instruction requires a nonexistent BB body-by-ID operation.
- Native renderer behavior remains correct.

## Verification

After implementation run `npm run build`, `npm --prefix integrations/bb test` and `npm test` from the repository root; **notRun**.

## Dependencies and limits

None. This corrects the documented facade calls and does not expand routing permissions.
