# PB-415.9 · Align the public BB beforeSpawn child type with ignored standard input

- **Scope:** [BB Host context delivery](../../reference/02-host.md#bb-host-context-delivery)
- **Created:** 2026-10-30
- **Dependencies:** none
- **Cost:** major
- **Parent:** PB-415.5

## Context

The existing public BB direct-command declaration promises that beforeSpawn receives a start function returning ChildProcessWithoutNullStreams. The implementation starts the child with ignored standard input; stdin is null. A consumer accepted by the declaration can therefore dereference a stream that is absent at runtime. The callback return value is also ignored by the implementation.

Evidence: the handwritten lib/bb-host.d.ts at daa801ac064e581a1e6636b0362a13b2e55fdbba declares ChildProcessWithoutNullStreams for both callback positions. At that same revision lib/bb-direct-command.ts starts with stdio: ['ignore', 'pipe', 'pipe'] and invokes beforeSpawn(start) without consuming its return value. Stage 5 preserves that public declaration through a local compatibility boundary; its implementation type retains the nullable stdin. Independent read-only entry-point review confirmed the mismatch predates this migration. This is static source evidence; no runtime child-stream reproduction was run for this finding.

## Work to do

- Correct the public callback declaration at an explicitly selected public-contract boundary, keeping the current ignored-input runtime behavior and documenting that the callback return value is unused.
- Add an isolated direct-command runtime fixture and a TypeScript consumer fixture requiring a null check before using stdin. Remove the legacy compatibility boundary with the consumer handover.

## Out of scope

- Changing process streams, command ownership, physical closure semantics or the shared-service architecture.

## Verification

- Reproduce the null standard-input value through the public entry point without an external model call. Record the exact source identity and command separately from the static evidence above.
- The declaration rejects an unchecked stdin dereference and accepts valid beforeSpawn callbacks. Existing runtime results, callback identity, command bytes and Promise identity remain unchanged.
- Required repository gates and independent review pass, with the public type change stated in the consumer handover.
