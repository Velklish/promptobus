# PB-373.4 · BB reviewer instructions exceed the enforced send body limit

- **Scope:** [BB host boundary](../../reference/02-host.md), bb-plugin-promptobus reviewer instructions and protocol
- **Created:** 2026-10-16
- **Dependencies:** none
- **Cost:** major

## Context

Finding discovered during PB-373 provider workflow validation. The BB reviewer role allows unbounded findings in the same result body, while its only authenticated send route rejects bodies longer than 2400 characters. The reviewer is read-only and cannot write an overflow artifact. Following the role instruction can therefore prevent delivery of the complete review.

Evidence: bb-plugin-promptobus/skills/promptobus-reviewer/SKILL.md:52 says the header is at most 2400 characters, findings follow in the same body and are not bounded. bb-plugin-promptobus/protocol.ts:78 defines body as z.string().min(1).max(2400). The plugin README:193 also states the cap. In thread thr_rs5bc9mbi2, the failed send argument at seq352/353 contains a 7303-byte report; the exact original unsent text is retained as artifact 20261016T091151790-1276-741a42 with SHA256 9680d6aeba62e8a3c959741e99988ce324d7a1d0f1ccb76d1d36ac5ddbea3506. It was preserved by the orchestrator, not submitted successfully by the reviewer. The subsequent provider HTTP 403 is separate evidence, not a demonstrated consequence of the body cap.

## Work to do

- Align the BB-specific reviewer instructions with the actual public send contract.
- Provide a supported bounded report path that preserves every finding, attribution and final all-calls release without requiring reviewer writes or a fabricated artifact tool.
- Keep any multipart ordering and completeness rule explicit and small; do not add a generic transport framework.

## Out of scope

Dropping findings, silently truncating the report, broadening reviewer filesystem/network permissions, relaxing source/evidence admission, or treating an owner-extracted draft as the reviewer's delivered result.

## Verification

- Add a regression check that fails on the old instruction: the selected BB role must not promise an unbounded single body when the admitted send tool caps it.
- A constrained reviewer can deliver a report larger than one body with every finding and a single terminal release preserved through a supported public route.
- Reject incomplete, duplicated or reordered reports as appropriate to the chosen contract. Next step: reconcile the BB role and send contract before another long review workflow.
