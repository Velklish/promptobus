# PB-14.1 · The § Model routing preamble still says "Not implemented yet" while parts of it now are

- **Scope:** [03-cli](../../reference/03-cli.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

`docs/reference/03-cli.md`, first line under `## Model routing`, opens with "**Not implemented yet.**" and says the section is what "PB-13…PB-21 implement against". PB-14 has since put a subsection under the same heading — `### Availability: the adapter, the preflight and the cache` — that describes running code, and PB-15…PB-21 will each add another. A reader who takes the bold line at face value stops before the part that ships today.

The rest of the preamble is still true and should stay: the running version has no `models` command, no `--strategy` flag, and `--help` names neither.

Verified by reading the file at commit `5bd4985`: `grep -n "Not implemented yet" docs/reference/03-cli.md` is line 27, and `grep -n '^### Availability' docs/reference/03-cli.md` is line 117 of the same section.

## Work to do

- Reword the preamble so it separates what is contract-only from what runs. The cheapest form that does not need touching on every task: name the not-yet half (the `models` command, the flags, the resolver) instead of the section as a whole.
- Natural owner is PB-20 (docs and the release), which reads the whole reference at the end of the series anyway. Doing it earlier means editing the same paragraph after each of PB-15…PB-21.

## Out of scope

- The code-list tables and the golden fixtures — they are correct and pinned by the suite.

## Verification

- `docs/reference/03-cli.md` no longer claims the whole section is unimplemented.
- `npm test` stays green: `test/model-routing.test.mjs` slices the section by its `###` headings, so a preamble edit must not move or rename them.
