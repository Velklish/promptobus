# PB-397.2 · Native reviewer finding checkpoint and replacement recovery

- **Scope:** [Protocol](../../reference/04-protocol.md), native reviewer finding checkpoints
- **Created:** 2026-10-24
- **Dependencies:** none
- **Cost:** major

## Context

Native reviewer artifacts required a filesystem path and replacement planning only
retained terminal results. A constrained reviewer could not durably publish a
preterminal finding through that artifact route.

Evidence: `node test/native-reviewer-checkpoint.test.mjs` on the unchanged base
failed because `promptobus_send` rejected the `artifact` argument and the
synchronous store required `artifactPath`.

## Work to do

- Add authenticated inline reviewer checkpoints using the synchronous artifact store.
- Bind reports to the current reviewer session, assignment and exact diff subject.
- Recover every verified checkpoint before replacement, preserving the complete report.
- Keep checkpoints separate from terminal results and retain reviewer isolation.

## Out of scope

- Native approval forms, permission grants, command capture and Stop implementation.
- Product model runs, installation, publication and the combined integration gate.

## Verification

- `node test/native-reviewer-checkpoint.test.mjs`: actual MCP/store/engine persistence,
  identity and subject refusal, immutable bytes and damaged reference rejection.
- `node test/promptobus-review.test.mjs`: automatic two-checkpoint replacement
  prompt and refusal when a committed checkpoint reference is omitted.
- Focused engine, protocol, prompt and permission suites; build, lint, audit and pins.
- Semantic mutation probes for producer/subject checks, report truncation and loss.
