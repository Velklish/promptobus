# PB-40 · A fresh worktree has no generated .claude/skills until backslop init, and the lift prompt names them as rules to read — two of three workers of the 2026-09-06b run reported the file missing

- **Scope:** `AGENTS.md` (the backslop block or a line beside it), `lib/spawn.js` (the rule list printed to the participant), [03-cli](../../reference/03-cli.md)
- **Created:** 2026-09-06
- **Dependencies:** none

## Context

Run 2026-09-06b, three workers lifted into fresh worktrees of this repository. Two first `status` messages (workers `adr` 07:31:17 and `review` 07:31:55 UTC) say the same thing: `.claude/skills/backslop-task/SKILL.md` does not exist in the worktree — `find` and `git ls-files` confirm — because the adapter output of backslop is generated by `npx github:Velklish/backslop#v0.4.0 init` and is not tracked. One worker read a copy from a neighbouring worktree, the other fell back to the procedure in `AGENTS.md`. The orchestrator's brief said to run `init` first; the participants read the rule list before the brief's instruction. The ati-agents repository records the same trap for its own `backslop lint` (`BL-542.1`) in its `AGENTS.md`; this repository's `AGENTS.md` does not.

## Work to do

- One sentence in `AGENTS.md` beside the backslop block: a fresh clone or worktree needs `init` first; `git status` does not change from it.
- Decide whether `spawn` should run `init` for a repository whose `backslop.json` declares an adapter, the way it runs `npm ci` — or only say in its rule list that the skill files are generated.

## Out of scope

- The backslop tool itself (a separate repository).

## Verification

- A fresh worktree after the documented step has the skill files; the rule list printed by `spawn` names no file that does not exist.
