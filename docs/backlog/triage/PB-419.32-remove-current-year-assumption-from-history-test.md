# PB-419.32 · Remove current-year assumption from history test

- **Scope:** [CLI reference](../../reference/03-cli.md)
- **Created:** 2026-11-05
- **Dependencies:** none
- **Cost:** major

<!-- quality-audit-import:2026-11-05:PB/PQA-308 -->

## Context

Evidence: `test/promptobus-history.test.mjs:46,78-80` creates messages using the default current clock but asserts a `2026-` date prefix. `src/v1/engine.ts:198` uses `new Date()` by default. Correct output in 2027 will fail that assertion. The date in the rendered message is the recording time, not the task ID.

## Work to do

Assert an ISO date with a four-digit year and the remaining output fields, or inject a fixed clock and assert its exact value. Preserve detection of malformed output.

## Acceptance criteria

The test accepts valid 2026 and 2027 timestamps and rejects malformed date or remaining fields, deterministically.

## Verification

After implementation run `npm run build` and `node test/promptobus-history.test.mjs`, plus a deterministic 2027 clock case; **notRun**.

## Dependencies and limits

None. The audit established this statically; a shifted-clock run was not performed.
