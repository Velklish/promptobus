# PB-222.2 · Keyed publication lease on Windows: child PID registration without POSIX exec

- **Scope:** [03-cli § Lease](../../reference/03-cli.md#lease)
- **Created:** 2026-09-26
- **Dependencies:** none
- **Cost:** major

## Context

PB-222's keyed publication lease records the Git child's PID through a POSIX shell before `exec`. It refuses `--key` on Windows before starting the publication command. The worker's final result on 2026-09-26 names this as the remaining platform follow-up. The host CLI stays cross-platform, while participant lift on Windows is outside its current contract.

<!-- quote:../../../lib/lease.js -->
  if (keyedLock && process.platform === 'win32') {
    throw new GateError('lease: keyed publication requires a POSIX shell to record the command pid before exec; your command was not run');
  }
<!-- /quote -->

## Work to do

- Provide a Windows child-PID registration path that records the publication child before it can touch the clone root.
- Keep the keyed lease held after wrapper death while that child lives; refuse ambiguous recovery until both processes are proved dead.
- Preserve canonical clone-key serialization and independence from the machine measurement lease.

## Out of scope

- Windows participant lift; its separate platform boundary remains in [03-cli](../../reference/03-cli.md).

## Verification

- A Windows run under `--key` starts only after child registration, and a wrapper-death/surviving-child test keeps the second publisher waiting.
- A missing or ambiguous child PID refuses recovery without running the second publisher; a completed child lets the key release.
- Existing POSIX keyed publication and machine lease checks remain green.
