# PB-33.2 · The per-harness `snapshot-stale` line prints `1970-01-01` for an entry the cache never held

- **Scope:** `lib/model-routing/resolver.js` (the `snapshot-stale` warning message), [03-cli](../../reference/03-cli.md) § Reason codes
- **Created:** 2026-09-06
- **Dependencies:** none

## Context

The reference already settles what the epoch means in this subsystem: "a cache that was never written carries the epoch as its `checkedAt`, so 'never checked' and 'expired' read apart", and the text output prints that case as `snapshot: never checked · source cache` with no age, "because an age counted from the epoch is true and useless".

The header line honours that. The per-harness `snapshot-stale` warning does not: it interpolates the harness's own `checkedAt` verbatim, so a harness with no entry produces

```text
  ! snapshot-stale: codex was answered from a cache entry past its TTL and no probe ran — it counts as unknown, checked at 1970-01-01T00:00:00.000Z
```

which reads as a bug to the person holding it, and reads as an entry checked in 1970 to anything parsing the prose.

The header line does not cover the case either, because `snapshot.takenAt` is the OLDEST entry's stamp only when the cache holds entries: with one fresh harness beside a missing one the header shows the fresh stamp and the epoch appears only down here. Measured on 2026-09-06, same box as PB-33.1: after `models --clear-exhausted codex` the header read `snapshot: … · 0 s old · source cache` from claude's live entry while the codex warning read `checked at 1970-01-01T00:00:00.000Z`.

## Work to do

- Say "never checked" instead of the stamp when `checkedAt` is the epoch, in the per-harness warning as the header already does. The two forms then agree, and the reason code's own documented distinction — an expired entry keeps its stamp, one the cache never held carries the epoch — is visible in both places rather than one.
- The `--json` form keeps the literal stamp, for the reason the header's does: a machine reader wants the number.

## Out of scope

- The `stale_cache` reason code itself, and the choice of the epoch as the sentinel. Both are settled and are what makes the two cases tellable apart at all.

## Verification

- A run against a snapshot with one fresh harness and one absent harness prints no `1970` anywhere in the text form.
- `--json` still carries the epoch for that harness.
