# PB-335.1 · The release channel ships the development tracker's devDependency: tag a side commit or release a packed tarball (owner decision)

- **Scope:** [Releasing](../../guides/releasing.md)
- **Created:** 2026-10-04
- **Dependencies:** PB-335
- **Cost:** major

## Context

Finding discovered while working on PB-335.
Evidence (PB-335 worker, 2026-10-04, measured on its branch; not re-run by the orchestrator): consumers install `github:Velklish/promptobus#vX` (`docs/guides/install.md`: the package is not on the npm registry). npm 11.6.2 prepares a git dependency by `npm install` in a temporary copy and packs it, running only `prepare`, never `prepack`/`postpack` (pacote `lib/dir.js:39`). `npm install git+file://<worktree>#<commit>` into a temporary project left `node_modules/promptobus/package.json` byte-identical to `git show <commit>:package.json`. So the git tree at the release tag is the release manifest: a pack-time strip cannot remove `devDependencies.backslop`, and `npm run pins` and `npm ci` need that field in the source manifest. PB-335 therefore keeps the field and names it, in the artifact boundary check and its documentation, as the one remainder this channel cannot drop.

Two ways to remove the remainder, both outside PB-335 because they change the release procedure or the install contract:

- **B — tag a side commit.** The release tag points at a commit whose `package.json` and lockfile drop the tracker fields; the CI tag job skips the tracker's init, lint and pins. Fully clean on the real channel; changes the release procedure and CI, and release tags leave main's history.
- **C — release a packed tarball.** Releases become an `npm pack` tarball attached to the GitHub release; the install docs switch to its URL, and a pack-time strip then covers the channel. Consumers also stop fetching the tracker and compiling TypeScript at install. Changes the install contract; the largest change.

## Work to do

- The owner chooses B, C, or keeping the named remainder; then implement the choice with the release guide, CI and install documentation it touches.

## Out of scope

- The tracker itself, its installed files and hooks in the source checkout.

## Verification

- Under the chosen channel, a consumer install of a release contains no tracker field in its `package.json`, measured by installing the release the way consumers do.
