## Work to do

Recovery audit, 2026-10-20: a later retained run persisted answer 7658 while delivery was paused; explicit same-grant resume ended 54m21.434s after the answer, followed by gates lasting 80.733s. Original event/command hashes and timing are preserved in the recovery audit. Current delivery code intentionally does not unpause merely because a message exists. Distinguish pauses caused by user Stop or denial from recoverable technical interruption, and expose persisted/applied/started/completed separately. Do not unconditionally resume every paused actor. The earlier outgoing bridge refusal remains a separate diagnostic branch; this timing alone does not prove its cause.

- Correlate the original provider turn, command completion, bridge calls and public thread events; identify the first lost-liveness boundary.
- Reproduce with a bounded no-model fixture if the public SDK supports it. Preserve authenticated identity and current-grant checks.
- Support a real handover continuation, or expose a precise actionable public API limitation instead of reporting a delivered result that exists only on disk.

## Out of scope

Mailbox polling model turns, self-addressed wakes, identity shims, native participant fallback, private host internals, or assuming that a long-running command is the proven cause.

- Retained-event replay preserves results, errors, attention and Stop without duplicate model activation.
- A disposable long-command workflow either sends the authenticated result in its valid turn or receives one supported continuation; local receipts alone never count as bus delivery.
- Stale grants cannot send after closure. Next step: public turn-liveness replay; do not weaken grant validation to hide this refusal.
