# PB-373.10 · BB needs an owned terminal task close operation

- **Scope:** [BB host boundary](../../reference/02-host.md), owned task completion and cleanup
- **Created:** 2026-10-20
- **Dependencies:** PB-385 terminal publication ordering; safe participant stop/recovery from PB-373.2
- **Cost:** major

## Context

The current BB plugin exposes participant stop/resume/archive and task creation, but no operation that closes the canonical BB-owned task. Participant archive preserves a workspace patch and archives the BB thread; it does not mark the canonical task done. Native `done` refuses BB-owned tasks. Consequently a completed BB task has no complete supported terminal route through these public surfaces.

Evidence: source `5386bd5d6dedd84dd69760cfee4f1c0f19543f87`, command registration in `bb-plugin-promptobus/runtime.ts`, host operations in `bb-plugin-promptobus/contract.ts`, and BB-owner refusal in `lib/done.js`. Accepted ADR-031 and the plugin README explicitly state that stop/archive do not close the canonical task. This is a requested lifecycle extension, not a regression in archive. Live terminal closure was not attempted. It is distinct from PB-333 native cleanup vocabulary and the separate unintegrated hypothesis about grant retirement before answer-driven continuation.

Priority: required for the requested end-to-end BB acceptance, conditional on owner agreement to extend this boundary. Impact: a supported canonical terminal route; frequency of manual cleanup and its cost are notMeasured.

## Work to do

- Add one supported task-scoped terminal operation to the existing BB plugin, with explicit completed/blocked/preserved outcomes.
- Verify owned participant calls and queued work through available BB records; retain unresolved resources instead of inventing global PID attribution.
- Preserve final results, errors, workspaces that are dirty/unpublished, and original evidence before canonical closure.
- Make repeated invocation idempotent and report exactly which owned resources were archived, retained or remain active.

## Out of scope

- Global cleanup, prefix-based deletion, private BB edits or native fallback.
- Treating idle alone as proof that an owned command has ended.

## Verification

- Complete a disposable BB task through work, review and acceptance, close it using the supported operation, and observe canonical terminal state.
- Active owned work, unsent result, dirty/unpublished workspace or unknown ownership produces explicit bounded refusal/preservation.
- Restart during closure and invoke it twice; no foreign resource is stopped or removed and retained evidence remains available.
- Run fixture checks first. Exact live scenario and repetitions require the recovery plan's approval.
