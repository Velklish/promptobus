# PB-20.2 · The version line in `01-overview.md` drifts with nothing to catch it

- **Scope:** [01-overview](../../reference/01-overview.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

`docs/reference/01-overview.md` line 3 writes the package version out in prose — the sentence reads "Version in package.json is 0.2.1". Nothing compares it to `package.json`, so it is correct only for as long as somebody remembers it at a release. It has already been wrong once in this repository's short life — the same drift in `README.md`, `README.ru.md` and `guides/install.md` said `promptobus 0.1.0` while the package was at `0.2.1`, and PB-20 fixed those three by removing the number rather than updating it.

The number was kept in the reference deliberately: the overview is the one place a reader asks "what is this package", and a version belongs in the answer. PB-20 added a sentence saying the line moves at a release and no gate holds it, which documents the hazard without removing it.

Evidence at this commit: `grep -n '0\.2\.1' docs/reference/01-overview.md` is the only occurrence outside `package.json` and `package-lock.json`; `npm test` has no check that reads it.

## Work to do

- One check in the suite reading `package.json` `version` and the reference line, red when they part. It is three lines and it is the kind of drift this project already documents a story about (`HostToolBin.version`, PB-15.1).
- Or, if the owner prefers no number in prose at all, remove it and point at `promptobus --version` — but then say so here, because the note added by PB-20 argues the opposite.

## Out of scope

- The release procedure itself and who bumps the version.

## Verification

- Mutation probe, commit first: raise `package.json` `version` alone → the new check is red; raise both together → green.
