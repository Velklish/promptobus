# PB-21.1 · two routing codes are published and nothing raises them

- **Scope:** [03-cli](../../reference/03-cli.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

PB-21 registered the nine routing error codes in `ERROR_CODES` (`src/v1/errors.ts`) and the drift check now reads the reference table against that list. Seven of them are raised by `lib/models.js` on the routed path. Two are not raised by anything in the tree.

- **`limit-hit-at-start`.** The case is real and handled: a lift refused because the account's limit was spent between the preflight and the launch marks the harness exhausted (`markLimitAtStart`, `lib/driver-claude.js`, called as `sayLimit` from `lib/liftoff.js`) and the command ends with the diagnosis. It ends through `fail()` — `console.error` plus `process.exit(1)` (`lib/util.js`) — so no typed refusal ever carries the code. Evidence: `grep -rn "limit-hit-at-start" lib src` finds only the enum entry; the two call sites are `lib/liftoff.js` lines 55 and 72, both `fail(...)`.
- **`model_not_available`.** A snapshot reason code, listed in `schemas/model-routing/snapshot.schema.json` and in the reference's reason table, where it is described as appearing "only on the explicit `--model` constraint path". No adapter writes it — an adapter knows the harness, not the constraint — and the command does not write a snapshot entry at all: an explicit `--model` that no tuple names is `constraint-unknown`, and one whose harness is down is `constraint-unavailable`. Evidence: `grep -rn "model_not_available" lib src schemas` finds three declarations and no writer — `src/model-routing.ts` line 44, `schemas/model-routing/snapshot.schema.json` line 39, and the reason table of 03-cli.

Both are documented as they stand — the error-code table of 03-cli says `limit-hit-at-start` names the case for a consumer rather than a second exit path — so this is a gap between a published vocabulary and its raisers, not a silent one.

## Work to do

Decide, per code, which way to close the gap, and do it in one pass:

- `limit-hit-at-start`: either raise a `PromptobusError` with it from the limit branch of `lib/liftoff.js` (the CLI catch already prints a `PromptobusError` as one line and exits 1, so the person's output does not change), or record in the reference that it is a consumer-facing label for a case the CLI ends through `fail()` and never a thrown code.
- `model_not_available`: either give the explicit-`--model` path a snapshot entry that carries it, or retire the code from the schema enum, the `src/model-routing.ts` union and the reason table together — the drift check reads the schema and the table, so at least those two move as one.

## Out of scope

- The other seven routing codes; they are raised and covered.
- Changing what a limit hit at start does: the cache mark, the diagnosis and the no-retry rule are ADR-003's and stay.

## Verification

- A check that raises whichever code survives, or — if a code is retired — the drift check staying green with it gone from both the schema enum and the reference table.
