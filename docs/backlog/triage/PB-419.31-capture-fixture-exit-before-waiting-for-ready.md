# PB-419.31 · Capture fixture exit before waiting for READY

- **Scope:** [CLI reference](../../reference/03-cli.md)
- **Created:** 2026-11-05
- **Dependencies:** none
- **Cost:** major

<!-- quality-audit-import:2026-11-05:PB/PQA-307 -->

## Context

Evidence: `test/live-abort.test.mjs:152-165` waits for READY with an exit listener, then installs a separate exit listener. If the fixture exits before READY, the second listener misses the already emitted event and its promise remains pending. An injected fake child reproduced exit 17 before READY followed by a pending promise after an event-loop barrier (probe exit 0). An actual runner failure was not observed.

## Work to do

Create one exit promise immediately after spawn, before awaiting READY, and reuse it in both paths. Preserve stderr and the existing verdicts.

## Acceptance criteria

A fixture that exits before READY produces a bounded diagnostic failure; normal SIGTERM and SIGHUP cases retain their verdicts.

## Verification

After implementation run `npm run build` and `node test/live-abort.test.mjs` from the repository root; **notRun**.

## Dependencies and limits

None. The injected helper probe is not an observed failure of the actual runner.
