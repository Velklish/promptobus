# PB-24.2 · The snapshot's model object carries no efforts or speed tiers, so PB-28 cannot record what the catalog would rate ultra and fast from

- **Scope:** `schemas/model-routing/snapshot.schema.json`, `lib/model-routing/cache.js`
- **Created:** 2026-09-06
- **Dependencies:** PB-24, PB-28, PB-29

## Context

A proposal, not a defect: the shape is the contract and this entry asks whether to widen it.

PB-28 asks the Codex adapter to "record per model its efforts and speed tiers so the catalog (PB-29) can rate `ultra` rows and `quotaCost` can name the `fast` tier". The snapshot's `model` object is closed and carries four properties — `model`, `rated`, `hidden`, `flags` (`schemas/model-routing/snapshot.schema.json`, `$defs.model`, `additionalProperties: false`) — so an adapter that attached `efforts` or `speedTiers` would have them dropped by `modelOf` in `lib/model-routing/cache.js`, silently, and only its own tests would notice.

The facts exist in the harness: `model/list` on codex-cli 0.146.0 answers `supportedReasoningEfforts` per row (`low/medium/high/xhigh/max`, plus `ultra` on sol and terra) and `additionalSpeedTiers: ["fast"]` beside `serviceTiers`. The spike of 2026-09-06 recorded them, and the catalog track took the effort ladders from that document rather than from a snapshot — which is why nothing is blocked today.

So the question is whether the *runtime* inventory should carry them at all, and it is an ADR-shaped question rather than a schema edit: ADR-004 § "Codex rows may carry the effort level above the rated ones" settles what the catalog does with `ultra` and says the service tier "is not an effort and is not modelled in v1 at all". A model object that carried `speedTiers` would be the first place in the package where a service tier exists as data.

PB-28 therefore does **not** implement the item, and its result says so.

## Work to do

- Decide, with the owner, whether the runtime inventory carries per-model effort ladders and speed tiers at all. If yes, it is an ADR-004 amendment first (the service tier is named as not modelled in v1), then the schema, `modelOf`, the reference, and the Codex adapter.
- If no, close this entry and strike the item from PB-28's text so the next reader does not re-derive the same question.

## Out of scope

- Rating `ultra` rows — PB-29 already has the ladders from the spike document.
- The `hidden` mark, which PB-24 already carries.

## Verification

- Either the schema carries the fields and a Codex fixture round-trips them into `models --json`, or PB-28's text no longer asks for them.
