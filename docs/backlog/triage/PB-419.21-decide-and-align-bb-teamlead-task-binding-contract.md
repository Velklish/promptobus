# PB-419.21 · Decide and align BB teamlead task binding contract

- **Created:** 2026-11-05
- **Dependencies:** none

## Context

Evidence: `integrations/bb/skills/promptobus-teamlead/SKILL.md` describes a child orchestrator with root/child mailbox access and gives a send example with a `task` argument. `integrations/bb/protocol.ts:109-113` has a strict send schema without that argument, while `engine-host.ts:188,200-202` binds operations to one task and participant. The role is offered through this facade, but the documented cross-task workflow is not provided by its binding. Native child-task capabilities and optional consumer extensions do not establish that the facade provides this route.

## Work to do

First decide the supported teamlead contract: either provide authenticated scoped root/child binding and routing, or revise the role duties to the supported single-task contract and explicitly exclude the unavailable workflow. Align the renderer, protocol, runtime and tests with the decision; preserve identity checks and lateral-access restrictions.

## Acceptance criteria

- A role test exercises the actual supported reads and sends and rejects unrelated task and unauthorized role access.
- Generated instructions and examples conform to the actual schema and do not promise unsupported cross-task rights.

## Verification

After implementation run `npm run build` and `npm --prefix integrations/bb test` from the repository root; **notRun**.

## Dependencies and limits

Depends on an explicit teamlead-contract decision. Live integration and consumer-specific routes were not tested; a wording change alone does not grant cross-task rights.
