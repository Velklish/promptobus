### PQA-5004 - Preserve failed reads in live home and registry hygiene verdicts

Audit priority: medium. Evidence status: confirmed.

Evidence: scripts/live-canary.mjs:71,82-85,140-152 converts read or parse failures to empty values. Lines 207-211 treat matching values as a clean observation. Fake-reader checks found that repeated EACCES and repeated malformed marketplace JSON each yielded a clean verdict, while changed bytes were detected. Registry reads in scripts/live-cursor.mjs:100-106,569-573 and scripts/live-mixed.mjs:111-119,610-620 also hide read failures. Other checks contribute to the overall canary result.

Acceptance: Use isolated readers to exercise a baseline refusal, a final refusal, malformed JSON, expected ENOENT, an observed change and a clean pair. Through each affected entrypoint, check that an unavailable observation identifies the cause and cannot pass hygiene, while clean, absent and changed inputs retain their respective verdicts. Preserve the stand when cleanup cannot be established. Run `node test/live-codex-hygiene.test.mjs` and the affected stands with fake providers.

### PQA-3003 - Exercise hygiene failures through both live entrypoints

Audit priority: medium. Evidence status: confirmed.

Evidence: test/live-codex-hygiene.test.mjs:33-40,85-93 extracts source fragments, supplies its own check function and assembles the baseline, final snapshot, count and exit in a fixed order. It can report failure even if scripts/live-codex.mjs:235-253 or scripts/live-mixed.mjs:573-645 skips the final verdict. The existing clean-path smoke and cleanup-failure cases do not exercise failed final observation.

Acceptance: Drive each entrypoint through its real control flow with isolated I/O. Verify the clean verdict and successful exit, then separately fail baseline and final observation and verify their diagnostics and nonzero exits. Removing the final observation on the normal path must fail the entrypoint check. Run `npm run test:one -- live-codex-hygiene.test.mjs`.
