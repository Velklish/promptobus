# PB-12.1 · Shipped v1 JSON schemas carry Russian descriptions

- **Scope:** [04-protocol](../../reference/04-protocol.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

Found while writing `schemas/model-routing/` for PB-12, where every description is English. The protocol v1 schemas next to them are not.

Evidence, run in this tree:

```text
$ for f in schemas/v1/*.json; do n=$(grep -cP '[\x{0400}-\x{04FF}]' "$f"); [ "$n" -gt 0 ] && echo "$f: $n"; done
schemas/v1/artifact.schema.json: 4
schemas/v1/message.schema.json: 5
schemas/v1/participant.schema.json: 8
schemas/v1/task.schema.json: 5
```

This is not the same as PB-9. That entry is scoped to the suite and verifies "no Cyrillic in `test/**`"; these four files are **shipped**: `schemas` is in the `files` array of `package.json` and the package exports them as `./schemas/*`. A third party who imports the schema to validate a task record reads its field documentation in a language the rest of the package does not speak — and the two schema directories now disagree with each other inside one tarball.

## Work to do

- Translate the `description` and `title` values of `schemas/v1/*.json` to English, leaving every structural keyword and every pattern byte for byte as it is.
- Check the parity test afterwards: `test/v1-validate.test.mjs` runs the own validators and ajv against one fixture set and reads verdicts, not text, so a description change must not move it — confirm rather than assume.

## Out of scope

- Suite titles and comments — PB-9.
- Any change to a schema's structure, `$id`, patterns or required lists. This is a text pass; a shape change in the same commit would be invisible in the diff noise.

## Verification

- `grep -cP '[\x{0400}-\x{04FF}]' schemas/v1/*.json` reports zero for every file.
- `npm test` and `npm run audit` green; the verdict count of `test/v1-validate.test.mjs` is unchanged.
