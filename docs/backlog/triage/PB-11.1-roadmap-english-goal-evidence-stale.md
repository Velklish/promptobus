# PB-11.1 · ROADMAP goal on English output cites lib/cli.js, which has no Russian left

- **Scope:** [README](../../reference/README.md)
- **Created:** 2026-09-05
- **Dependencies:** none

## Context

Found while adding the routing goal to [ROADMAP.md](../../ROADMAP.md) for PB-11. The goal "English runtime output" ends with the evidence line "`lib/cli.js` help is still Russian". That is no longer true, and it was the only thing that goal named as unfinished.

Evidence, run in this tree:

```text
$ grep -cP '[\x{0400}-\x{04FF}]' lib/cli.js
0
$ for f in lib/*.js; do n=$(grep -cP '[\x{0400}-\x{04FF}]' "$f"); [ "$n" -gt 0 ] && echo "$f: $n"; done
(no output)
```

No file in `lib/` carries a Cyrillic character. `helpText` (`lib/cli.js` lines 10–77) is English throughout.

A goal whose evidence contradicts the code is worse than no evidence: the next reader either believes the ROADMAP and looks for a translation that is already done, or believes the code and stops trusting the ROADMAP.

Two shapes, and they are not the same task: either the runtime output is done and the goal closes with evidence of that, or the goal is really about `test/**` and `schemas/v1/*.json`, which still carry Russian — but `test/**` is already PB-9 and the schemas are PB-12.1, so the goal would be a duplicate of two queued entries rather than a goal.
- Update the evidence line either way. A goal that stays must name a file that still shows the gap.
