# BB participant transitions: Stop, resume, fresh phase and archive

Proposed internal interface; owner review pending. Source: `791d9bdd7b1b28cba8bb121ea3cdf3825d70763f`. The strongest reason for one module is a race: by the time a queued resume reaches the front, the operator may already have stopped the participant again. Reading the epoch there instead of at command entry would give the *older* resume permission to undo the newer Stop.

## Interface and ownership

Instantiate `participantTransitions` once per BB plugin runtime with its existing SDK, binding store, delivery engine and concrete admission/evidence/host operations. Four methods: `stop(target)`, `resume(target, signal)`, `freshPhase(target, {launchContext, assignment, evidenceManifest?}, signal)`, `archive(target, signal)`. `target` is the registered task/participant lookup, never a caller-selected thread or environment. Methods resolve the binding. Return the existing action payload (including partial Stop/notification outcome); command adapters retain schemas, incompatible-option diagnostics, stdout/stderr and exit codes. No epoch, queue ticket, wake flag, compensation callback or asserted Stop proof in the interface.

The concrete BB module owns transition ordering. Keep fresh-grant validation, prompt construction and reviewer evidence policy in named phase-assignment functions; keep archive eligibility, capture and preservation in archive-specific functions. Invoke them inside the appropriate transition, not as interchangeable caller hooks. [`delivery.ts`](../../integrations/bb/delivery.ts) owns replay, exact queued-message cancellation, wake budgets and durable delivery updates; [`lifecycle.ts`](../../integrations/bb/lifecycle.ts) owns SDK observation/Stop and workspace capture. [`bindingStore.updateDelivery`](../../integrations/bb/bindings.ts) transacts on the separate deliveries row; saving a stale binding must not reset its epoch. No new store schema, native-driver adapter, physical kill proof or authority source.

The per-thread promise queue is local to the plugin instance, not a durable lock. Retain one shared queue for transitions, child launch/registration under the parent and paused-notification reconciliation in `recovery run`. Offer those two collaborators concrete parent operations; do not hand command handlers a general `withTransition` primitive. On reload only persisted bindings, intent, delivery/epoch and SDK observations survive. The host journal remains canonical and BB owns the environment.

## Ordering to preserve

The source for these paths is the registered commands and `withParticipantTransition`, `stopWithChildNotifications`, `syncChildNotifications`, `resumeDelivery` and `sendPhaseAssignment` in [`runtime.ts`](../../integrations/bb/runtime.ts).

| Intent | Durable writes and waits, in order | Refusal or completion |
|---|---|---|
| Stop | Resolve binding; synchronously `pause` (write paused, increment epoch and store reason) **before any await or queue join**. Start `stopBbParticipant` immediately. Inside queue try canceling owned queued wake (warn on failure); join Stop and child sync, then observe parent again. | Confirm only with prior Stop confirmation **and** fresh matching available/idle thread, idle runtime, zero background agents and queued messages. Exit 0 only if also every notification confirmed; otherwise partial result/exit 1 or existing error. Pause persists. |
| Resume | Require current-mode binding; capture entry epoch before queue, compare on entry. Await thread and host check; admit current control. Normal delivery calls `recovery.resume` with original epoch: replay, observe idle/available, no active agents or interactions, cancel queued wake; compare epoch **in delivery transaction**, increment and clear pause/reset budget. | Restore child attention then re-read paused/epoch against resume result before `recovery.run`. Wake runner also fences waits, sends and receipts. Never replace entry epoch with a new read after admission. |
| Pending initial assignment | Same admission; reject missing prompt or outstanding queued assignment. Check reviewer evidence if applicable. Resume without ordinary wake, then send the complete stored assignment. | Persist sending receipt with epoch before SDK send. Compare pause/epoch after reply; sent clears pending, queued retains id, matching early cancellation pauses, unknown stays fenced. No mailbox-only substitute. |
| Fresh phase | Within same resume entry fence require assignment and previous grant; validate bounded context (reviewer also needs manifest), distinct token **and** phase. Await current control against previous grant and reviewer evidence; recheck entry epoch before transfer pause. Capture that pause's epoch. Stop + child sync + final observation; only then clear context, admit next binding, recheck evidence, host assignment. Save full new prompt as pending on same binding. | Resume without wake against **transfer epoch**, verify not paused, send complete assignment with receipt fence, record launch intent assignment. A Stop while clear/admit/assignment waits may leave a prepared binding; do not equate that write with resumed delivery or revive an ended token. Refuse unconfirmed Stop before clearing context. |
| Archive | Already archived returns stored phase/preservation. Require ready/archiving, no recorded lifecycle child; page SDK unarchived children including hidden, then **reread** binding/phase and local children. Acquire per-thread archive guard; pause and save archiving. Serialize Stop + child sync, require confirmation. Capture complete stable workspace against recorded base, preserve on coordinator, save artifact id/hash/time. Re-observe idle/available and no active agents, recapture and compare bytes, request archive, read thread back. | Only confirmed `archivedAt` permits archived save. Successful first archive returns `environmentOwner: 'BB', accepted: false`; idempotent branch retains its smaller response. Release in-memory guard in finally. Failed preservation/observation leaves environment for recovery. Do not hold the Stop queue around all archive I/O or change child-scan races. |

Child sync iterates nonarchived children by **parent** (not lifecycle owner alone). Missing thread with unknown spawn is incomplete. SDK get must match child thread/project/provider/parent/lifecycle owner; choose `off` if parent is durably paused, otherwise `stuck`. Validate every identity and the policy on update response. The parent can change during either SDK wait. If resume restore fails after some children changed, pause again immediately; Stop and reconcile all children to off, warn on incomplete compensation and propagate the error. Keep Stop observation separate from notification completeness. Neither a successful SDK request nor idle observation establishes physical termination of every provider call.

Deletion test: all four registered actions can be read without reconstructing pause-before-wait, queue key, epoch capture/recheck, notification restore, cancellation or compensation. Dispatch only selects intent and formats its result. A helper wrapping the SDK Stop alone would still leave three callers able to undo a newer pause.

## Registered-command witnesses for implementation

Use the existing `stand`, `s.control`, `deferred`, `s.reload`, `s.reconcile` and SQLite delivery readback in [`engine.test.mjs`](../../integrations/bb/test/engine.test.mjs); keep [`lifecycle.test.mjs`](../../integrations/bb/test/lifecycle.test.mjs) beside them. Hold fake SDK/host promises, not production hooks or timers. Each row is a planned assertion, not a reported run.

| Barrier and competing action | What must be observable at the command surface and in the store |
|---|---|
| Hold ordinary resume's `beforeGet`, `beforeCheck` or `beforeControl`; issue Stop | Before release: paused at higher epoch, Stop already initiated. After release: resume exit 1, same Stop epoch, no wake. Other participant still progresses. |
| Hold child `stuck` update during resume, then Stop; separately refuse second child's update | Race: resume loses its epoch and queued Stop leaves all owned children off. Partial refusal: exit 1, compensation advances pause epoch, Stop attempted, first child also off; if compensation incomplete, warning/diagnostic visible. Foreign identity on get must produce no update; mismatched update receipt cannot confirm. |
| Hold child registration, or change parent activity while suppressing children | Stop pauses immediately but cannot acknowledge until serialized registration and fresh observation finish. Unknown child, queued work or active background agent prevents successful receipt. |
| Hold fresh control/evidence validation, then Stop; repeat after transfer pause during host assignment and during SDK send | Before transfer: no clear/context transfer. After transfer: stale resume or stale receipt refused, durable higher epoch stays paused, no ordinary wake or usable ended grant. If send already issued, no claim of unsending it. Unknown/error-state Stop blocks fresh phase across reload. |
| Pause while a wake send reply is outstanding, reload and return a late queued id | Read same persisted Stop epoch, reconcile exact queue ownership; no duplicate send, mailbox ACK or reactivation. Explicit valid resume required. Repeat pending initial case: reject queued retry, deliver exact prompt after cancellation/admission; reviewer needs evidence. |
| Hold archive child-list page; add child or finish overlapping archive | Reread rejects child or returns stored terminal receipt. No second preserve/archive. Child refusal before pause does not advance epoch. |
| Hold archive Stop, preservation reads or final observations | Pause remains; unconfirmed Stop, partial patch, changed snapshot or restarted runtime refuses archive. Success events `stop`, `preserve`, `archive`, then confirmed SDK get and archived binding. No acceptance event. |
