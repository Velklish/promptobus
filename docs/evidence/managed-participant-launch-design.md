# One launch for a worker or a new reviewer

The owner approved one internal launch call for a worker or a new reviewer. The shared module owns the order of operations, each role owns its concrete preparation, and the driver owns native start and Stop. Source examined: `791d9bdd7b1b28cba8bb121ea3cdf3825d70763f`. The seam is **before** the participant write: a worker may already own a generation when worktree creation fails. A helper that takes a finished launch plan is too late to own that failure.

## What the two entrypoints publish today

Read [`spawn`](../../lib/spawn.ts) (exclude `spawnTeamlead`) alongside [`reviewLift`](../../lib/review.ts). The task journal, the grant, the driver's session record and the live seat are different records. Removing one is not evidence about the others.

| Boundary | Worker | Reviewer starting a session |
|---|---|---|
| Admission | Dry-run returns; binary/version, options and foreign project layer checked before worktree writes. | Dry-run returns; real lift checks tool/options. Reuse is a separate locked path: check current generation, write/retarget diff, stamp and send assignment, restore watch; no new grant or seat. |
| Journal reservation | Codex creates a new task if needed, then reserves **before** freshening/creating the worktree. Others reserve after obtaining the worktree and creating/binding the task. Clear throughput sidecar before dependency work; patch the Codex record with the actual branch point. | Create task if needed; reserve **before** binding/handoff and writing the diff. Record includes assignment time, snapshot, histories and `pending: true`. |
| Role preparation | Exclude/freshen, create or reuse directory, bind owner and hand off contact points; install dependencies on fresh tree, run generator, rebuild prompt and launch from actual results. Journal already identifies the tree during long operations. | Bind/handoff, write and retarget the actual diff; retain read ceiling and prior findings for relift. Clear sidecar for new lift. |
| Grant and files | Copy reserved Codex generation to **rebuilt** launch. Finalize service, refresh env/argv/config/settings, write launch files, then optional locked retitle before start. | Copy Codex generation; write Codex files other than `mcpConfigPath` **before** registration. Finalize with the plan's file scope, then publish remaining files with MCP-root preparation. Resolve launch tool. |
| Native start | Both call `reservedSpawn` with their own cwd, address, tool, host, env, task, ref, await options and role-specific failure/Stop/retry text. The seat is acquired here, not when the participant is journaled. | Same mechanism; no worker worktree or worker retry message. |
| Result | Persist session/null and optional full id. On successful return, announce, ensure warden, retain brief and report driver observation. | Dead persistence keeps pending; alive Codex writes false, legacy omits the key. On return, ensure warden and report reviewer-specific routes. |

[`reserveNativeParticipant`, `persistNativeParticipant`, `persistLegacyParticipant`, `releaseNativeReservation`](../../lib/native-lifecycle.ts) own the locked journal checks. Reservation under `withReservationIdle` checks the expected participant; Codex gets a UUID and prior native generations require terminal evidence. Other drivers do not acquire a Codex generation. [`finalizeManagedServiceLaunch`](../../lib/service-launch.ts) selects the launch ID (supplied or generated), checks store/host, isolates owner/actor environments and registers pending grants. Driver-called `beforeStart` verifies record identity/version, stages provenance and binds grant lifetime; `realize` binds the actual native id. Do not move those calls out of drivers.

[`reservedSpawn`](../../lib/live-reservation.ts) owns the token-address pair and driver hooks: reserve → stage record/generation → mark launching before the uncertain native call; alive persistence with full id registers the seat before journal persistence. On return it removes a bound seat only when journal harness/ref/id match. On throw it removes the seat only if start was not marked or Stop was confirmed. An unbound return is not proof of Stop.

### Failure ownership today

Read the two caller catches separately: preparation failure permits guarded journal release after revocation; a `reservedSpawn` failure permits it **only for `LiveAdmissionError`**. The following are observations about native start, not commands to retry.

| Native evidence on exception | Live seat (`reservedSpawn`) | Participant journal (caller and native lifecycle) | Owned grant (managed launch) |
|---|---|---|---|
| Proved no start: preparation or seat admission failed | No seat acquired by this attempt. | If reserved, attempt guarded Codex release after successful cleanup: only the unchanged generation without a session record may be marked `nativeUnlaunched`. Never erase the participant. | Nothing to revoke before registration; revoke actual registrations on partial or completed finalization. |
| Proved no start: driver staging throws before `starting` | Attempt to remove this seat by token. | Ordinary driver exception is not admission failure. The outer catch does **not** mark the generation unlaunched. Even with no seat and zero native calls, a journal reservation or driver record may still block relift. | Attempt revocation; its success says nothing about journal release. |
| Uncertain start: `starting` crossed, no confirmed Stop | Retain launching or registered seat, record/ref and generation for [`stop` / `recoverLiveSeat`](../../lib/stop.ts). Lost reply or failed persistence cannot establish exit. | Keep last published session/generation; neither caller invents `nativeUnlaunched` or terminal proof. | Attempt revocation even when native outcome is unknown. |
| Confirmed Stop: driver called `stopped`, then threw | Attempt to remove this seat. A dead persistence callback is not the `stopped` signal. | Driver owns terminal evidence and retirement; no general caller release. Future admission checks that evidence independently. | Attempt revocation; an unresolved grant remains a cleanup failure even if Stop was confirmed. |

**Errors today:** if cleanup succeeds, propagate the original exception. `revokeFailedManagedLaunch` retains the original and revocation/native-cleanup failures together and skips the release callback if revocation fails. There is a narrower gap: when removing the seat throws, `changeSeat` replaces the driver's original exception *inside* `reservedSpawn`; an outer catch cannot recover it.

**Proposed correction, separate from extraction:** the catch in `reservedSpawn` that still has the driver exception owns error composition. If seat removal throws, propagate an `AggregateError` containing the driver error first (also its `cause`) and the seat-write error second, with task/address/ref for inspection. Do not report the seat removed or retry the write against another token. Outer grant revocation must preserve that exception and any additional revocation failure. This does not change journal-release eligibility. Any proposal to make an earlier no-start failure retryable needs a separate decision and generation/record proof.

## Approved one-call interface

`launchParticipant({kind: 'worker', plan, tool, awaitOptions} | {kind: 'reviewer', plan, tool, awaitOptions}) → {output, session, seen}`. Plans are the existing trusted, preflighted worker/new-reviewer plans; exclude reuse and teamlead at the type boundary. Reflect final launch/env/config in the plan just as today. No public export. No caller-supplied generation, grant, callbacks, free-form authority or rollback handle.

Let this module drive the interleaved preparation. Extract concrete worker functions for tree/task setup, install/generate/rebuild, and retitle; concrete reviewer functions for record metadata, diff/handoff and evidence preparation. They still live with the role code (in sibling files to avoid circular imports). The module invokes them at the rows above. It owns *when* to open the participant and place role data in the journal, obtains the generation from that return, and partitions reviewer grant files internally. Do not let a role function start a driver, finalize credentials, or release a reservation. A role can return a discovered base SHA or rebuilt plan; it cannot supply a new host, task or actor. Keep all state per invocation. Existing preflight, reuse, success reporting, warden and brief stay at the entrypoints.

Deletion test: neither entrypoint imports `reservedSpawn`, service finalization/revocation or native reservation/persistence for these two paths; neither copies `launchId`, decides whether a resource precedes registration, supplies `persist`, or catches `LiveAdmissionError` to release a generation. Inside the module, one persistence function selects generation-checked Codex patch vs guarded legacy replacement (reread and retain `sessionRecord`); only the reviewer supplies the pending policy. A wrapper accepting a persistence callback and a cleanup callback fails this test.

## Failure witnesses for implementation

Run each common row through worker **and** new reviewer, across Claude, Cursor, Codex and OpenCode with scripted binaries; apply the Codex-only witnesses separately. Record journal generation/metadata, credential binding or revocation, session record/ref, seat phase/token and native invocation count at the barrier and on exit. Expected evidence (not executed):

| Held or failed operation | Expected observation |
|---|---|
| Dry-run / tool refusal / stale expected participant | No new grant, seat or start; no new generation from refused reservation. Existing owner unchanged. |
| Worktree failure / dependency or diff preparation throws after reservation | Journal may already exist; no grant/seat/start. Only matching Codex reservation with no session record may be marked `nativeUnlaunched`; never delete the worktree as rollback. |
| Reviewer resource write / grant registration / remaining files or retitle fail | Inspect file visibility at registration: reviewer resources present, final config not yet published. No seat/start. Revoke only registrations actually made; do not promise removal of already published files. |
| Live cap refuses after publication | Grant revoked, no new seat/driver call; guarded native release after revocation. Prior occupied seat survives. |
| Driver record staging or `beforeStart` fails | No start if marker not crossed; seat released on throw. Driver owns staged record cleanup; do not treat every driver error as admission failure. |
| Start marked, response lost / persistence fails after full id | Keep launching/registered seat and record identity unless driver confirms stopped. Revoke owned grant; return original diagnosis and Stop route, not `nativeUnlaunched`. |
| Driver confirms Stop then throws | Seat removable on throw; retain driver Stop/retirement evidence. A dead persistence call alone does not set this flag. |
| Alive/dead persistence, repeat launch | Assert session and sessionRecord retained per harness, matching full-id publication before bound seat removal, reviewer pending behavior above. Retry pending reviewer with full prompt; live reuse gets diff only. Worker does not gain reviewer pending semantics. |
| Original failure plus cleanup failure | Exercise [`revokeFailedManagedLaunch`](../../lib/driver-common.ts): both causes and recovery reference visible, registered cleanup not re-run by outer catch; no release after failed revocation. For the separate seat-error correction, inject a driver failure, a failed seat removal and then failed revocation; assert that all three errors remain inspectable, the first remains identifiable, and no new journal release or claim of successful cleanup appears. |

**Alternative considered:** a staged interface (reserve a generation, then finish the launch) would keep preparation inline. Each entrypoint would still have to reserve at the right point for its harness and handle a failure between calls. The owner selected one call so that both obligations stay in the shared module.
