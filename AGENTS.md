## Задачи и решения — backslop

Трекер задач и журнал решений живут в `docs/` и ведутся командой `npx github:Velklish/backslop#v0.2.0` (конфиг — `backslop.json`, префикс задач — `PB`). Списка задач в файлах нет: очередь, работу, отложенное и triage печатает `npx github:Velklish/backslop#v0.2.0 status`. Правила ведения — `docs/backlog/README.md`, термины — `docs/GLOSSARY.md`. Версия раскладки — поле `version` в `backslop.json`; обновление backslop — `npx github:Velklish/backslop#v0.2.0 upgrade`, по своему решению, а не по чужому коммиту.

**Скиллы:** `backslop-task` — цикл одной задачи; `backslop-batch` — заход worker'ами по track'ам; `backslop-seed` — наполнение документации после установки.

**Процедура изменения.** Роли две: worker правит и проверяет (шаги 1–4), approver принимает и закрывает (5–7); одиночный агент совмещает обе и идёт по шагам подряд.

1. **Задача.** Возьми первую в очереди (`npx github:Velklish/backslop#v0.2.0 status`) или заведи: `npx github:Velklish/backslop#v0.2.0 new <slug> --title "…"` — в triage, с `--queue` — сразу в очередь. Мелочь без следа в трекере допустима, если правка исчерпывается одним заходом и не меняет контракт. Находка, которую этот заход не закроет, — сразу файл: `npx github:Velklish/backslop#v0.2.0 new <slug> --parent N`, с уликой.
2. **Правка.** Реверс прежнего решения — чистым удалением, без зачёркиваний и пометок «отменено». Стиль существующего файла сохраняй. Термины — из глоссария; нужного нет — предложи, молча не выдумывай.
3. **Доки тем же ходом.** Незадокументированное изменение считается незавершённым: справочник `docs/reference/`, README затронутой подсистемы, CHANGELOG. Архитектурное решение — `npx github:Velklish/backslop#v0.2.0 adr <slug>` и строка в таблицу `docs/README.md`.
4. **Гейты до отчёта.** Команды из `gates` в `backslop.json` зелёные. Правку теста проверяй мутационной пробой: сначала коммит, потом проба.
5. **Приёмка и архив** — approver'ом, одним ходом: ревью диффа, `npx github:Velklish/backslop#v0.2.0 archive N`, дописать `result.md` (исход, что сделано, чем проверено), `npx github:Velklish/backslop#v0.2.0 lint` зелёный. Worker свою работу принятой не объявляет и файлы задач между каталогами не двигает.
6. **Разбор triage** — сразу после закрытия: каждой записи ход — слить, уточнить, `npx github:Velklish/backslop#v0.2.0 mv N queue`, `npx github:Velklish/backslop#v0.2.0 mv N deferred` с условием возврата. К владельцу — только за отказом.
7. **Фиксация.** Коммит с номером задачи первым в сообщении: `PB-N: <что сделано>`. В основную ветку задача уезжает одним коммитом: взятие, правки по ревью и приёмка схлопываются перед пушем.

Границы worker'а: правит только свою ветку или worktree, каталоги статусов и `docs/archive/` не трогает; закрытие и triage — approver.
