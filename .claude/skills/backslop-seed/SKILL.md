# backslop-seed — наполнение скелета документации

`backslop init` кладёт скелет: индекс, глоссарий, roadmap, справочник, первый ADR, каталоги задач. Наполнить его может только тот, кто прочитал репозиторий и поговорил с владельцем. Этот скилл — порядок такого наполнения: сначала улики, потом вопросы, потом текст. Команда `npx github:Velklish/backslop#v0.2.0` дальше называется `backslop`; каталог документации — `docs/`.

**Предусловие:** в корне лежит `backslop.json` и каталог `docs/`. Их нет — сначала `backslop init`, этот скилл ничего не раскладывает сам.

**Три правила, которые держат весь скилл:**

- **Улика на каждое утверждение.** Термин — с путём к файлу, где он живёт; решение — с зависимостью, конфигом или коммитом, которые его показывают; команда гейта — с файлом, где она объявлена. Улики нет — это `[TODO]`; нужно решение человека — `[ASK]`.
- **Дописывать, не перезаписывать.** Файл, написанный человеком, не трогается целиком: заполняются места с `[TODO]`, добавляются строки в таблицы, новое кладётся рядом. Повторный запуск закрывает только пробелы.
- **Спросить дешевле, чем уверенно написать неверное.** Файл с выдуманной мотивировкой решения хуже пустого раздела: следующий читатель поверит ему.

## Фаза 1. Инвентаризация — молча и read-only

Ничего не пиши и не спрашивай, пока не прочитал репозиторий. Что искать и где — [references/inventory.md](references/inventory.md). Итог фазы — четыре списка кандидатов, каждый пункт с уликой:

| Список | Куда пойдёт | Откуда берётся |
|---|---|---|
| команды сборки, тестов, линтеров | `gates` в `backslop.json` | манифесты пакетов, Makefile, CI-конфиг, README |
| подсистемы | таблица `docs/reference/README.md` | каталоги верхнего уровня, проекты, сервисы, точки входа |
| термины | `docs/GLOSSARY.md` | имена сущностей, таблиц, событий, enum, ключей конфига, слова из README и обсуждений |
| решения | `docs/adr/` | крупные зависимости, «почему» в комментариях и README, переезды в истории git |

Существующая документация — README, ARCHITECTURE, CONTRIBUTING, `docs/**`, ADR в другом формате — читается первой: это уже канон, и его надо не переписать, а сослаться на него из индекса. ADR в другом формате — вопрос владельцу: мигрировать в `docs/adr/` с сохранением номеров и дат или оставить и сослаться.

## Фаза 2. Опрос владельца — только неизвлекаемое

Спрашивай инструментом опроса, свою рекомендацию ставь первой. Не спрашивай то, что видно из репозитория. Что обычно не извлекается:

1. суть проекта одной строкой и кто владелец — для индекса и ADR;
2. цели на обозримый срок и чем решается порядок — для `ROADMAP.md`; целей нет — так и записывается;
3. кто и как ревьюит изменения — для гейта ревью в процедуре;
4. спорные термины: два имени у одного понятия, старое слово, которое пора убрать — для глоссария;
5. какие из кандидатов в решения — настоящие решения, а какие — случайность истории; список кандидатов показывается целиком **до** записи, владелец выбирает; правила отбора — [references/adr-backfill.md](references/adr-backfill.md).

Ответы фиксируй сразу в артефактах фазы 3, а не в памяти сессии.

## Фаза 3. Наполнение

Порядок — от каркаса к деталям; каждый пункт — правка мест с `[TODO]` или добавление строк, не переписывание.

1. **`docs/README.md`** — имя проекта, найденные документы строками таблицы (существующие README, ARCHITECTURE и прочие — ссылками, со статусом «Живой»), принципы из опроса, если владелец их назвал.
2. **`docs/GLOSSARY.md`** — 10–30 терминов, каждый с EN-парой, определением в одну-две фразы и уликой; спорные — с пометкой `[?]` до решения владельца; убранные слова — в нижнюю таблицу с заменой. Формат и критерии включения — [references/glossary.md](references/glossary.md).
3. **`docs/adr/`** — backfill выбранных решений: `backslop adr <slug> --title "…"`, статус `Accepted`, дата — исходная, из истории, с пометкой «записано задним числом» в Context; в `adr-001-process.md` — владелец в Deciders. Каждому ADR — строка в таблицу `docs/README.md`. Мотивировка только с уликой; история скудна — так и написано в Context.
4. **`docs/reference/README.md`** — таблица подсистем с точками входа из инвентаризации; тела разделов не пишутся сейчас, а становятся задачами: `backslop new describe-<подсистема> --queue --title "Справочник: <подсистема>"` (slug — латиница в нижнем регистре и дефисы: `describe-orders-api`).
5. **`docs/ROADMAP.md`** — цели из опроса; целей нет — одна фраза об этом вместо `[TODO]`.
6. **`backslop.json`** — `gates` из найденных команд после подтверждения владельцем; `backslop lint` остаётся в списке.
7. **Очередь и triage** — недописанное и открытые вопросы: разделы справочника — в очередь, вопросы без ответа — файлами в `triage/` (`backslop new <slug>` с формулировкой вопроса и уликой).

## Фаза 4. Проверка и итог

- `backslop lint` зелёный; `backslop status` показывает посев.
- Итог владельцу: что заполнено, где остались `[TODO]` и `[ASK]`, что встало в очередь, какие ADR записаны и какие кандидаты отклонены. Много `[ASK]` на скудной истории — правильный исход, не дефект.
- Повторный запуск скилла — тот же порядок; закрываются только пробелы.
